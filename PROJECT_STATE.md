Защищённые маршруты: `GET /auth/me`, `GET /auth/sessions`, `DELETE /auth/sessions/{sessionId}`, `POST /auth/sessions/end-others`, `POST /auth/sessions/end-all`, `POST /auth/logout`; коды ошибок различают «обновите токен» (`ACCESS_TOKEN_EXPIRED`), «войдите» (`AUTH_REQUIRED`) и «сессия завершена, войдите заново» (`SESSION_ENDED`). `POST /auth/session/refresh` ротирует пару и сдвигает скользящий срок (мобильное 90 дней, кабинет 180 дней, админка 12 часов от входа без продления); повтор того же обмена в пределах 60 с возвращает ту же пару (гонки, потерянный ответ), более позднее предъявление заменённого токена завершает сессию (D-044). Refresh-токен в базе не хранится ни в каком виде — только случайное зерно и номер поколения, токен выводится с секретом сервера. Список сессий — только свои, текущая отмечена, IP сокращён до `/24`; чужая сессия неотличима от несуществующей. Мгновенный отзыв: каждый защищённый запрос проверяет строку сессии в PostgreSQL (чёрного списка в Redis нет); при недоступном Redis отозванные сессии отклоняются, действующие работают, не работает только обмен токена (503, повтор); при недоступной PostgreSQL защищённые маршруты отвечают 503. Механика cookie-сессий кабинета и админки готова (HttpOnly, Secure, SameSite=Strict, cookie уходит только на обмен и только с `Origin` своего веб-клиента), выдача закрыта до TASK-006: 403 `SESSION_KIND_UNAVAILABLE` до проверки кода, код не расходуется.
