# TASK-001 — Инициализация монорепозитория и рабочего окружения

## Цель
Рабочий монорепозиторий с каркасами всех приложений и общих пакетов, локальным окружением зависимостей и CI. После задачи любой разработчик или coding-agent поднимает проект одной командой, а CI проверяет типы, линт и тесты на каждом изменении.

## Контекст
Первая задача разработки. PRODUCT.md 1.2 и ARCHITECTURE.md 0.3 утверждены. Архитектура задаёт: монорепозиторий, единый TypeScript-стек, четыре приложения (сервер, мобильное, кабинет поставщика, админка) и общие пакеты (контракты, доменные правила, UI-кит, локализация интерфейса). Эта задача создаёт форму, в которую лягут все последующие задачи, поэтому важнее сделать её аккуратно, чем быстро.

## Текущее состояние
- В репозитории только документы: PRODUCT.md, ARCHITECTURE.md, CLAUDE.md, tasks/. Кода нет.
- CLAUDE.md, блок «0. Проект», заполнен планируемыми командами с пометкой «уточнить после TASK-001».
- Ограничений по версиям инструментов от Product Owner нет; ориентируйся на актуальные стабильные версии и ARCHITECTURE 3–4.

## Требования
1. Структура монорепозитория по ARCHITECTURE 4: приложения и пакеты в согласованных местах, общие пакеты подключаются без публикации.
2. Каркасы приложений, каждый запускается и показывает заглушку «работает»:
   - сервер: HTTP-процесс с health-эндпоинтом и отдельная точка входа для worker-процесса (пока пустая);
   - мобильное приложение: стартует на симуляторе/эмуляторе;
   - кабинет поставщика и админка: стартуют в браузере.
3. Каркасы пакетов: контракты (с одной тестовой схемой и её использованием на сервере и в одном клиенте), доменные правила (с одной функцией и тестом, например нормализация артикула по ARCHITECTURE 10), UI-кит, локализация интерфейса (три языка, один ключ).
4. Локальное окружение: PostgreSQL, Redis, Meilisearch, S3-совместимое хранилище поднимаются одной командой; пример файла переменных окружения; секретов в репозитории нет.
5. Единые инструменты качества на весь репозиторий: форматирование, линт (включая запрет импортов через границы пакетов, ARCHITECTURE 4), проверка типов, тесты.
6. CI: на каждый push и pull request — установка, линт, типы, тесты, сборка веб-приложений и сервера. Мобильная нативная сборка в CI этой задачей не требуется.
7. Актуализировать блок «0. Проект» в CLAUDE.md фактическими командами. Остальной CLAUDE.md не менять.
8. Значимые технические решения (менеджер пакетов, инструмент сборки, версии платформ, структура) зафиксировать в ARCHITECTURE.md, если они уточняют или отклоняются от написанного.

## Бизнес-правила
Не применимы. Единственное продуктовое ограничение — язык: идентификаторы, комментарии и коммиты на английском (CLAUDE.md 5).

## Edge cases
- Разработчик на Windows и на macOS должны поднимать окружение одинаковыми командами.
- Пакет не должен уметь импортировать внутренности другого пакета в обход его публичного входа.

## Не входит в задачу
- Модель данных, миграции, реальные эндпоинты (TASK-002).
- Контракт клиент–сервер сверх одной демонстрационной схемы (TASK-003).
- Аутентификация, любая бизнес-логика.
- Настройка staging/prod, деплой, публикация в сторы.
- Реальные интеграции с внешними сервисами.
- README и документация сверх CLAUDE.md.

## Acceptance Criteria
1. Свежий клон, одна команда установки и одна команда запуска зависимостей — все четыре приложения стартуют по командам из CLAUDE.md.
2. Health-эндпоинт сервера отвечает; worker-процесс запускается отдельной командой и корректно завершается.
3. Демонстрационная схема из пакета контрактов используется и на сервере, и в клиенте; изменение схемы ломает типы там и там.
4. Тест доменной функции проходит; тесты запускаются одной командой для всего репозитория.
5. Линт запрещает импорт через границы пакетов: намеренно неправильный импорт падает на линте.
6. CI зелёный на чистом репозитории; в CI выполняются линт, типы, тесты, сборка.
7. В репозитории нет секретов; есть пример файла переменных окружения.
8. Блок «0. Проект» в CLAUDE.md соответствует фактическим командам; diff остального CLAUDE.md пуст.

## Что должно реально работать
- Сценарий «новый разработчик»: клон → установка → запуск окружения → запуск сервера → открыть health → запустить админку в браузере → запустить мобильное на эмуляторе. Каждый шаг — командами из CLAUDE.md.
- Сценарий «сломанный контракт»: изменить тип поля в демонстрационной схеме → проверка типов падает и на сервере, и в клиенте.
- Сценарий «нарушение границы»: добавить импорт внутреннего файла чужого пакета → линт падает.
