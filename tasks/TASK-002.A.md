# TASK-002.A — FIX: интеграционные тесты падают в CI

## Цель
Интеграционные тесты и цикл миграций TASK-002 проходят не только локально, но и в CI на GitHub Actions. Результат подтверждён фактическим зелёным прогоном.

## Контекст
TASK-002 получила FAIL по AC-3 и AC-7. Локально всё прошло, но после push прогон CI на GitHub Actions упал на шаге `test:integration`. В отчёте TASK-002 проверка CI была помечена NOT RUN с пояснением «нет доступа к GitHub Actions». Остальные критерии TASK-002 приняты и переделке не подлежат.

## Текущее состояние
- Код TASK-002 в `main`, последний прогон CI красный, падает шаг `test:integration`.
- Причина падения Product Owner'у и продуктовой стороне неизвестна.
- В рабочем окружении есть токен GitHub (`.env`). Какие у него права — неизвестно.

## Требования
1. **Получи результат прогона сам.** Используя токен GitHub из окружения, получи статус последних прогонов CI и полный лог упавшего шага. Токен не выводить в терминал, лог, отчёт, коммит.
   Если токену не хватает прав на чтение Actions — остановись и в отчёте назови точные недостающие права (Product Owner добавит их). Не обходи ограничение.
2. **Найди причину** по логу, а не по догадке. Если локальная среда (Windows) отличается от CI (Linux) — назови, чем именно.
3. **Исправь** минимально: только то, что нужно, чтобы интеграционные тесты и цикл миграций проходили в CI. Не ослабляй и не пропускай тесты, не убирай шаг из CI.
4. **Если интеграционные тесты сейчас в CI не проверяют цикл миграций «применить → откатить → применить»** (AC-3 TASK-002) — добавь это в CI.
5. **Сэкономь минуты CI** (бесплатная квота): прогон только на push в `main` и на pull request; отмена устаревшего прогона при новом push в ту же ветку; кэш зависимостей, если его ещё нет.
6. **Подтверди фактом:** после push дождись завершения прогона и получи его итог через тот же доступ.
7. Если в процессе обнаружено, что корректное завершение процессов по сигналу (TASK-002, Known Issues) можно проверить в CI на Linux без существенного усложнения — проверь; если нет — не делай, укажи в отчёте.

## Не входит в задачу
- Изменения, не связанные с падением CI и экономией минут.
- Переделка принятых частей TASK-002.
- Новые таблицы, эндпоинты, модули.

## Acceptance Criteria
1. В отчёте приведена фактическая причина падения, подтверждённая фрагментом лога CI (без секретов).
2. Последний прогон CI после исправления — `success`; в отчёте ссылка на прогон и его статус, полученный через API/CLI, а не предположение.
3. В успешном прогоне выполнены шаги `test:integration` и цикл миграций «применить → откатить → применить».
4. Ни один тест не удалён, не пропущен и не ослаблен; шаг интеграционных тестов в CI остаётся.
5. CI запускается только на push в `main` и на pull request, устаревшие прогоны отменяются.
6. Токен не появился ни в выводе, ни в отчёте, ни в коммитах.
7. Если прав токена недостаточно — статус BLOCKED с перечнем недостающих прав (это допустимый исход).

## Что должно реально работать
- Push исправления → прогон CI на GitHub Actions зелёный, включая интеграционные тесты и миграции.
- Второй push, сделанный до завершения первого прогона, отменяет первый.
