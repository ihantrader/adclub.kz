# TASK-005.A — Доводка этапа A по итогам сквозной проверки TASK-001…TASK-005

Модель: Sonnet 5, Medium

## Цель

Закрыть дефекты и пропуски TASK-001…TASK-005, найденные сквозной проверкой, до начала TASK-006. Поведение продукта не меняется.

## Контекст

TASK-001…TASK-005 приняты. Повторная сверка требований с кодом (а не с отчётами) нашла:

- одно невыполненное требование TASK-002 — политика необратимых изменений схемы в ARCHITECTURE.md;
- утечку внутренних деталей инфраструктуры через публичный маршрут готовности;
- пробелы в проверках (корректное завершение API, граница пакетов на линте) и в инструкции запуска.

- ARCHITECTURE.md 0.9, PROJECT_PLAN.md 1.7, PRODUCT.md 1.3, SCREENS.md 1.0.

  - В проверке SMS-лимитов счётчик номера растёт раньше проверки лимита по IP.

## Требования

1. **Правки Product Owner.** Первым действием закоммитить `PROJECT_PLAN.md`, `PROJECT_STATE.md` и все новые файлы `tasks/` отдельным коммитом по D-024.
2. **Маршрут готовности.** Ответ `/ready` показывает состояние каждой зависимости, но не содержит текста ошибок драйверов, адресов, портов, имён пользователей и других внутренних деталей. Подробная причина пишется только в журнал. Изменение контракта — совместимое (проверка совместимости проходит без трейлера); если без ломающего изменения не обойтись — обосновать в отчёте.
3. **Политика необратимых изменений схемы** в ARCHITECTURE.md: удаление и переименование колонок и таблиц, смена типа, очистка и преобразование данных. Как такие изменения выполняются поэтапно, что делается с down-частью, как откатываться на базе с данными, какие проверки обязательны перед применением.
4. **Инструкция запуска.** В CLAUDE.md, блок 0 — шаг создания `.env` из `.env.example`. Проверить на чистой копии репозитория, что по инструкции поднимаются API, worker и миграции.
5. **Корректное завершение процессов.**
   - API по сигналу завершается корректно, и это проверяется в CI так же, как для worker.
   - Остановка API и worker ограничена по времени: если закрытие зависло или упало, процесс всё равно завершается с ненулевым кодом и записью в журнал.
   - Повторный сигнал не запускает закрытие второй раз.
6. **Срок админской сессии.** Значение больше 12 часов в настройке не принимается: процесс не стартует с понятной ошибкой.
7. **Образ MinIO** в dev-окружении закреплён на конкретной версии.
8. **Граница пакетов.** Линт запрещает импорт внутренностей чужого пакета и через относительный путь, во всех приложениях и пакетах. Правила границ (пакетов и модулей `apps/api`) покрыты автоматическими тестами.
9. **Лимиты кодов входа.** Отказ по лимиту на IP не расходует SMS-лимит номера.

## Бизнес-правила

- Внутренние детали инфраструктуры не попадают в ответы API.
- Админская сессия не живёт дольше 12 часов ни при каких настройках.

## Edge cases

- `/ready` при недоступной PostgreSQL, при неверном пароле БД, при недоступных Redis и S3: в ответе нет адреса, порта, имени пользователя и текста драйвера; после восстановления — снова «ok» без перезапуска.
- Зависшее закрытие подключения при остановке.
- Два сигнала остановки подряд.
- Относительный импорт из приложения в `src` другого пакета; импорт внутри своего пакета остаётся разрешён.

## Не входит в задачу

- Роли, права, порядок отказа во входе в кабинет и админку — TASK-006.
- Санитайзер журнала, поле `context` журнала, коды ошибок прочих 4xx — TASK-009.
- Возврат SMS-попытки в счётчик при недоставке ни одним каналом — открытый продуктовый вопрос, не в этой задаче.
- Любые изменения продуктового поведения.

## Что должно реально работать

- Остановить PostgreSQL → запросить `/ready` → статус «ошибка» без внутренних деталей → поднять PostgreSQL → `/ready` снова «ok».
- Свежая копия репозитория → шаги из CLAUDE.md → `/health` отвечает, миграции применены.
- Запустить API → отправить сигнал остановки → процесс завершился в пределах лимита.
