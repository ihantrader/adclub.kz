# TASK-010.A — Доводка по приёмке TASK-010 и стабильность dev и CI

Модель: Opus 5, High

## Цель

Закрыть замечания приёмки TASK-010 и вернуть надёжность рабочему окружению: `pnpm dev` снова запускает всё одной командой, а CI краснеет только из-за настоящих дефектов. Продуктовое поведение не меняется.

## Контекст

TASK-010 принята (PASS WITH NOTES). При приёмке найдено:

1. **Порядок соседей перезаписывается молча.** `PUT …/order` для категорий, характеристик и вариантов списка не проверяет версию: два администратора сохраняют разный порядок — побеждает последний, первый об этом не узнаёт. TASK-010 требовала, чтобы одновременная правка не перезаписывала чужое изменение молча. Повторная отправка того же порядка пишет лишнюю запись в журнал действий.
2. **404 клиентских маршрутов справочника без явного запрета кэширования.** Прокси, кэширующий 404 по умолчанию, может дольше заявленных 60 секунд показывать 404 для только что восстановленной категории.

Замечания окружения, накопившиеся за несколько задач:

3. **`pnpm dev` из корня не стартует.** Turborepo: «You have 10 persistent tasks but `turbo` is configured for concurrency of 10». Постоянных задач `dev` стало 10 после TASK-075 (`ui-core`, `ui`). Это основная команда запуска из CLAUDE.md, на ней стоят ручные проверки интерфейса Product Owner.
4. **Нестабильные интеграционные тесты фоновых задач и очистки.** CI несколько раз краснел не из-за кода задачи: `jobs.integration.test.ts` «runs each scheduled occurrence once with two workers» (CI 35327943796), ранее — другие тесты расписания (TASK-009.A, три красных прогона подряд); `sign-in-data-cleanup.integration.test.ts` «Cleanup identity.cleanup-login-codes did not complete: gone» (локально). Тесты окон лимитов кодов и расписания зависят от расхождения часов процесса и контейнера PostgreSQL/Redis (на машине разработки Docker VM расходится с хостом на секунды).

## Требования

1. **Порядок без молчаливой перезаписи.** Изменение порядка соседей (категорий, характеристик, вариантов) учитывает, от какого состояния порядка его сделали; если порядок успел измениться — отказ с кодом конфликта, ничего не перезаписывается. Отправка того же порядка, что уже сохранён, ничего не меняет и не пишет запись в журнал действий. Изменение контракта — аддитивное.
2. **404 клиентских маршрутов справочника не кэшируется** прокси и клиентом дольше, чем разрешено для успешных ответов (или не кэшируется совсем) — заголовки проверены тестом.
3. **`pnpm dev` из корня** запускает API, кабинет, админку и сборку общих пакетов в режиме наблюдения одной командой, как описано в CLAUDE.md, с запасом на будущие пакеты. Проверить фактическим запуском.
4. **Стабильность тестов.** Нестабильные тесты из контекста проходят надёжно: причина найдена и устранена, а не замаскирована повтором. Проверки не ослабляются. Тесты, зависящие от времени, не зависят от расхождения часов процесса и контейнеров или явно учитывают его. Доказательство — многократный прогон (число прогонов на усмотрение агента, не меньше 10 для каждого исправленного теста) локально и зелёные прогоны CI.
5. **Документация.** ARCHITECTURE.md (версия, история, решения); CLAUDE.md, блок 0 — если меняется запуск dev.

## Бизнес-правила

- Изменение одного администратора не исчезает молча из-за изменения другого.
- Восстановленная категория видна клиентам не позже заявленного времени.

## Edge cases

- Два администратора одновременно сохраняют разный порядок одних и тех же подкатегорий; то же для характеристик и вариантов.
- Один администратор повторно отправляет тот же порядок.
- Категория скрыта → клиент получил 404 → категория восстановлена → повторный запрос через прокси.
- Прогон интеграционных тестов под нагрузкой (полный набор параллельно).

## Не входит в задачу

- Позиции справочника — TASK-011.
- Уникальность названий при автопереводе — TASK-012 (замечание записано туда).
- Синхронизация часов Docker VM на машине разработки.

## Acceptance Criteria

- **AC-1.** Тесты: одновременное сохранение разного порядка — второе получает конфликт, порядок первого сохранён; повторная отправка того же порядка не создаёт записи в журнале — для категорий, характеристик и вариантов.
- **AC-2.** Тест: 404 клиентских маршрутов справочника с заголовками, запрещающими кэширование сверх разрешённого.
- **AC-3.** `pnpm dev` из корня стартует; в отчёте — фактический вывод запуска и ответы API, кабинета и админки.
- **AC-4.** Для каждого нестабильного теста из контекста — найденная причина, исправление и доказательство (многократный прогон); проверки не ослаблены — в отчёте diff проверок.
- **AC-5.** Контракт совместим без трейлера; существующие тесты проходят без ослабления; коммиты по D-024 с составом в отчёте; CI на `main` зелёный, включая коммит с отчётом (номер и статус через `gh`).
- **AC-6.** ARCHITECTURE.md и (при изменении запуска) CLAUDE.md обновлены.

## Что должно реально работать

- `pnpm dev` из корня → API на `:3000` отвечает `/health`, кабинет на `:5175` и админка на `:5174` открываются.
