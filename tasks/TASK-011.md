# TASK-011 — Позиции справочника

Модель: Opus 5, High

## Цель

Администратор заводит позиции справочника трёх видов — запчасти по артикулу, товары по характеристикам и услуги, — заполняет их характеристики, в том числе массово, и связывает аналоги. Один артикул одного бренда — одна карточка. Позиции, у которых не заполнены обязательные для полноты характеристики, помечаются неполными, но не блокируются.

## Контекст

Вторая задача EPIC-04 «Справочник товаров и услуг». Опирается на категории и характеристики (TASK-010). От неё зависят переводы (TASK-012), фото (TASK-013), совместимость (EPIC-05), предложения поставщиков (EPIC-07), каталог и поиск.

- **PRODUCT 7.1:** справочник ведёт администратор; поставщик позиции не создаёт, а выбирает из справочника.
- **PRODUCT 7.3:** основной ключ запчасти — артикул производителя; один артикул одного бренда = одна карточка; поиск по артикулу обязателен; часть товаров описывается набором характеристик (моторное масло: бренд, вязкость, допуск, объём) — справочник поддерживает оба типа.
- **PRODUCT 7.4:** характеристики задаются на уровне категории; при добавлении характеристики у существующих позиций значение пустое; нужен способ массового дозаполнения; до заполнения позиции неполные, это не блокирует продажу.
- **PRODUCT 7.5:** аналоги оригинальных деталей — отдельные позиции справочника, видны рядом с оригиналом.
- **PRODUCT 11:** единый справочник услуг ведёт администратор.
- **ARCHITECTURE 5.2:** `catalog_item` (`category_id`, `item_type` part/generic/service, `brand_id`, `article`, `article_norm`, `status` draft/active/archived, `completeness`), уникальность `(brand_id, article_norm)` для запчастей; `brand` (`name`, `aliases`, `is_oem`); `item_attribute_value` (типизированные значения, отсутствие строки — пусто, `source` admin/import/ai); `item_analog` (`relation`, `status` proposed/approved). `packages/domain` — `normalizeArticle`.
- **SCREENS.md 1.1:**
  - A-CAT-02: при добавлении характеристики — «У N позиций значение будет пустым», «Дозаполнить».
  - A-CAT-03 «Дозаполнение»: таблица позиции × характеристика, «Только пустые», правка в ячейке.
  - A-CAT-04 «Позиции»: поиск по артикулу и названию; отборы — категория, бренд, неполные характеристики (остальные отборы — с их задачами).
  - A-CAT-05 «Карточка позиции», вкладка «Основное»: тип, бренд, артикул и нормализованный вид, категория, название; дубль «бренд + артикул» — «Такая позиция уже есть» со ссылкой; вкладки «Характеристики», «Аналоги».
- **D-003, D-022, D-024** — как в предыдущих задачах.

## Текущее состояние

- **Справочник** (TASK-010, TASK-010.A; ARCHITECTURE 4.15–4.16): категории двух уровней товаров и услуг, характеристики подкатегорий (число, список, да/нет, текст; «фильтр», «участвует в полноте»; архивирование), названия kk/ru/en в общей таблице `translation` с признаком ручной правки, версии строк и конфликт одновременной правки, порядок с `expectedOrder`, одна блокировка на изменения структуры, журнал действий в той же транзакции, клиентские ответы с кэшем до 60 с, ошибки без кэша; модуль `apps/api/src/modules/catalog`; dev-заполнение `operator dev:catalog:seed`.

- Журнал действий, санитайзер, настройки, фоновые задачи — есть (этап A). `pnpm dev` из корня работает.

## Требования

### 1. Бренды

- Бренд: название, другие написания (например, «Geely» и «GEELY Auto»), признак «оригинальный производитель». Администратор создаёт, изменяет, архивирует.
- Название и написания уникальны среди всех брендов без учёта регистра и пробелов — одно написание не может принадлежать двум брендам.
- Архивный бренд нельзя выбрать для новой позиции; существующие позиции его сохраняют.

### 2. Позиции

- **Виды:**
  - **запчасть** — бренд и артикул обязательны, категория товаров;
  - **товар по характеристикам** (масло, жидкости) — бренд, характеристики, без обязательного артикула, категория товаров;
  - **услуга** — без бренда и артикула, категория услуг.
  Вид позиции не меняется после создания.
- **Категория** — только подкатегория (второй уровень) подходящего вида: товары для запчастей и товаров, услуги для услуг; активная или скрытая, не архивная.
- **Название** kk/ru/en в общей модели переводов: русское обязательно, остальные можно оставить пустыми (автоперевод — TASK-012).
- **Артикул** хранится как введён и в нормализованном виде (`normalizeArticle`). Пустой после нормализации артикул — ошибка.
- **Уникальность запчасти:** один нормализованный артикул одного бренда — одна позиция, это держит база. Попытка создать дубль или изменить позицию так, что она совпадёт с другой, — отказ «Такая позиция уже есть» со ссылкой (идентификатором) на существующую.
- **Уникальность товара по характеристикам:** в одной категории одного бренда не может быть двух позиций, у которых все характеристики «участвует в полноте» заполнены и совпадают, — отказ с той же ссылкой. Незаполненные характеристики совпадением не считаются.
- **Состояния:** черновик / активна / в архиве. Удаления нет. Черновик — для позиций, которые готовятся или пришли запросом (запросы поставщиков — позже). Архивную позицию нельзя выбрать для новых предложений (EPIC-07), история её сохраняет.
- **Смена категории** — только в подкатегорию того же вида. Значения характеристик прежней категории к новой не относятся и в формах не показываются; сохраняются ли они — решение агента, описать в ARCHITECTURE; полнота пересчитывается.
- **Одновременная правка** не перезаписывает чужое изменение молча (версия, как в TASK-010).
- Каждое изменение — запись в журнале действий в той же транзакции.

### 3. Значения характеристик

- Значение хранится по типу характеристики: число (в границах, целое, если так задано), вариант списка (только активный вариант этой характеристики), да/нет, текст (ограничение длины). Пустое значение — отсутствие значения.
- Значение можно задать только для характеристики категории позиции. Для архивной характеристики новое значение задать нельзя; сохранённые значения остаются.
- Источник значения фиксируется (администратор; импорт и ИИ — позже).

### 4. Полнота

- Позиция **неполная**, если хотя бы одна активная характеристика её категории с признаком «участвует в полноте» не заполнена; иначе полная.
- Полнота всегда соответствует данным: пересчитывается при изменении значений, при добавлении, архивировании и восстановлении характеристики, при смене признака «участвует в полноте», при смене категории позиции. Способ — на усмотрение агента; расхождение между сохранённой полнотой и фактической недопустимо и проверяется тестом.
- Неполнота не блокирует ничего (PRODUCT 7.4).
- При добавлении характеристики с признаком «участвует в полноте» администратор видит, у скольких позиций значение будет пустым (SCREENS A-CAT-02): число возвращается в ответе создания характеристики или отдельным запросом.

### 5. Массовое дозаполнение

- Таблица «позиции × характеристики» категории с отбором «только пустые» (по выбранной характеристике), постранично.
- Изменение значений многих ячеек одним запросом: каждая ячейка проверяется по правилам требования 3; запрос применяется целиком или не применяется вовсе, ответ перечисляет ошибки по ячейкам.
- Изменение ячейки, которую другой администратор изменил после чтения, — конфликт (не молчаливая перезапись).
- Каждое применённое изменение — в журнале действий (допустима одна запись на запрос с перечнем изменений; описать).
- Ограничение размера запроса — описать.

### 6. Аналоги

- Администратор связывает позицию с её аналогом и снимает связь. Связь — между двумя позициями вида «запчасть» одной подкатегории, симметричная (если Б — аналог А, то А — аналог Б), без связи позиции с собой и без дублей.
- Архивная позиция в новых связях не участвует; существующие связи сохраняются.
- Связи от поставщиков на рассмотрении — позже (EPIC-07/модерация); модель должна это позволить.

### 7. API для администратора

- Бренды: список с поиском, создание, изменение, архивирование.
- Позиции: список с поиском по артикулу (по нормализованному виду, в том числе по части артикула) и по названию (на любом языке), отборами по категории, бренду, виду, состоянию, полноте; постранично; карточка позиции с характеристиками (значения по активным характеристикам категории, пустые — явно) и аналогами; создание, изменение, смена состояния; значения характеристик; дозаполнение; аналоги.
- Только в контексте `admin`.
- Клиентские маршруты позиций (каталог для пользователя и поставщика) — не в этой задаче: пользователю позиции показываются только при наличии предложений (PRODUCT 7.8, EPIC-07, EPIC-10).

### 8. Данные для разработки

`dev:catalog:seed` (или отдельная команда) дополняет примерное дерево позициями: несколько запчастей (колодки двух брендов, из них пара аналогов), несколько масел по характеристикам (часть — неполные), 2–3 услуги. Только development и тесты, повторный запуск без дублей.

### 9. Контракт и документация

- Маршруты, схемы, коды ошибок — в `contracts`, OpenAPI, `@adclub/api-client`; изменение аддитивное.
- ARCHITECTURE.md: подраздел решений 4.x (модель позиций и брендов, уникальность двух видов, полнота и её согласованность, дозаполнение, аналоги, поиск по артикулу), уточнение 5.2, версия и история.
- CLAUDE.md, блок 0: как заполнить позиции в dev и найти позицию по артикулу через API.

## Бизнес-правила

- Один артикул одного бренда — одна карточка.
- Позицию создаёт и меняет только администратор.
- Неполная позиция продаётся; неполнота — пометка, а не запрет.
- Удаления нет — архивирование.
- Аналог — отдельная позиция, связь явная.
- Вид позиции не меняется.

## Edge cases

- Артикул «04465-0K090», «04465 0k090», «044650K090» одного бренда — одна позиция; тот же артикул другого бренда — другая.
- Две одновременные попытки создать одну и ту же запчасть — ровно одна успешна, вторая получает ссылку на первую.
- Смена бренда или артикула существующей позиции на занятую пару.
- Масло того же бренда с теми же вязкостью, допуском и объёмом в той же категории; с незаполненным допуском.
- Характеристика «участвует в полноте» добавлена в категорию с сотней позиций → все неполные; архивирована → снова полные; признак снят → полные.
- Значение с архивным вариантом списка; число вне границ; дробное для целой характеристики; значение для характеристики другой категории.
- Дозаполнение: одна ячейка из пятидесяти с ошибкой; ячейку одновременно меняет другой администратор.
- Позиция в скрытой категории; в архивной категории; перенос в категорию другого вида.
- Аналог сам себе; аналог из другой подкатегории; аналог — услуга; повторная связь; связь с архивной позицией.
- Поиск по части артикула и по названию на казахском.
- Мобильная сессия и сессия кабинета вызывают маршруты администратора.

## Что должно реально работать

В dev, запросами к API от администратора:

- Заполнить dev-базу → найти колодки по артикулу «04465 0k090» → найдена позиция с артикулом «04465-0K090».
- Создать ту же запчасть с артикулом «044650K090» → отказ «Такая позиция уже есть» со ссылкой.
- Добавить к «Моторным маслам» характеристику с «участвует в полноте» → ответ показывает число позиций с пустым значением → в списке с отбором «неполные» они есть → дозаполнить их одним запросом → отбор «неполные» пуст.
- Дозаполнение с одной ошибочной ячейкой → ничего не применено, ошибка указана по ячейке.
- Связать две колодки как аналоги → карточка каждой показывает другую → снять связь.
- В журнале действий видны все изменения с автором.
