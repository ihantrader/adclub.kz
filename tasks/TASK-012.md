# TASK-012 — Переводы справочника

Модель: Opus 5, High

## Цель

Названия справочника автоматически переводятся на казахский и английский, администратор может исправить перевод вручную, и ручная правка никогда не затирается автопереводом. Перевод выполняется фоновой задачей через внутренний интерфейс ИИ с тестовой реализацией — подключение настоящего провайдера не требует переделки.

## Требования

### 1. Интерфейс ИИ

- Внутренний интерфейс шлюза ИИ (`AiGateway` по ARCHITECTURE 9.6) с операцией перевода: вход — тексты и целевые языки, выход — переводы по схеме. Реализация выбирается конфигурацией.
- **Тестовая реализация** (для dev, тестов и CI) — без обращения к внешним сервисам, детерминированная, умеет: вернуть перевод, вернуть ошибку, ответить медленно, вернуть текст, не проходящий проверку (чтобы такие случаи проверялись тестами).
- **Реализация через Claude** (`claude-sonnet-5`): подключается ключом в конфигурации; без ключа не используется, приложение работает на тестовой реализации. Настоящий вызов внешнего сервиса в этой задаче не выполняется и в CI не делается; если ключа нет — так и написать в отчёте.
- Каждый вызов фиксируется записью учёта (`ai_job`, вид `translate`): вид, провайдер, модель, инициатор, статус, использованные токены и стоимость, если провайдер их сообщает; ошибки — с безопасным для журнала текстом. Персональных данных в записи нет.
- Дневной предел расходов на ИИ (`ai_daily_budget_usd`, настройка) учитывается: при исчерпании новые задачи перевода не отправляются, событие видно оператору; сами лимиты гостевого режима и помощника — не в этой задаче.

### 2. Что и когда переводится

- Переводятся названия категорий, характеристик, вариантов списков, позиций, брендов и единицы измерения — то, что уже хранится в `translation`.
- **Источник — русский текст.** Перевод ставится в очередь, когда русский текст создан или изменён и для языка нет ручной правки.
- **Ручная правка не затирается никогда:** строка с ручной правкой автопереводом не перезаписывается, даже если исходный текст изменился. Такой перевод помечается устаревшим (исходник изменился), и администратор видит это.
- **Перевод с `origin = ai` при изменении исходника** заменяется новым автопереводом.
- **Повторный перевод по требованию** администратора — только для строк `origin = ai` (SCREENS A-CAT-05).
- Пустой или отсутствующий перевод не мешает работе: клиентам по-прежнему отдаётся русский с признаком отката.

### 3. Фоновая обработка

- Перевод выполняется фоновой задачей (TASK-008): пакетами, с повторами при временных ошибках и мёртвой очередью при окончательных.
- Постановка задачи — в той же транзакции, что и изменение текста: нет изменения без задачи и задачи без изменения.
- Размер пакета, число повторов и дневной предел — настройки.
- Повторное выполнение задачи не создаёт дублей и не портит данные (идемпотентность).
- Недоступность провайдера не ломает работу справочника: тексты остаются прежними, ошибки видны оператору.

### 4. Проверки перевода

- Перевод проходит те же проверки, что ручной ввод: длина, отсутствие управляющих символов, **уникальность названия среди соседей** (категории, характеристики, варианты — той же проверкой и под той же блокировкой, что у администратора).
- Не прошедший проверку перевод не сохраняется: строка остаётся без перевода (откат на русский), случай виден оператору и не повторяется бесконечно.

### 5. API для администратора

- Просмотр переводов сущности: по полям и языкам — текст, источник (`исходник` / `ИИ` / `вручную`), признак «исходник изменился», модель и время для автоперевода.
- Ручная правка перевода (ставит признак ручной правки) и снятие ручной правки с постановкой в очередь автоперевода.
- «Перевести заново» — для строк `origin = ai`; для строк с ручной правкой — отказ с понятным кодом.
- Список того, что ждёт перевода или устарело, с отбором по виду сущности и языку — чтобы администратор видел объём работы.
- Только в контексте `admin`; каждое изменение — в журнал действий в той же транзакции.

### 6. Клиенты

- Отдача названий клиентам не меняется: язык запроса, откат на русский с признаком. Автоперевод появляется у клиентов не позже времени кэширования (60 с).

### 7. Данные для разработки и документация

- В dev автоперевод работает на тестовой реализации: после `dev:catalog:seed` и запуска worker'а казахские и английские названия появляются у того, где их нет.
- ARCHITECTURE.md: подраздел решений 4.x (интерфейс ИИ и его реализации, учёт вызовов, очередь переводов, устаревание по `source_hash`, проверки перевода), уточнение 5.4 и 9.6, ключи настроек в 14, версия и история.
- CLAUDE.md, блок 0: как в dev увидеть автоперевод, как посмотреть очередь переводов и записи учёта вызовов; **добавить пропущенное из TASK-011.A** — отбор `sameProduct=matching`, поле `sameProductItems`, dev-задача `dev.daily-at-setting`.

## Бизнес-правила

- Ручная правка перевода важнее автоперевода и не затирается.
- Автоперевод — рабочий текст, отдельного подтверждения не требует (ARCHITECTURE 5.4).
- Исходный язык — русский; отсутствие перевода не блокирует ничего.
- Названия среди соседей уникальны и после автоперевода.
- Расходы на ИИ ограничены настройкой.

## Edge cases

- Русский текст изменён у строки с ручной правкой на казахском и автопереводом на английском.
- Провайдер вернул пустой текст, слишком длинный текст, текст с управляющими символами, текст на другом языке.
- Провайдер недоступен или отвечает медленно; временная ошибка и окончательная ошибка.
- Дневной предел расходов исчерпан в середине пакета.
- Два быстрых изменения исходника подряд — сохраняется перевод последнего, а не предыдущего.
- Автоперевод совпал с названием соседа.
- Сущность удалена (архивирована) до выполнения задачи перевода.
- Повторное выполнение той же задачи после сбоя.
- Администратор правит перевод, пока задача перевода в очереди.

- **AC-1.** Интерфейс ИИ с двумя реализациями; тестовая умеет возвращать перевод, ошибку, медленный ответ и негодный текст; без ключа приложение работает на тестовой — тесты.
- **AC-2.** Каждый вызов фиксируется записью учёта с моделью, статусом и стоимостью (если известна), без персональных данных — тесты.
- **AC-3.** Изменение русского текста ставит задачу перевода в той же транзакции; откат транзакции не оставляет задачи — тест.
- **AC-4.** Ручная правка не затирается автопереводом ни при каких условиях; при изменении исходника помечается устаревшей — тесты.
- **AC-5.** Автоперевод заменяется новым при изменении исходника; повторный перевод по требованию работает для `ai` и отклоняется для ручной правки — тесты.
- **AC-6.** Негодный перевод (пустой, длинный, с управляющими символами, совпадающий с соседом) не сохраняется, виден оператору и не повторяется бесконечно — тесты.
- **AC-7.** Недоступность провайдера и исчерпанный дневной предел не ломают справочник и не теряют изменения — тесты.
- **AC-8.** Повторное выполнение задачи не создаёт дублей — тест.
- **AC-9.** API администратора: просмотр, правка, снятие ручной правки, повторный перевод, список ожидающих и устаревших; только контекст `admin`; журнал действий — тесты.
- **AC-10.** Клиенты получают автоперевод не позже времени кэширования; откат на русский работает как прежде — тест.
- **AC-11.** В dev после заполнения и запуска worker'а появляются казахские и английские названия — фактический прогон в отчёте.
- **AC-12.** Контракт, OpenAPI, клиент — аддитивно, совместимость без трейлера; миграции обратимы; таблицы в сверке схемы; существующие тесты не ослаблены; перехват вывода чист.

## Что должно реально работать

В dev (API, worker, серверная команда):

- Заполнить справочник → запустить worker → у категорий и позиций появляются казахские и английские названия с источником «ИИ»; гость видит их на своём языке.
- Исправить казахское название вручную → изменить русское → автоперевод обновил английский, казахский остался ручным и помечен «исходник изменился».
- «Перевести заново» для английского — работает; для казахского с ручной правкой — отказ.
- Снять ручную правку с казахского → он переводится заново.
- Сделать провайдера недоступным → изменения сохраняются, задачи повторяются, затем уходят в мёртвую очередь; после восстановления перевод выполняется.
- Исчерпать дневной предел → новые переводы не отправляются, событие видно оператору.
