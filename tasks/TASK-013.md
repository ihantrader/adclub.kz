# TASK-013 — Фотографии позиций

Модель: Opus 5, High

## Цель

У позиции справочника есть фотографии: администратор загружает их или подтверждает присланные, у каждой видно источник, клиенты получают ссылки с ограниченным сроком, а где фото нет — заглушку. Подтверждает фотографию всегда человек.

Поиск фотографий ИИ и загрузка поставщиком подключаются позже на эту же модель.

Четвёртая, завершающая задача EPIC-04. Опирается на позиции (TASK-011) и переводы (TASK-012).

## Требования

### 1. Загрузка и хранение

- Администратор загружает файл изображения к позиции. Принимаются растровые форматы, пригодные для мобильного приложения и веба; векторные и потенциально опасные форматы (в том числе SVG) не принимаются. Проверка — по фактическому содержимому файла, а не по имени и заявленному типу.
- Предельный размер файла — настройка. Превышение — понятная ошибка, а не 500.
- Файл хранится в объектном хранилище; в базе — сведения о нём (ключ, тип, размер, размеры изображения, контрольная сумма), позиция, источник, статусы, кто и когда добавил.
- Повторная загрузка того же изображения к той же позиции не создаёт дубль.
- Данные, которые могут быть в файле и не нужны (координаты съёмки и прочие метаданные), не сохраняются вместе с изображением.
- Маршруты загрузки исключены из общей проверки «тело только JSON» (ARCHITECTURE 4.14).

### 2. Источник и подтверждение

- У фотографии обязательно указан источник: ссылка (для найденных в интернете) или пометка «снято поставщиком» / «загружено администратором».
- **Статусы:** кандидат → подтверждена → отклонена. Клиентам отдаются только подтверждённые.
- Подтверждает и отклоняет только администратор, с причиной при отклонении. Каждое действие — в журнал действий в той же транзакции.
- Модель позволяет добавить фотографии-кандидаты от ИИ (с типом источника и оценкой) и от поставщика, не переделывая её: это отдельные задачи.
- **Генерация изображений запрещена** — правило записать в ARCHITECTURE, чтобы будущие задачи ИИ его соблюдали.

### 3. Основная фотография и порядок

- У позиции есть основная фотография (показывается в списках) и порядок остальных. Основной может быть только подтверждённая.
- Удаление и отклонение основной фотографии переводит роль на следующую подтверждённую или оставляет позицию без фото.
- Позиция без подтверждённых фотографий отдаётся клиентам без фото — клиент показывает заглушку (DESIGN).

### 4. Выдача клиентам

- Ссылка на изображение выдаётся с ограниченным сроком действия (настройка) и не позволяет перебрать чужие файлы.
- Размеры для списка и карточки: клиент получает подходящий вариант, чтобы не грузить в списке полноразмерное изображение. Способ (заранее подготовленные варианты или преобразование по запросу) — на усмотрение агента, описать в ARCHITECTURE.
- Настройка `photo_display_mode`: при `copy` клиенту отдаётся наша копия, при `link` — ссылка на источник; поведение при каждом значении описать и покрыть тестом.
- Выдача фотографий встроена в существующие клиентские ответы справочника; отдельного публичного файлового хранилища не появляется.

### 5. Удаление и хранение

- Фотографию можно убрать: запись переходит в отклонённые или удалённые, файл в хранилище удаляется не сразу, а фоновой задачей по сроку (настройка) — чтобы ошибочное удаление можно было отменить в пределах срока.
- Файлы, на которые нет записей (например, загрузка прервалась), удаляются фоновой задачей.
- Удаление позиции (архивирование) фотографии не теряет.

### 6. Отказ хранилища

- Недоступность объектного хранилища не роняет API и не портит данные: загрузка отвечает понятной ошибкой с признаком «можно повторить», чтение справочника продолжает работать (без ссылок на изображения).

### 7. Контракт и документация

- Маршруты, схемы, коды ошибок — в `contracts`, OpenAPI, `@adclub/api-client`; изменение аддитивное; загрузка файла описана в OpenAPI.
- ARCHITECTURE.md: подраздел решений 4.x (хранение, ключи, проверка содержимого, варианты размеров, подписанные ссылки и их срок, отложенное удаление, `photo_display_mode`, запрет генерации изображений), уточнение 5.2 и 14, версия и история.
- CLAUDE.md, блок 0: как в dev загрузить фото, посмотреть его у позиции и проверить отложенное удаление.

## Бизнес-правила

- Фотография принадлежит позиции, а не поставщику.
- Публикуется только то, что подтвердил человек.
- У фотографии всегда известен источник.
- Сгенерированные изображения товаров недопустимы.
- Нет фото — заглушка, а не пустое место.

## Edge cases

- Файл с расширением `.jpg`, который на самом деле не изображение; SVG; файл больше предела; пустой файл; обрыв загрузки.
- Одна и та же картинка загружена дважды; одна картинка у двух разных позиций.
- Отклонение и удаление основной фотографии; удаление единственной.
- Подтверждение фотографии, которую параллельно отклонил другой администратор.
- Срок ссылки истёк — клиент получает новую при следующем запросе.
- Хранилище недоступно при загрузке, при выдаче и при фоновом удалении.
- `photo_display_mode` изменён при существующих фотографиях.
- Позиция архивирована, затем восстановлена.

## Acceptance Criteria

- **AC-1.** Загрузка изображения администратором работает; содержимое проверяется фактически (подделанное расширение, SVG, не изображение, пустой файл, превышение размера — понятные ошибки) — тесты.
- **AC-2.** Повторная загрузка того же изображения к той же позиции не создаёт дубль; ненужные метаданные не сохраняются — тесты.
- **AC-3.** Источник обязателен; статусы кандидат / подтверждена / отклонена; клиентам отдаются только подтверждённые; отклонение с причиной; журнал действий в той же транзакции — тесты.
- **AC-4.** Основная фотография и порядок по правилам требования 3, включая удаление основной и последней — тесты.
- **AC-5.** Ссылки для клиентов ограничены по сроку и не позволяют обратиться к чужим файлам; истёкшая ссылка заменяется новой — тесты.
- **AC-6.** Варианты размеров: в списке не отдаётся полноразмерное изображение — тест.
- **AC-7.** Оба значения `photo_display_mode` работают по описанию — тесты.
- **AC-8.** Отложенное удаление файлов и уборка файлов без записей выполняются фоновой задачей по срокам из настроек; повторный запуск задачи безопасен — тесты.
- **AC-9.** Недоступность хранилища: загрузка — понятная ошибка с признаком повтора, чтение справочника работает, процесс жив — тесты.
- **AC-10.** Маршруты загрузки не ломаются проверкой «тело только JSON»; остальные маршруты по-прежнему отвечают 415 на не-JSON — тесты.
- **AC-11.** Только контекст `admin` для загрузки и модерации (матрица предиката).
- **AC-12.** Контракт, OpenAPI (включая загрузку файла) и клиент — аддитивно, совместимость без трейлера; миграции обратимы; таблицы в сверке схемы; существующие тесты не ослаблены; перехват вывода чист.
- **AC-13.** Коммиты по D-024 с составом в отчёте; CI на `main` зелёный с первой попытки, включая коммит с отчётом (номер и статус через `gh`).
- **AC-14.** ARCHITECTURE.md (4.x, 5.2, 14, версия, история) и CLAUDE.md (блок 0) обновлены.

## Что должно реально работать

В dev (API, worker, MinIO):

- Загрузить фото к позиции → оно кандидат → подтвердить → в карточке позиции оно основное, ссылка открывается, в списке приходит уменьшенный вариант.
- Загрузить файл с расширением `.jpg`, который не изображение, и SVG → отказы с понятными ошибками.
- Отклонить основную фотографию → основной становится следующая подтверждённая; отклонить последнюю → позиция без фото.
- Удалить фотографию → файл остаётся в хранилище до срока → после запуска фоновой задачи с уменьшенным сроком файл удалён.
- Остановить MinIO → загрузка отвечает ошибкой с признаком повтора, дерево категорий и карточка позиции продолжают отвечать → поднять MinIO → загрузка работает.
- Переключить `photo_display_mode` на `link` и обратно → выдача меняется по описанию.
