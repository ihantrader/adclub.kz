# TASK-015 — Совместимость позиций с автомобилями

Модель: Opus 5, High

## Цель

Позиция справочника знает, к каким автомобилям она подходит, с той точностью, которая известна: «все Geely Atlas» или «только Atlas второго поколения с двигателем JLD-4G20». Для автомобиля пользователя, в том числе неполного, система однозначно отвечает: «подходит», «уточните параметр», «не подходит» или «совместимость не указана». Поставщик может предложить данные о совместимости, но в справочник они попадают только после подтверждения администратором.

## Контекст

Вторая, завершающая задача EPIC-05. Неверная совместимость — главный продуктовый риск: купленная деталь не встанет на машину, это прямой удар по доверию к клубу (PRODUCT 7.5).

- **PRODUCT 7.5:**
  - совместимость — атрибут позиции справочника, ответственность за неё несёт администратор;
  - поставщик может прислать свои данные о совместимости как предложение к рассмотрению; ручное подтверждение администратором обязательно;
  - аналоги — отдельные позиции, видны рядом с оригиналом, если совместимы с автомобилем пользователя;
  - **D-029:** у категории признак «совместимость обязательна». В таких категориях позиция без данных о совместимости **не показывается** при выбранном автомобиле, а без выбранного автомобиля видна с пометкой «совместимость не указана». В универсальных категориях позиции видны всегда;
  - позиция, которая не подходит к выбранному автомобилю, не показывается в списках; открытая по поиску или ссылке, показывается с заметным предупреждением, и при оформлении заявки пользователь подтверждает, что понимает это;
  - **неполный автомобиль:** если у автомобиля не указан параметр (например, двигатель), а совместимость позиции задана до этого параметра, позиция показывается с пометкой «уточните двигатель» и предложением дополнить автомобиль. Скрывать такие позиции нельзя.
- **ARCHITECTURE 5.3:** `item_compatibility` — позиция и условия по уровням (марка обязательна; модель, поколение, кузов, двигатель, КПП, привод, годы — необязательны; пустое поле означает «любой»), статус (предложена / подтверждена / отклонена), источник (администратор / поставщик / ИИ), основание, кто рассмотрел. Позиция совместима, если есть подтверждённая запись, у которой каждое заполненное поле совпадает с автомобилем, а год автомобиля попадает в диапазон. Результат для клиента: «точно» или «не хватает параметров» с перечнем полей.
- **ARCHITECTURE 4.23 (TASK-014, I230):** модель автомобилей заложена под совместимость с переменной точностью и неполный автомобиль.
- **DESIGN 7.8:** четыре отметки — «Подходит», «Не хватает параметра» (с кнопкой «Дополнить автомобиль»), «Не подходит», «Совместимость не указана».
- **SCREENS.md 1.1:** A-CAT-05, вкладка «Совместимость» — автомобили на любом уровне; предложения поставщиков «на рассмотрении»; проверки ИИ не применяются без подтверждения. A-MOD — очередь модерации.
- **D-004:** предложенное (поставщиком или ИИ) хранится отдельно от подтверждённого и подтверждается человеком.

## Требования

### 1. Записи о совместимости

- Позиция может иметь несколько записей; каждая — условия по уровням: марка обязательна, остальные уровни и годы необязательны. Незаполненный уровень означает «любой».
- Условия согласованы: модель принадлежит марке, поколение — модели, годы в пределах поколения, если оно указано; несогласованная запись отклоняется понятной ошибкой.
- Дубли подтверждённых записей одной позиции не создаются.
- Совместимость ведётся для позиций товаров (запчасти и товары по характеристикам); для услуг — не ведётся.
- Архивирование автомобиля не удаляет записи совместимости: у пользователей, выбравших этот автомобиль, результат не меняется.

### 2. Ведение администратором

- Администратор добавляет, изменяет и удаляет (или архивирует) подтверждённые записи позиции, с основанием (текст или ссылка).
- Одновременная правка не перезаписывает чужое молча; каждое изменение — в журнал действий в той же транзакции.
- Копирование совместимости с одной позиции на её аналог — одним действием (частый случай: аналог подходит к тем же машинам). Скопированное — подтверждённые записи с отметкой источника.
- Только контекст `admin`.

### 3. Предложения поставщика и модерация

- Сотрудник поставщика в сессии кабинета предлагает запись совместимости к позиции справочника с основанием (текст, ссылка на каталог). Предложение не влияет на результат для пользователей, пока его не подтвердили.
- Поставщик видит свои предложения и их состояние; отклонённые — с причиной. Чужие предложения ему не видны.
- Администратор видит очередь предложений (позиция, поставщик, условия, основание, дата), подтверждает как есть, подтверждает с правкой или отклоняет с причиной. Подтверждение создаёт подтверждённую запись.
- Совпадающее с уже подтверждённой записью предложение помечается и подтверждается без дубля.
- Ограничение частоты предложений от одного поставщика — настройка.
- Модель должна позволить позже добавить предложения от ИИ (источник «ИИ», проверка — отдельная задача этапа D).

### 4. Расчёт результата для автомобиля

- **Вход:** описание автомобиля — модификация целиком или частично известные уровни (марка, модель, поколение, кузов, двигатель, КПП, привод, год); неизвестные уровни — отсутствуют.
- **Результат для позиции:**
  - **«Подходит»** — есть подтверждённая запись, все заполненные условия которой совпадают с известными уровнями автомобиля и год попадает в диапазон;
  - **«Уточните параметр»** — ни одна запись не даёт «подходит», но есть запись, которая не противоречит автомобилю и требует уровней, неизвестных у автомобиля; в ответе перечислены недостающие уровни (например, «двигатель»);
  - **«Не подходит»** — у позиции есть подтверждённые записи, и каждая противоречит автомобилю;
  - **«Совместимость не указана»** — у позиции нет подтверждённых записей.
- Если подходят несколько записей — результат «лучший» из возможных: «подходит» важнее «уточните параметр».
- Неизвестный год у автомобиля при заданных годах в записи — это недостающий параметр («уточните год»).
- **Правило показа (D-029)** — отдельно от результата, чтобы клиенты не вычисляли его сами:
  - категория с обязательной совместимостью: при выбранном автомобиле показываются «подходит» и «уточните параметр»; «не подходит» и «совместимость не указана» — скрыты в списках. Без автомобиля видны все, «совместимость не указана» — с пометкой;
  - универсальная категория: позиции видны всегда; если записи есть — отметка по результату, если нет — без отметки;
  - «не подходит» в списках скрыта в любой категории; открытая напрямую — показывается с предупреждением, и в ответе есть признак «требует подтверждения пользователем при заявке».
- **Расчёт для многих позиций сразу** выполняется без запроса на каждую позицию: список позиций одной категории для одного автомобиля считается целиком на стороне базы. Производительность — разумное время на тысячах позиций; числа — в отчёте.
- Одна и та же функция расчёта используется везде (сервер, будущий каталог, будущий гараж); её правила покрыты тестами на таблице случаев, включая все четыре результата, неполный автомобиль, неизвестный год, несколько записей и граничные годы.

### 5. Маршруты для клиентов

- Проверка совместимости набора позиций для описания автомобиля: ответ по каждой позиции — результат, недостающие уровни, признак показа в списке и признак предупреждения. Доступно гостю и любой сессии; позиции, которых нет или которые в архиве, — одинаково «не найдено».
- Описание автомобиля в запросе проверяется: несогласованное (модель другой марки и т. п.) — понятная ошибка.
- Полноценный клиентский каталог с фильтром по автомобилю — EPIC-10 и EPIC-07; здесь — основа, которую он возьмёт.

### 6. Данные для разработки

- `dev:catalog:seed` (или отдельная команда) добавляет совместимость примерным позициям: колодки Geely — к конкретному поколению Atlas; их аналог TRW — через копирование; одна позиция в категории с обязательной совместимостью — без данных; одна — с записью, требующей двигатель. Только development и тесты, без дублей при повторе.

### 7. Контракт и документация

- CLAUDE.md, блок 0: как в dev добавить совместимость, предложить её от поставщика, подтвердить и проверить результат для автомобиля.

## Бизнес-правила

- В справочник попадает только подтверждённая администратором совместимость (D-004).
- Незаполненный уровень записи — «любой»; неизвестный уровень автомобиля — повод спросить, а не скрыть.
- В категориях с обязательной совместимостью позиция без данных не показывается при выбранном автомобиле (D-029).
- Несовместимая позиция не попадает в списки; открытая напрямую — с предупреждением и подтверждением при заявке.
- Поставщик видит только свои предложения.

## Edge cases

- Автомобиль без двигателя, запись требует двигатель; другая запись той же позиции подходит без двигателя.
- Автомобиль без года; запись с годами и запись без годов.
- Год автомобиля на границе диапазона; запись с годом начала без года окончания.
- Позиция с одной записью на другую марку; с записями на две марки.
- Запись ссылается на архивную модификацию; автомобиль пользователя архивирован в справочнике.
- Предложение поставщика совпадает с существующей записью; два поставщика предлагают одно и то же; предложение к архивной позиции.
- Копирование совместимости на аналог, у которого уже есть часть тех же записей.
- Поставщик пытается увидеть чужое предложение или подтвердить своё.
- Проверка тысячи позиций для одного автомобиля.

## Что должно реально работать

В dev, запросами к API:

- Колодки Geely подтверждены к Atlas второго поколения → проверка для Atlas второго поколения с известным двигателем — «подходит»; для Atlas первого поколения — «не подходит», скрыта в списке, признак предупреждения есть.
- Запись требует двигатель, у автомобиля двигатель не указан → «уточните параметр: двигатель», позиция показывается.
- Позиция в категории с обязательной совместимостью без записей → при выбранном автомобиле скрыта; без автомобиля — видна с «совместимость не указана».
- Скопировать совместимость колодок Geely на аналог TRW → аналог даёт тот же результат.
- Поставщик предлагает запись к позиции → результат для пользователя не изменился → администратор подтверждает → результат изменился; второе предложение отклонено с причиной → поставщик видит причину.
- Мобильная сессия пытается подтвердить предложение → отказ; поставщик другой компании не видит чужое предложение.
