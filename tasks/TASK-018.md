# TASK-018 — Предложения поставщиков на товары

Модель: Opus 5, High

## Цель

Поставщик в кабинете находит позицию справочника и выставляет на неё своё предложение: цену, наличие или «под заказ», срок, самовывоз и/или доставку, гарантию. Правит его прямо из списка, снимает с продажи и возвращает. Система умеет рассчитать дату получения по рабочим дням поставщика и однозначно сказать, видно ли предложение на витрине.

## Контекст

Первая задача EPIC-07 «Предложения поставщиков». Справочник (EPIC-04), автомобили и совместимость (EPIC-05), поставщики и сотрудники (EPIC-06) готовы. От этой задачи зависят услуги (TASK-019), каталог для пользователя (TASK-020), заявки (EPIC-08), импорт прайса (EPIC-16).

- **PRODUCT 7.1:** поставщик не создаёт позиции — выбирает из справочника и задаёт свою цену, наличие и условия; если позиции нет — запрос на добавление (модерация, этап C).
- **PRODUCT 9:** в предложении пользователь видит цену (клубную), наличие (в наличии / под заказ), срок и расчётную дату получения, способ получения (самовывоз и/или доставка), город (подписчику — район или адрес), рейтинг, гарантию (если указана), «проверенный партнёр». Рыночная цена не показывается.
- **PRODUCT 9.1:** поставщик указывает, делает ли доставку, и срок в днях с момента подтверждения заявки; система рассчитывает **дату** получения с учётом рабочих дней и нерабочих дат поставщика; пользователю показывается дата, а не срок. Доставку платформа не организует.
- **PRODUCT 12.3, 12.4:** снятые позиции не удаляются и остаются в кабинете отдельным списком; цены, наличие и сроки ведёт поставщик, правка — прямо из списка.
- **SCREENS.md 1.1:**
  - S-OFF-01 «Мои предложения»: вкладки «В продаже» / «Снятые»; поиск и отборы по своим предложениям («В наличии / Под заказ»); правка в строке — цена, наличие, срок; поле сохраняется сразу, «Сохранено» с «Отменить»; «Новая цена — для новых заявок»; «Снятые» — «Вернуть в продажу» с просьбой проверить цену; пусто — «Предложений пока нет».
  - S-OFF-02 «Поиск позиции справочника»: **только по запросу** (полный справочник не виден); результаты — категория, бренд, артикул, «Уже в ваших предложениях»; не найдено — запрос на добавление (этап C).
  - S-OFF-03 «Предложение на товар»: позиция только для чтения; поля — цена, наличие, срок в днях с подтверждения, получение (самовывоз / доставка, можно оба), гарантия по желанию; предпросмотр «Клиент увидит: Самовывоз — завтра, 14 марта».
  - A-SUP-03, вкладка «Предложения» — администратор только просматривает.
- **ARCHITECTURE 5.x:** `offer` — поставщик, точка выдачи, позиция, цена, валюта, наличие (in_stock / on_order), срок в днях, самовывоз, доставка, гарантия (месяцы или текст), статус (активно / снято / приостановлено), когда и почему снято (вручную / отсутствует в импорте), артикул и название у поставщика, ссылка на импорт. ARCHITECTURE 13.2: расчёт даты получения — чистая функция в `packages/domain`: от даты подтверждения прибавить срок в **рабочих днях поставщика** в его часовом поясе.
- **Решения:** D-003, D-022, D-024; D-005 (правила видимости — на сервере, на уровне ответа, с тестами) — полностью в TASK-020, здесь только признак видимости.

## Текущее состояние

- Позиции справочника трёх видов (TASK-011), фото (TASK-013), совместимость (TASK-015).
- Поставщик: одна точка выдачи (город, адрес, район), часы работы по дням недели, нерабочие даты, часовой пояс, статусы и признак `visibleOnShowcase` (TASK-016); сотрудники и права в кабинете (TASK-017); контекст `supplier` с компанией из сессии.
- Общее ограничение частоты открытых маршрутов (TASK-016); журнал действий, настройки, фоновые задачи.
- Предложений, клиентского каталога и заявок нет.

## Требования

### 1. Предложение

- Поставщик выставляет предложение на **активную позицию-товар** справочника (запчасть или товар по характеристикам; услуги — TASK-019) для своей точки выдачи. Одна позиция — одно предложение у точки (держит база); повторная попытка — понятная ошибка со ссылкой на существующее.
- **Поля:** цена в тенге (целое, в пределах настроек), наличие (в наличии / под заказ), срок в рабочих днях с момента подтверждения заявки (для «под заказ» обязателен и больше нуля), самовывоз и/или доставка (хотя бы одно), гарантия (месяцы или короткий текст, необязательно), свой артикул и название у поставщика (необязательно).
- Самовывоз возможен только при заполненном адресе точки выдачи; если адреса нет — понятная ошибка с подсказкой заполнить карточку.
- **Правка** каждого поля отдельным запросом (правка из списка), с версией; каждое изменение — в журнал действий с автором-сотрудником. Изменение действует для новых заявок; уже созданные заявки берут снимок (требование 5).
- **Снятие с продажи** вручную и **возврат в продажу**; снятое не удаляется и видно на вкладке «Снятые»; при возврате ответ напоминает проверить цену (признак в ответе).
- Предложение на позицию, которую администратор архивировал, остаётся у поставщика, но на витрине не видно; признак в ответе объясняет почему.

### 2. Поиск позиции для поставщика (S-OFF-02)

- Только по запросу: минимальная длина запроса, поиск по артикулу (как у администратора — по нормализованному виду и по части) и по названию на трёх языках.
- Только активные позиции-товары в видимых категориях; постранично с пределом размера страницы; без возможности выгрузить справочник целиком (нет пустого запроса, нет «всё подряд»).
- В каждом результате — категория, бренд, артикул, название на языке запроса, фото (миниатюра, если есть), признак «уже в ваших предложениях».
- Ограничение частоты запросов на сотрудника — настройка.

### 3. Мои предложения (S-OFF-01)

- Список своих предложений: вкладки «в продаже» / «снятые», поиск по названию и артикулу, отборы «в наличии / под заказ», «без фото»; постранично.
- В строке: название, артикул, цена, наличие, срок, самовывоз / доставка, признак видимости на витрине с причиной, если не виден.

### 4. Дата получения

- Чистая функция в `packages/domain`: по моменту подтверждения заявки, сроку в рабочих днях и расписанию точки (часы по дням недели, нерабочие даты, часовой пояс) возвращает дату получения. Используется для предпросмотра здесь и для каталога и заявок позже (TASK-020, EPIC-08) — одна функция на всех.
- **Правила (предположение, подтверждается Product Owner при приёмке):**
  - срок считается в рабочих днях точки; выходные дни недели и нерабочие даты пропускаются;
  - срок 0 («в наличии, забрать сразу»): если подтверждение пришло в рабочий день до конца рабочих часов — тот же день; иначе — ближайший рабочий день;
  - срок N > 0: N-й рабочий день после дня подтверждения;
  - круглосуточная точка — каждый день рабочий, если он не отмечен нерабочей датой;
  - если в ближайшие 60 дней нет ни одного рабочего дня — дату не рассчитывать и сообщить об этом (ошибка данных поставщика).
- Предпросмотр для поставщика: «Клиент увидит: Самовывоз — …» для момента «сейчас» — маршрут кабинета или поле ответа.
- Функция покрыта таблицей случаев: выходные, праздник подряд с выходными, конец рабочего дня, круглосуточно, смена года, часовой пояс.

### 5. Снимок предложения

- Способ зафиксировать, какими были условия предложения в момент создания заявки (цена, наличие, срок, самовывоз / доставка, гарантия, город и точка, название позиции), не зависящий от последующих правок и снятия предложения. Сами заявки — EPIC-08; здесь — модель и функция снимка, покрытые тестом.

### 6. Видимость на витрине

- Одна серверная функция отвечает, видно ли предложение пользователю, и почему нет: предложение активно; поставщик виден на витрине (не на паузе и не заблокирован, TASK-016); позиция активна, её категория и узел видимы; у точки есть город. Клиентский каталог (TASK-020) использует только её.
- При паузе и блокировке поставщика предложения не удаляются и не меняют своё состояние — только становятся невидимыми; после снятия паузы видны снова.

### 7. Администратор

- Просмотр предложений поставщика (только чтение), с теми же отборами и признаком видимости.

### 8. Контракт и документация

- Маршруты, схемы, коды ошибок — в `contracts`, OpenAPI, `@adclub/api-client`; изменение аддитивное.
- ARCHITECTURE.md: подраздел решений 4.x (модель предложения, поиск для поставщика, расчёт даты и его правила, снимок, функция видимости), уточнение 5.x, 13.2 и 14, версия и история.
- CLAUDE.md, блок 0: как в dev найти позицию от имени поставщика, выставить предложение, увидеть предпросмотр даты, снять и вернуть.

## Бизнес-правила

- Поставщик выбирает позиции из справочника, не создаёт их.
- Одна позиция — одно предложение у точки.
- Новая цена действует для новых заявок; условия созданной заявки не меняются.
- Снятое предложение не удаляется.
- Пользователь видит дату получения, а не срок; нерабочие дни поставщика не выдаются.
- Пауза и блокировка поставщика скрывают предложения, не удаляя их.
- Справочник целиком поставщику не выдаётся.

## Edge cases

- Два сотрудника одновременно выставляют предложение на одну позицию.
- Правка цены двумя сотрудниками одновременно.
- Предложение «под заказ» со сроком 0; самовывоз без адреса точки; ни самовывоза, ни доставки.
- Позиция архивирована администратором после выставления предложения; категория скрыта.
- Поставщик на паузе правит предложения.
- Подтверждение в пятницу вечером после закрытия; перед длинными праздниками; 31 декабря.
- Поиск пустой строкой, одной буквой, артикулом с пробелами и дефисами; частые запросы.
- Сотрудник другой компании пытается изменить чужое предложение.

## Не входит в задачу

- Предложения на услуги и цены по моделям — TASK-019.
- Клиентский каталог, сортировка, скрытие названия поставщика без подписки — TASK-020.
- Заявки и счётчик активных заявок по предложению — EPIC-08.
- Импорт прайса файлом и снятие по импорту — EPIC-16.
- Запрос на добавление позиции, фото от поставщика — этап C и модерация.
- Экраны кабинета — EPIC-11.

- **AC-2.** Поиск позиции для поставщика: только по запросу, активные позиции видимых категорий, постранично, признак «уже в ваших», ограничение частоты; справочник целиком получить нельзя — тесты.
- **AC-3.** Мои предложения: вкладки, отборы, признак видимости с причиной — тесты.
- **AC-4.** Функция даты получения в `packages/domain` с таблицей случаев из требования 4; предпросмотр для поставщика — тесты.
- **AC-5.** Снимок предложения не меняется после правки и снятия предложения — тест.
- **AC-6.** Функция видимости на витрине по требованию 6; пауза и блокировка скрывают без изменения предложений — тесты.
- **AC-7.** Администратор видит предложения поставщика только для чтения.

## Что должно реально работать

В dev, запросами к API от сотрудника поставщика:

- Найти колодки по «04465 0k090» → позиция найдена, «уже в ваших» — нет → выставить предложение 12 500 ₸, в наличии, самовывоз → предпросмотр показывает дату.
- Попытаться выставить второе предложение на ту же позицию → отказ со ссылкой.
- Изменить цену из списка → версия выросла, в журнале автор-сотрудник.
- Снять предложение → оно на вкладке «Снятые» → вернуть → ответ просит проверить цену.
- Администратор ставит поставщика на паузу → признак видимости «нет, пауза поставщика» → снимает паузу → снова «да».
- Пустой запрос поиска → отказ; много запросов подряд → 429.
