# TASK-019 — Предложения на услуги

Модель: Opus 5.5, High

## Цель

Первая из трёх задач по услугам (решение Product Owner 10.10.2026: EPIC-13 продолжается услугами):
1. **TASK-019** — предложения на услуги;
2. **TASK-038** — заявка на услугу;
3. **TASK-039.B** — запись на экранах.

В справочнике услуги уже есть («замена масла», «развал-схождение»), но выставить на них предложение поставщик не может, а пользователь их не видит. После задачи:
- поставщик-сервис выставляет услугу с ценой — одной для всех моделей или по моделям автомобилей;
- пользователь видит «Услуги в {город}» и карточку услуги с ценой для своей модели.

Записываться — позже (TASK-038, TASK-039.B).

  - «только услуги» — без товаров.

## Требования

### 1. Данные и правила

- **Предложение на услугу** — то же `offer` с позицией типа `service`. Своё у него:
  - нет наличия, срока «под заказ», самовывоза и доставки — услуга оказывается в точке;
  - **цена:** «одна для всех моделей» или **цены по моделям** (марка → модель из справочника автомобилей; одна строка на модель, без дублей; модель в архиве — цена остаётся, но клиент с такой моделью её не увидит, решение агента записать);
  - гарантия — как у товара;
  - свой артикул и название — как у товара.
  
  Миграция с откатом, правила в базе.
- **Тип поставщика (строка плана):**
  - «только товары» — не выставляет услуги;
  - «только услуги» — не выставляет товары;
  - «товары и услуги» — всё.
  
  Проверка на сервере для новых предложений и при возврате снятого. Уже выставленные несовместимые предложения не ломаются: они видны в «Моих предложениях» с пометкой и не показываются клиентам. Правило витрины — одно (`offerShowcase`), причина в `reasons`. Решение агента — записать.
- **Витрина:**
  - услуга видна только в городе точки поставщика и только при выбранном городе;
  - только если у предложения есть цена для модели основного (выбранного) автомобиля пользователя или «одна цена для всех»;
  - часы точки (D-060), пауза и блокировка — как у товара, тем же правилом.
- **Цена для автомобиля** — одна функция в домене: модель автомобиля → цена предложения или «нет цены». Ею пользуются витрина, снимок для будущей заявки (TASK-038) и предпросмотр в кабинете.

### 2. Сервер и контракт

- **Кабинет:**
  - поиск позиции для нового предложения находит и услуги — с учётом типа поставщика;
  - выставление услуги — цена одна или по моделям;
  - правка с версией — в том числе таблицы цен по моделям целиком с версией;
  - снятие и возврат;
  - «Мои предложения» — услуги рядом с товарами, отбор «Услуги».
- **Каталог для пользователя:**
  - дерево услуг (`kind: services`) уже отдаётся;
  - список услуг подкатегории в городе — с ценой «от N ₸» для автомобиля пользователя и числом предложений;
  - карточка услуги — предложения с ценой для модели, поставщик по правилам `showcase-visibility.ts`, рейтинг и «проверенный партнёр», без наличия и срока;
  - без города — `empty: city_required`;
  - пусто в городе — понятное `empty`.
- **Администратор** — просмотр предложений-услуг у поставщика и у позиции, как у товаров.
- **Контракт** — аддитивно.

### 3. Кабинет поставщика

- **«Добавить позицию»:** поиск находит услуги (поставщику «только товары» — нет).
- **Форма S-OFF-04:**
  - переключатель «Одна цена для всех моделей» / «Цены по моделям»;
  - выбор марки и модели с поиском (как в админке — `SearchSelect`, или своим компонентом кабинета; решение агента);
  - список «модель — цена» с добавлением и удалением;
  - подсказка «Клиенты с моделями без цены это предложение не увидят»;
  - ошибки сервера у своей строки (дубль модели, цена вне пределов настроек).
- **«Мои предложения»:** услуга в списке и таблице — цена «одна» или «от N ₸ · M моделей»; правка цены в строке — только для «одной цены», таблица моделей — в карточке.
- **Поставщик «только услуги»** не видит в поиске товаров и наоборот.

### 4. Приложение

- **Каталог (M-CAT-01):**
  - блок «Услуги в {город}» — подкатегории услуг плиткой;
  - в режиме «Весь Казахстан» — подсказка «Услуги показываются только по выбранному городу» (T-CITY-01) и выбор города.
- **Список услуг подкатегории:** название, «от N ₸ для {модель}», число предложений; пусто — «В {город} пока нет этой услуги» и «Выбрать другой город».
- **Карточка услуги (M-CAT-08):**
  - название, описание, город;
  - предложения с ценой для модели автомобиля, поставщик по правилам видимости, рейтинг, «проверенный партнёр»;
  - вместо «Записаться» — «Запись на услуги появится позже» (по образцу «Под заказ» до TASK-039).
- **Смена автомобиля в шапке** меняет цены.

## Бизнес-правила

- Все правила на сервере: тип поставщика, витрина, цена для модели. На клиентах расчёта нет.
- Поставщик гостю не называется («Поставщик клуба»), как у товаров.
- Совместимость к услугам не применяется (TASK-015: `COMPATIBILITY_NOT_APPLICABLE`).
- Реальных сообщений не отправлять.

## Edge cases

- Цены по моделям и ещё «одна цена для всех» одновременно — нельзя, одно из двух.
- Одна модель дважды в таблице цен — отказ у строки.
- У пользователя автомобиль без модели — не бывает (гараж требует модель); если всё же нет — цены по моделям не подходят, видна только «одна цена».
- Поставщик сменил город точки — услуги переезжают в новый город (витрина по городу точки).
- Тип поставщика сменили на «только товары» при выставленных услугах — услуги пропадают с витрины с причиной в кабинете.
- Длинное казахское название услуги — без поломки плитки и карточки.

## Не входит

- Запись на услугу (заявка, время, ответы поставщика) — TASK-038.
- Экраны записи — TASK-039.B.
- Поиск по каталогу — EPIC-15.

## Acceptance Criteria

1. Предложение на услугу: данные, миграция с откатом, цена одна или по моделям, правила в базе; доменная функция «цена для автомобиля» с юнит-тестом.
2. Тип поставщика ограничивает выставление и возврат товаров и услуг; несовместимые старые — вне витрины с причиной. Интеграционные тесты.
3. Витрина услуг: только город точки, только при выбранном городе, только с ценой для модели; часы, пауза, блокировка — тем же правилом. Интеграционные тесты, в том числе совпадение правила и SQL-двойника.
4. Кабинет: поиск услуги, форма S-OFF-04 с ценами по моделям, «Мои предложения» с услугами.
5. Приложение: «Услуги в {город}», список, карточка M-CAT-08 с ценой для модели, «Запись на услуги появится позже», «Весь Казахстан» — выбор города.
6. Проход в браузере:
   1. сотрудник выставляет «Замену масла» с ценами для Coolray и Atlas;
   2. в приложении с Coolray в Алматы — цена для Coolray;
   3. смена автомобиля на Atlas — цена для Atlas;
   4. автомобиль другой модели — предложения нет;
   5. «Весь Казахстан» — просьба выбрать город;
   6. поставщик «только товары» не находит услугу в поиске.
7. Контракт аддитивно (`openapi:compat` без трейлера), `openapi:check` PASS.
8. `ARCHITECTURE.md` — раздел решений; `CLAUDE.md` блок 0 — «Предложения на услуги в dev».
9. `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` и интеграционные тесты изменённых модулей — PASS локально. CI проверяет архитектор при приёмке.
10. Отчёт `tasks/TASK-019-REPORT.md` с идентификатором прогона CI.
