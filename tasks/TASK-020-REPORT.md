## Technical Decisions
Все внесены в ARCHITECTURE.md 4.29 (I283–I298). Главное:
- **Необязательная сессия — режим контракта `auth: "optional"`**: без токена — гость; присланный токен проверяется ровно как на защищённом маршруте (негодный — 401, другой контекст — 403), а не молча превращается в гостя (I284).
- **Клубный доступ — одна функция, без кэша**; выдача вручную на учётную запись номера (создаётся при необходимости, как у `admin:grant`), одна открытая выдача, новая заменяет прежнюю (I285, I286).
- **D-060 — в самом правиле витрины TASK-018** (факт `schedule`, SQL-двойник), а не только в каталоге: так и кабинет показывает причину (I287).
- **Совместимость в списке — по области «подкатегория», а не по списку id**: тот же единый расчёт, но ~25 мс против ~930 мс на 3 000 позиций (I290).
- **Атрибутные фильтры — один JSON-параметр `attributes`**: контракт строки запроса допускает только скалярные параметры, а ответ списка должен оставаться GET и кэшироваться гостю (I291).
- **«Рекомендуемые» по умолчанию — вес города 3** при весах цены и даты по 1: предложение выбранного города выше остальных (PRODUCT 6.3), внутри города решают цена, дата и «проверенный партнёр» (I293).
- **Курсор — позиция в порядке сортировки** (ключ с id на конце): без пропусков и повторов при любой сортировке и при изменениях между страницами (I294).
- **Поставщик без доступа — вариант `hidden` без полей**, данные поставщика для такого зрителя не читаются из базы; в списке данных поставщика нет ни у кого (I295).
- **Кэширование**: гостю `public, max-age=60`, сессии `private, no-store`, всем `Vary: Authorization` (I296).
- **Ключевые характеристики** — до двух первых фильтруемых характеристик подкатегории со значением (признака «ключевая» у характеристики нет; I294).
- **Одна дата получения на предложение** для самовывоза и доставки — у предложения один срок (I288).

## Known Issues / Risks
- **`warrantyText` — свободный текст поставщика** (до 100 символов) и отдаётся всем: поставщик может вписать туда своё название или телефон. Сейчас не фильтруется; кандидат для модерации или проверки при сохранении.
- **Список вычисляется целиком в процессе API** (тысячи позиций — ~260 мс); для десятков тысяч позиций в одной подкатегории понадобится выборка страницами в SQL или индекс поиска (EPIC-15).
- **Открытые маршруты каталога без лимита частоты по адресу** (в отличие от проверки совместимости): у мобильных операторов Казахстана много пользователей за одним адресом (CGNAT), общий лимит мог бы отрезать настоящих пользователей. Решение о лимите — вместе с EPIC-15/нагрузочным тестом.
- **`CompatibilityEvaluator.evaluate` по большому списку id медленный** (~930 мс на 3 000 id; TASK-015) — каталог обходит это областью «подкатегория»; другим будущим потребителям (гараж, поиск) стоит учитывать.
- Тесты, зависящие от часов Docker-контейнера (подписанная ссылка MinIO на 1 с в `catalog-photos.integration.test.ts`), изредка падают на машине разработки при расхождении часов; в CI не наблюдалось.
- Экраны админки для клубного доступа нет (TASK-034); выдача — API и серверной командой.
