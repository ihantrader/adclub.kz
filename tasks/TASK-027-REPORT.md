## Technical Decisions

Внесены в `ARCHITECTURE.md` 4.37 (I384–I395). Существенное:

- **I384. React Navigation 7, а не Expo Router.** Expo Router — умолчание Expo, но тянет `react-native-reanimated`, `react-native-gesture-handler`, `@react-native-masked-view`, `@expo/ui` и меняет точку входа на файловую маршрутизацию; нужны из этого сейчас только вкладки. React Navigation — та же библиотека под Expo Router; единственный новый нативный модуль — `react-native-screens ~4.26`, он есть в `bundledNativeModules` Expo SDK 57, то есть в Expo Go. Панель вкладок рисует дизайн-система, навигатор только сообщает текущую вкладку. Стеки внутри вкладок и ссылки из push (TASK-031) — той же библиотекой, без смены каркаса.
- **I385–I386. Порядок старта — чистая функция; ожидание сервера — у оболочки.** Время — не свойство чистой функции: `pending` означает «ответа ещё нет» и даёт `splash`, а через 2,5 с оболочка сама сообщает `unverified`, и порядок идёт дальше.
- **I387. Одно хранилище устройства** (`createDeviceStore` с внедрённым адаптером, как `createThemeModeStore` в `ui-core`): ключи `adclub.mobile.{language,city,first-run,theme}`, отказ хранилища и испорченное значение не ломают приложение, выбор, сделанный до чтения, не перетирается. С TASK-029 язык и город переезжают в учётную запись, здесь остаётся копия устройства.
- **I388. Словари приложения — в `packages/i18n`** (`src/mobile/*.json`), отдельными файлами от общего плоского словаря; казахский помечен `$about` как непроверенный носителем. Тест сверяет ключи трёх языков, тексты SCREENS, длину подписей вкладок и отсутствие капса.
- **I389.** Системный язык определяется строже серверного `pickLanguage` (`null` вместо отката на русский) — иначе экран выбора языка не показался бы никогда.
- **I390. Город — одно значение и одно место правил**; `reconcileCity` подтягивает переименование и убирает архивный город; сопоставление ответа геокодера и поиск — чистые функции под тестами.
- **I391. Сквозные состояния — компоненты дизайн-системы без текстов** (тексты всегда свойствами); сеть — один хук `useOnline` на `expo-network`, неизвестное состояние считается «сеть есть».
- **I395. Проверка в браузере.** Долг T-2 не снят, но тот же код React Native запускается под `react-native-web`; для этого добавлены **dev-зависимости** `react-native-web`, `react-dom`, `@expo/metro-runtime` и конфигурация `mobile-web` в `.claude/launch.json`; в `pnpm build` они не участвуют. Понадобились две поправки: `Appearance.setColorScheme?.(…)` (в `react-native-web` метода нет; на телефоне поведение прежнее) и разрешение origin страницы в API при таком запуске — CORS к приложению на телефоне отношения не имеет.

### Как запустить на телефоне (Product Owner)

1. В корне репозитория: `docker compose -f infra/docker/compose.dev.yml up -d --wait`, затем `pnpm install` и `pnpm --filter api migrate`.
2. Запустить API: `pnpm --filter api dev` (порт 3000). Города в базе: `pnpm --filter api operator dev:suppliers:seed` (если ещё не заполнены).
3. Запустить приложение: `pnpm --filter mobile start`. Телефон с Expo Go — в той же Wi-Fi-сети, сканировать QR. Брандмауэр должен пропускать входящие на порты 8081 и 3000.
4. Для проверки пункта 11 чек-листа: `pnpm --filter api operator settings:set client_min_version_ios 2.0.0 --reason "проба"` (для Android — `client_min_version_android`), вернуть — `settings:reset <ключ> --reason "проба"`; изменение действует не позже чем через 30 с.

## Errors & Fixes

- **Правило `react-hooks/set-state-in-effect`.** Первая версия `useCities` меняла состояние прямо в теле эффекта. Переписана: состояние меняется только в колбэках запроса, «идёт загрузка» и «обновление поверх списка» выводятся из ключа запроса.
- **Побочный эффект в отрисовке.** `CitySheet` вызывал `reconcile(cities)` прямо при отрисовке — перенесено в `useEffect`.
- **`Appearance.setColorScheme` отсутствует в `react-native-web`** — падала вся `ThemeProvider` при запуске в браузере. Вызов сделан необязательным (`?.`); на телефоне поведение прежнее.
- **CORS при запуске в браузере.** Страница на `127.0.0.1:8082` не могла обратиться к API. Это свойство браузера, а не приложения: API запускался с origin страницы в `SUPPLIER_WEB_ORIGINS` (переменная окружения для локального запуска, в репозиторий не попала).

## Deviations

- **Словари приложения — отдельные файлы внутри `packages/i18n`, а не новые ключи общего плоского словаря.** Требование «kk/ru/en через `packages/i18n`» выполнено (набор языков, `Lang`, откат и сами тексты — в этом пакете), но экранные тексты мобильного лежат в `src/mobile/*.json` и экспортируются отдельно: так общий словарь остаётся про то, что нужно всем клиентам и серверу.
- **Кнопки, ведущие в ещё не сделанные задачи, не нарисованы, чтобы не было «мёртвых» нажатий:** «Войти» у пустой вкладки «Заявки» и у карточки гостя в профиле (TASK-029), «Добавить автомобиль» в гараже (TASK-028), «Показать активные заявки» на экране обновления и на экране «Нет сети» (TASK-030 — сохранённой копии пока не существует). Тексты самих состояний — как в SCREENS.
- **Шаг «первый запуск: автомобиль» (M-START-05) — TASK-028.** Порядок старта его знает (`first-run-car`) и хранение помнит шаг, но экрана нет: после выбора города первый запуск считается пройденным. Когда появится экран, поменяется одно значение, а не порядок.
- **Пустые состояния каталога — рабочий текст**, SCREENS его не задаёт («Каталог скоро откроется» / «Здесь появятся клубные цены поставщиков — по вашему городу и вашему автомобилю»); утверждается вместе с экраном каталога (TASK-028).
- **Добавлены dev-зависимости для запуска в браузере** (`react-native-web`, `react-dom`, `@expo/metro-runtime`) — не продуктовая платформа, а способ проверить экраны без телефона; в `pnpm build` и в бандлы iOS/Android не входят.

## Known Issues / Risks

- **Долг T-2 не снят.** На реальном устройстве, эмуляторе и симуляторе приложение не запускалось ни разу. Браузерный запуск проверяет логику и вёрстку, но не нативную заставку, системные запросы разрешений, шрифты системного размера и поведение Expo Go.
- **Новые нативные модули** (`react-native-screens`, `expo-location`, `expo-network`) взяты из набора Expo SDK 57 (`bundledNativeModules`), то есть должны быть в Expo Go. Подтвердится это первым запуском на телефоне.
- **Пакеты предлагают обновление** (`expo` 57.0.23 → 57.0.25, `npx expo install --check` сообщает ещё о двух) — не трогал: это отдельное решение, не входящее в задачу.
- Казахские тексты — черновые, носителем не подтверждены (помечено в файле). Отдельная задача на вычитку — за Product Owner.
- CI на `main` по этим коммитам ещё не прогонялся (см. AC-8).
