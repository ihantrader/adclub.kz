# TASK-027 — Каркас приложения: навигация, язык, город, сквозные состояния

Модель: Opus 5, Medium

## Цель

Приложение впервые становится приложением: запускается, решает, что показать, говорит на языке пользователя, спрашивает город один раз и показывает четыре вкладки в утверждённом дизайне. Дальше на этот каркас садятся гараж (TASK-028), вход (TASK-029) и заявки (TASK-030) — поэтому важнее красоты здесь правильные основания: один порядок решений при старте, одно место для сквозных состояний, один способ ходить в API.

## Контекст

Первая задача EPIC-10. Сервер готов по всему пути этапа B: каталог, заявки, коды и QR, уведомления. Приложение — пустой каркас: `App.tsx`, экран-заглушка, экран «Требуется обновление» и витрина компонентов.

- **SCREENS 3.1:** нижние вкладки — Каталог · Заявки · **AI Pilot** · Гараж · Профиль; **до этапа D вкладки AI Pilot нет — вкладок четыре.**
- **SCREENS 5.1 — порядок решений заставки M-START-01:** (1) сервер ответил, что нужно обновление → M-START-03; (2) язык не выбран: системный kk/ru/en применить молча, иначе → M-START-02; (3) первый запуск не пройден → M-START-04 или шаг, на котором остановились; (4) сохранённая сессия отозвана → каталог гостем и шторка «Вы вышли из аккаунта», сохранённые коды удалены; (5) нет сети, пользователь вошёл, есть сохранённые активные заявки → M-ORD-02 без сети; (6) пришёл push → экран из push; (7) иначе → M-CAT-01. **Заставка не ждёт сервер дольше нескольких секунд**; без ответа приложение продолжает, а ответ 426 открывает экран обновления в момент получения.
- **M-START-02:** заголовок на трёх языках, варианты «Қазақша», «Русский», «English», без флагов; выбор применяется сразу.
- **M-START-03:** текст с сервера на языке интерфейса, запасной текст в приложении; «Откройте App Store» / «Откройте Google Play»; «Показать активные заявки» — **только если пользователь вошёл и есть сохранённая копия** (её заводит TASK-030). При возврате в приложение политика запрашивается заново.
- **M-START-04 и M-CITY-01:** «Где вы находитесь?», «Определить автоматически» (системный запрос геолокации **только после нажатия**) и «Выбрать из списка»; отказ, неопределившийся или неизвестный город → список с выбранным «Весь Казахстан». **Город определяется один раз**, повторно автоматически не определяется; город — одно значение, меняется в шапке каталога и в профиле. В разделе услуг «Весь Казахстан» неактивен.
- **SCREENS 2 (сквозные состояния):** загрузка каркасом содержимого, а не спиннером; обновление поверх старого содержимого; кнопка показывает ход и не нажимается второй раз; четыре случая «пусто» со своими текстами; ошибка без технических кодов, введённые данные не теряются, изменившийся на сервере объект показывается фактическим состоянием; баннер «Нет сети» и экран «Нет сети» с кнопкой «Мои активные заявки»; «нет подписки» — вместо названия поставщика «Поставщик клуба».
- **DESIGN.md 6–8:** тёмная тема по умолчанию для приложения, настройка «Оформление» (Тёмная / Светлая / Как в системе), приподнятая круглая кнопка в центре вкладок (в приложении — AI Pilot, этап D), шкала Onest с моноширинными цифрами, системный размер шрифта, отступы кратны 4, зона нажатия 48, значки Tabler, правила длинных казахских текстов, макеты `design/mockups/mobile.html`.
- **PRODUCT 6.6:** гостю доступны каталог и гараж; **PRODUCT 6.7** — офлайн (копия заявок — TASK-030).
- **Долг T-2:** приложение никогда не запускалось на эмуляторе, симуляторе и в нативной сборке — на машине разработки нет Android SDK и macOS. Проверка идёт через Expo Go на телефоне Product Owner.

## Текущее состояние

- `apps/mobile`: Expo, `App.tsx`, `src/screens/HomeScreen.tsx` (заглушка с кнопкой витрины), `src/screens/UpdateRequiredScreen.tsx`, `src/update-gate/*` (политика клиента и решение «нужно ли обновление» — TASK-003), `src/services/api.ts`, `src/config/*` (адрес API), `src/design-system/*` (компоненты React Native на `ui-core`, TASK-075), `src/dev/*` (витрина).
- `packages/ui-core` — токены обеих тем, режимы темы, контраст, логика компонентов; `packages/i18n` — kk/ru/en и `pickLanguage`; `packages/api-client` — типизированный клиент по `apiRoutes`; `packages/contracts` — схемы.
- Сервер: `/meta/client-policy`, `/cities` (TASK-016, `defaultCityId`), каталог и заявки (TASK-020…023).
- Тесты мобильного (`pnpm test`) покрывают только чистую логику и файлы — без React Native.
- **Нет:** навигации, экранов старта, выбора языка и города, сквозных состояний, профиля, работы с сетью в приложении.

## Требования

### 1. Навигация и оболочка

- Четыре нижние вкладки — Каталог, Заявки, Гараж, Профиль — в утверждённом дизайне (макеты `design/mockups/mobile.html`, токены `ui-core`). Место центральной кнопки AI Pilot предусмотрено дизайном, но вкладки нет (этап D).
- Вкладки открываются и переключаются у гостя; экраны вкладок в этой задаче — **каркасы** с правильными состояниями, а не готовые списки: каталог — TASK-028, заявки — TASK-030, гараж — TASK-028, профиль — эта задача (язык, город, оформление).
- Библиотеку навигации выбирает агент (что принято в Expo сегодня), выбор обосновать в ARCHITECTURE.

### 2. Старт и маршрутизация

- Порядок решений M-START-01 реализуется **один раз, в одном месте, чистой функцией** (её легко проверить тестом без React Native): на входе — политика клиента, выбранный язык, состояние первого запуска, сессия, сеть, наличие сохранённой копии заявок, push; на выходе — какой экран открыть.
- Пункты, чьи данные появятся позже (сессия и сохранённая копия — TASK-029/030, push — TASK-031), **предусмотрены в этой функции** и закрыты значениями «нет»; дописывать их позже — значит передать другое значение, а не менять порядок.
- Заставка не ждёт сервер дольше нескольких секунд; ответ 426 открывает экран обновления в момент получения, в том числе когда приложение уже работает; при возврате приложения из фона политика запрашивается заново.

### 3. Язык интерфейса

- kk/ru/en через `packages/i18n`; при первом запуске системный язык применяется молча, иначе — M-START-02.
- Язык хранится на устройстве и меняется в профиле; перенос языка в учётную запись — TASK-029.
- Все тексты экранов — через словари, не строками в компонентах; тексты — рабочие формулировки SCREENS (русский — как в SCREENS, kk и en — перевод; **казахский помечается как непроверенный носителем**, как в прошлых задачах).
- Длинные казахские подписи не ломают вёрстку (DESIGN 7): проверить на самых длинных строках экранов задачи.

### 4. Город

- M-START-04 и шторка M-CITY-01: список городов с сервера (`/cities`, язык интерфейса), поиск, «Весь Казахстан», текущий отмечен, «Определить автоматически».
- Геолокация запрашивается **только после нажатия**; отказ и неизвестный город — список с выбранным «Весь Казахстан»; определение один раз, повторно автоматически не делается.
- Город хранится на устройстве (в учётную запись — TASK-029), меняется в шапке каталога и в профиле, одно значение на приложение.
- Сервер недоступен — понятная ошибка и возможность повторить; приложение не застревает на экране города.

### 5. Сквозные состояния — один раз на всё приложение

- Загрузка (каркас содержимого), обновление поверх содержимого, кнопка с ходом и защитой от второго нажатия, четыре случая «пусто», ошибка без кодов, «Нет сети» (баннер и экран), «Требуется обновление» — **общие компоненты и правила** в `apps/mobile/src/design-system` на `ui-core`, а не повторённые на каждом экране.
- Экраны-каркасы этой задачи используют их по-настоящему (загрузка городов, ошибка сети, пустое состояние вкладки).
- Тема: тёмная по умолчанию, настройка «Оформление» в профиле (Тёмная / Светлая / Как в системе), выбор сохраняется на устройстве.
- Системный размер шрифта учитывается; зона нажатия не меньше 48.

### 6. Работа с API

- Один способ обращения к серверу: `packages/api-client` с заголовками `X-Client: mobile/<версия> (ios|android)` и `Accept-Language`; версия — из `app.json`.
- Ответ 426 ведёт на экран обновления, 503 и сетевой отказ — на состояние ошибки с «Повторить»; тела ошибок читаются по единому формату контракта.
- Токенов и сессии в этой задаче нет (TASK-029) — клиент готов их принять, но не хранит.

### 7. Проверка на устройстве (долг T-2)

- Агент проверяет то, что может без телефона: сборка (`pnpm build`, `expo export` для iOS и Android), тесты чистой логики, запуск dev-сервера Expo.
- **Проверка на реальном устройстве — за Product Owner.** В отчёте дать короткую инструкцию (команда, что открыть) и **список из 8–12 пунктов**, что проверить глазами, включая два плохих сценария (нет сети при старте; отказ в геолокации) и один казахский экран.
- Если агент найдёт способ запустить эмулятор или симулятор на машине разработки — тем лучше, но выдумывать результат запрещено: не запускалось — так и писать.

### 8. Документация

- ARCHITECTURE.md: выбор навигации и хранения на устройстве, где живёт порядок решений старта, как устроены сквозные состояния, как приложение ходит в API, что хранится на устройстве и что переедет в учётную запись; версия и история.
- CLAUDE.md, блок 0 — как запустить приложение и что в нём сейчас работает.

## Бизнес-правила

- Гость пользуется приложением без регистрации: каталог и гараж ему доступны (PRODUCT 6.6).
- Город спрашивается один раз и больше не навязывается.
- Геолокация — только по явному нажатию.
- Приложение не зависает из-за сервера: без ответа оно продолжает работать, а обновление требует ровно тогда, когда сервер это сказал.

## Edge cases

- Первый запуск без сети; сервер отвечает 426 сразу при старте и позже, во время работы.
- Системный язык — турецкий (не kk/ru/en): показывается выбор языка.
- Отказ в геолокации; геолокация вернула город, которого нет в справочнике; справочник городов не загрузился.
- Пользователь закрыл приложение на середине первого запуска и вернулся.
- Самый длинный казахский заголовок и самый большой системный размер шрифта на маленьком экране.
- Переключение темы на «Как в системе» при смене системной темы на ходу.

## Не входит в задачу

- Каталог и карточка позиции, гараж и выбор автомобиля (TASK-028), вход и профиль пользователя (TASK-029), заявки, QR и офлайн-копия (TASK-030), push (TASK-031), подписка (EPIC-14), AI Pilot (этап D).
- Нативные сборки и публикация в сторах (TASK-074), EAS Build.

- **AC-2.** Порядок решений старта — одна чистая функция, покрытая тестами по всем семи пунктам SCREENS 5.1, включая «нет ответа сервера за несколько секунд» и «426 во время работы».
- **AC-3.** Язык: системный kk/ru/en применяется молча, иначе экран выбора; смена языка в профиле меняет интерфейс; тексты — из словарей, казахский помечен непроверенным — тесты и проверка.
- **AC-4.** Город: первый запуск, геолокация только по нажатию, отказ и неизвестный город ведут к списку с «Весь Казахстан», определение один раз, город меняется в профиле — тесты логики и проверка.
- **AC-5.** Сквозные состояния — общие компоненты; экраны задачи используют загрузку, ошибку с «Повторить», пустое состояние и баннер «Нет сети» по-настоящему.
- **AC-6.** Обращения к серверу — только через `api-client` с `X-Client` и `Accept-Language`; 426 открывает экран обновления в момент получения — тест.
- **AC-7.** Тема: тёмная по умолчанию, настройка «Оформление» работает и сохраняется.
- **AC-8.** `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build` (включая `expo export` для iOS и Android) — зелёные; CI на `main` зелёный с первой попытки, включая коммит с отчётом.
- **AC-9.** В отчёте — инструкция запуска и чек-лист ручной проверки на устройстве (8–12 пунктов, из них два плохих сценария и один казахский экран); честно сказано, что именно агент запускал сам.
- **AC-10.** ARCHITECTURE.md и CLAUDE.md блок 0 обновлены; коммиты по D-024 с составом в отчёте.

## Что должно реально работать

На телефоне через Expo Go:

- Первый запуск: заставка → (выбор языка, если системный не kk/ru/en) → «Где вы находитесь?» → «Выбрать из списка» → город выбран → каталог-каркас с четырьмя вкладками.
- «Определить автоматически» → системный запрос геолокации; отказ → список городов с выбранным «Весь Казахстан».
- Перезапуск приложения: город и язык сохранились, город повторно не спрашивается.
- Выключить сеть и запустить: приложение открывается, показывает «Нет сети» и не зависает.
- Профиль: смена языка на казахский меняет интерфейс; «Оформление» переключает тему и сохраняется после перезапуска.
- Поднять минимальную версию приложения настройкой на сервере (`client_min_version_ios|android`) → приложение показывает экран «Нужно обновить приложение».
