# TASK-032 — Кабинет поставщика: предложения; всплывающие сообщения не закрывают навигацию

Модель: Opus 5.5, High

## Цель

Поставщик должен сам вести свои предложения с телефона: найти позицию справочника, выставить цену и наличие, поправить цену прямо в списке, снять и вернуть предложение. Сейчас это делает только Product Owner запросами к API. Это вторая из трёх задач кабинета (TASK-031 → **TASK-032** → TASK-033).

Попутно — замечание Product Owner после проверки TASK-031 на iPhone: **всплывающее сообщение** («Сохранено» и т. п.) появляется внизу и **перекрывает нижние вкладки**. Так не должно быть ни в кабинете, ни в мобильном приложении.

## Требования

### 1. «Мои предложения» (S-OFF-01)

- Вкладки «В продаже» и «Снятые» со счётчиками; поиск по своим предложениям (название, артикул, свой артикул поставщика); отборы «В наличии / Под заказ» и «Без фото»; подгрузка страниц.
- **Строка:**
  - на телефоне — карточка, на компьютере (от 1024) — таблица;
  - название и артикул, цена, наличие, срок в днях, значки получения;
  - **«Активные заявки: N»**;
  - **«Не видно клиентам»** с понятной причиной, если предложение не на витрине. Например: «Задайте часы работы точки» со ссылкой на «Компанию», «Компания на паузе».
- **Правка в строке:** цена, наличие, срок. Поле сохраняется сразу (с версией), затем «Сохранено» с «Отменить» (возврат прежнего значения той же правкой) и подсказка «Новая цена — для новых заявок».
  - Чужая версия (коллега поменял) — понятный текст и свежие значения, введённое не теряется молча.
  - Цена и срок вне пределов настроек — ошибка у поля.
- **Снять:** если есть активные заявки — предупреждение «По этому предложению N активных заявок — их нужно выполнить», снятие всё равно разрешено.
- **«Снятые»:** «Вернуть в продажу» с просьбой проверить цену (`checkPrice`). Позиция ушла из справочника — понятный отказ.
- **Пусто:** «Предложений пока нет» и «Добавить позицию». «Загрузить прайс» — не показывать до этапа C.
- **Число активных заявок по предложению** сервер сейчас, вероятно, не отдаёт. Добавить аддитивно:
  - в список и карточку предложения;
  - поставщику — только по своим заявкам;
  - «активные» — по тому же правилу, что вкладки заявок поставщика (TASK-021).

  `openapi:compat` — без трейлера.

### 2. Поиск позиции (S-OFF-02)

- Только по запросу (полного справочника поставщик не видит). Подсказка, что искать: артикул в любом написании или название. Меньше трёх символов — подсказка, а не запрос.
- Результат: название, категория, бренд, артикул. Уже выставленная — «Уже в ваших предложениях» со ссылкой на него.
- Не найдено — «Позиции нет в справочнике. Напишите администратору клуба». Запрос на добавление S-OFF-05 — этап C.
- Лимит частоты (429) — «Слишком много поисков, подождите N с».

### 3. Новое предложение (S-OFF-03)

- Позиция — только чтение (название, бренд, артикул, категория).
- **Поля:**
  - цена;
  - наличие («В наличии» / «Под заказ»; у «Под заказ» — срок в днях больше 0);
  - получение — самовывоз и/или доставка;
  - гарантия по желанию — месяцы или текст;
  - свой артикул и своё название по желанию.
- **Начальное значение «доставки»** — из настройки компании «Доставка по умолчанию для новых предложений» (требование 4).
- **Предпросмотр** «Клиент увидит: Самовывоз — завтра, 14 марта» — по `offer-receipt-preview`, обновляется при смене срока. Точка без часов — «Задайте часы работы, иначе клиенты не увидят предложение» (D-060).
- **Отказы сервера — понятным текстом у нужного поля:**
  - самовывоз без адреса точки — ссылка на «Компанию»;
  - контакты в тексте гарантии — «Уберите телефон, ссылку или e-mail из гарантии»;
  - предложение на эту позицию уже есть — ссылка на него.
- После сохранения — карточка предложения, «Сохранено».

### 4. «Доставка по умолчанию» в компании (S-COMP-01)

- **Сервер:** у компании появляется флаг «доставка по умолчанию для новых предложений» (миграция, аддитивно в контракте `GET`/`PATCH /supplier/company` и в админском просмотре, журнал действий — как у других полей компании, с версией).
- **Кабинет:** переключатель на экране «Компания».
- Флаг влияет только на начальное значение формы нового предложения. Существующие предложения не меняет.

### 5. Карточка предложения

Все поля предложения с правкой (та же форма, что у нового, позиция — только чтение), состояние витрины с причиной, «Активные заявки: N», «Снять» / «Вернуть в продажу». Адрес страницы переживает перезагрузку.

### 6. Всплывающие сообщения не закрывают навигацию (кабинет и мобильное)

- **Правило DESIGN 7.7 (уже записано):** сообщение появляется **над** нижними вкладками и над закреплённой нижней кнопкой экрана, с отступом 8, и никогда не закрывает навигацию и главное действие. Без нижних вкладок — над системной безопасной зоной. На компьютере — внизу по центру области содержимого.
- Исправить в кабинете (`packages/ui` и/или оболочка кабинета) и проверить то же в мобильном приложении (`apps/mobile/src/design-system`). Если там та же проблема — исправить.
- Сообщение, у которого есть действие («Отменить»), остаётся достаточно долго, чтобы нажать: пока на него смотрят — не исчезает. Время — на усмотрение агента, решение — в отчёте.

## Бизнес-правила

- Правила витрины, даты получения и проверки предложения — только на сервере (`offerShowcase`, `receiptDate`, проверки TASK-018/020.A). Кабинет показывает их результат и ничего не считает сам.
- Сотрудник видит и правит только предложения своей текущей компании (сервер уже проверяет). Смена компании не оставляет на экране чужих предложений.
- Все сотрудники компании равны.
- «Новая цена — для новых заявок»: активные заявки сохраняют цену своего снимка (уже так на сервере).

## Edge cases

- Два сотрудника одновременно правят цену одного предложения — второй видит понятный конфликт и свежую цену.
- Снятие предложения, по которому есть активные заявки, — предупреждение, затем снятие. Заявки продолжают жить.
- Компания на паузе — предложения видны и правятся, у каждого «Не видно клиентам: компания на паузе».
- Точка без часов — у всех предложений одна понятная причина и ссылка на «Компанию».
- Поиск «04465 0k090», «044650K090», «04465-0K090» находит одну позицию.
- Длинное казахское название позиции в карточке на 360 px — переносится, ничего не налезает.
- Нет сети — список из последнего ответа не показывается как свежий: баннер «Нет сети», правка неактивна (правило TASK-031).
- «Отменить» во всплывающем сообщении после того, как коллега уже поменял то же поле, — конфликт, а не тихая перезапись.

## Не входит

- Заявки и сканер (TASK-033).
- Прайс, модерация фото, данные о совместимости, запрос на добавление позиции, услуги, просмотры (этапы C–D).
- Изменения правил витрины и даты получения.

## Что должно реально работать

Product Owner в кабинете на iPhone (сотрудник «Автомаркета») находит моторное масло по названию, выставляет его «В наличии» с самовывозом и видит «Клиент увидит: Самовывоз — завтра». Затем меняет цену колодок прямо в списке, получает «Сохранено · Отменить» над вкладками, а не поверх них. Открывает мобильное приложение — у колодок новая цена, а новое масло есть в каталоге.

Снимает масло — оно пропадает из каталога. Возвращает — кабинет просит проверить цену.
