## Result
- **Ручной ввод кода ищет сам.** Как только в ячейках шесть цифр — набраны своей клавиатурой, с физической клавиатуры или вставкой «482 915» / «482-915» / «482 915 7» — уходит поиск. Кнопки «Найти» нет. Один набранный код — один запрос: двойное касание последней цифры, Enter, повторное событие ввода ничего не дублируют; «Стереть» и новая цифра (даже та же) или другой код поверх — новый поиск. Пока идёт поиск, экран ввода остаётся на месте, ячейки и клавиши неактивны, «Ищем заявку» с индикатором — только после 300 мс (D-069). «Код не найден» → «Ввести ещё раз» — ячейки пустые. «Нет сети» → код крупно → «Повторить» ищет тот же код без перенабора. После 429 набирать можно, запрос не уходит до `Retry-After`, под ячейками — «Поиск по коду снова будет доступен через N мин»; когда срок вышел, код из ячеек ищется один раз сам. «Выдать» по-прежнему отдельное нажатие.
- **Блокировку компании проверяет сервер.** Заблокированная компания не может принять заявку, отметить «Готово к выдаче» и отказать — ни из кабинета (403 `SUPPLIER_BLOCKED`), ни кнопками W-01 в WhatsApp (нажатие сохраняется с исходом `supplier_blocked`, заявка не меняется, никому ничего не отправляется). Просмотр заявок, поиск по коду и выдача (в том числе поздняя) работают. Пауза действия по заявкам не запрещает. Снятие блокировки возвращает действия без повторного входа.
- **Кабинет показывает отказ текстом:** «Кабинет заблокирован администратором клуба: принять, отметить готовность или отказать нельзя. Выдача по коду доступна» — перечитывает заявку и компанию, кнопки исчезают.
- **Время в тексте конфликта** — грамматически: «Заявку уже принял Ерлан вчера в 14:02», «… 12 сентября в 14:02»; en — «yesterday at 14:02», «on September 12 at 14:02»; kk — «кеше 14:02 кезінде». Так же — моменты в исходах сканера («Заявка уже выдана вчера в 14:02»).

## Technical Decisions
Внесено в `ARCHITECTURE.md` 4.51:
- **I538–I539.** Правило — доменная функция рядом с `orderTransition`, спрашивает его только `OrderTransitions.move` (единственный путь к статусу заявки) — поэтому кабинет и WhatsApp получают одно решение. Отказ не пишется в журнал заявки: это не поздний ответ, а запрещённое действие.
- **I540.** 403 `SUPPLIER_BLOCKED`, а не 409: заявка ни при чём, запрещено действие компании.
- **I541.** Нажатие кнопки заблокированной компанией — исход `supplier_blocked` без ответа сотруднику: шаблона нет, тексты W-* меняются только с одобрения Meta.
- **I542–I543.** Автопоиск — чистый «шлюз» `createCodeEntryGate`; поиск идёт под теми же ячейками (без смены экрана и растворения), 429 — ожидание с причиной и одним поиском после срока.
- **I544.** `formatAt` — момент внутри фразы со своим предлогом; `formatWhen` (отдельная подпись) не менялся.

## UAT / E2E
Встроенный браузер, кабинет (`supplier-web` dev) + API + worker из `.claude/launch.json`, dev-база с миграцией; данные — dev-скрипт: администратор с TOTP через настоящий вход, клиент с клубным доступом, четыре заявки у «Автомаркета» (три приняты). Панель браузера была скрыта, поэтому действия — через DOM (клики по клавишам, события ввода и клавиатуры), счёт запросов — по `performance` и журналу сети.
- Ручной ввод: «44443», затем «2» дважды подряд в одном такте → ровно один `POST /supplier/orders/lookup`, «Заявка найдена № 1024», «Выдать» — отдельной кнопкой. Сначала при этом нашлась ошибка (см. Errors & Fixes).
- Ввод «000 000 7» как вставка → один поиск → «Код не найден» → «Ввести ещё раз» → ячейки пустые.
- Набор с клавиатуры «2» → «247831» и два Enter → один запрос, № 1025 найдена; «Выдать» → «Выдано · Әлия Тест».
- «Нет сети» (событие `offline`): «975157» → ни одного запроса, «Нет связи … 975 157 · Повторить»; сеть вернулась → «Повторить» → один запрос, № 1026 найдена.
- 429 (`order_lookup_failures_per_member` = 2): второй неверный код → «Слишком много попыток … через 59 мин»; «Сканировать следующую» → под ячейками «Поиск по коду снова будет доступен через 58 мин»; «888888», «Стереть», «9» — ноль запросов. Ожидание 8 с (память страницы) → после срока код из ячеек ушёл один раз сам («Заявка ещё не принята» для № 1027).
- Блокировка: открыта карточка новой № 1027, «Автомаркет» заблокирован через `POST /admin/suppliers/<id>/block` в сессии админки → «Принять» → текст «Кабинет заблокирован администратором клуба: …», кнопок «Принять»/«Отказать» больше нет. Сканер при блокировке: «975157» → найдена → «Выдать» → «Выдано». Блокировка снята → компания перечитана (`refreshCompany`, как это делает таймер) → «Принять» снова есть → «Принять» → «Принята», телефон открылся, без повторного входа.
- Вёрстка ручного ввода на 375: горизонтальной прокрутки нет, строка состояния держит высоту 24, клавиатура не сдвигается.
- **Не проверено в браузере:** нажатие кнопки WhatsApp заблокированной компанией (проверено интеграционным тестом с настоящим вебхуком), живой iPhone (проверка Product Owner ниже).

## Errors & Fixes
- **Два касания быстрее отрисовки теряли цифры.** При проверке в браузере пять нажатий подряд оставили в ячейках «3» вместо «44443»: клавиатура строила код от `code` последней отрисовки. Теперь клавиши строят его от текущих ячеек (`codeRef`); повторная проверка — «44443», затем одна заявка на двойное касание. В TASK-033 то же было возможно при очень быстром наборе на телефоне.
- **Растворение одинаковых экранов.** Переход ручного ввода в «поиск» менял ключ `FadeSwap` — экран растворялся сам в себя; ключ для поиска из ручного ввода оставлен «manual».
- **dev: устаревший предбандл Vite.** Кабинет показывал ключ `scan.searchWaits` вместо текста: `@adclub/i18n` отдавался из `apps/supplier-web/node_modules/.vite/deps`, собранного в прошлой сессии. Удалён кэш, кабинет перезапущен — текст на месте. Код не менялся.
- **Оболочка.** Одна попытка heredoc была заблокирована хуком до выполнения; файлы не пострадали. Все правки — Edit/Write или скрипты `.mjs` в scratchpad.

## Deviations
- Нажатие кнопки WhatsApp заблокированной компанией ничего не отвечает сотруднику: шаблона с таким смыслом нет (задача запрещает новый), а W-03 «уже обработана» был бы неправдой. Причину сотрудник видит в кабинете.
- После снятия блокировки кнопки возвращаются при следующем чтении компании кабинетом — при возврате страницы на экран или раз в 5 минут (как было до задачи), не мгновенно. Повторный вход не нужен.
- Если код набран, пока действует 429, он ищется сам, когда срок истёк (одним запросом). Задача говорит «поиск не уходит до `Retry-After`»; что делать после — не задано, выбран вариант без лишнего действия.

## Known Issues / Risks
- Миграция `1790750000000_button-press-supplier-blocked` меняет только CHECK; откат превращает исходы `supplier_blocked` в `conflict`.
- `Retry-After` после 429 живёт в памяти страницы (как в TASK-033): перезагрузка страницы забывает его — следующий поиск снова получит 429 от сервера.
