# TASK-033.A — Поиск по коду без «Найти»; блокировка компании на сервере

Модель: Opus 5.5, Medium

## Цель

Две доводки по итогам TASK-033:

1. **Замечание Product Owner после проверки на iPhone:** при ручном вводе кода после шестой цифры приходится ещё нажимать «Найти». Лишнее действие: **поиск должен начинаться сам, как только введена последняя цифра**.
2. **Замечание приёмки:** при блокировке компании кабинет прячет «Принять», «Готово к выдаче», «Отказать», но **сервер эти действия разрешает**. По SCREENS 6.0 при блокировке доступны только просмотр заявок и закрытие по коду. Критичное правило должно проверять сервер (CLAUDE.md §7), а не только интерфейс. Это нужно до приглашения реальных поставщиков.

## Требования

### 1. Автоматический поиск при ручном вводе

- Как только в ячейках шесть цифр — набраны своей клавиатурой, с физической клавиатуры или вставкой «482 915» / «482-915» — **поиск начинается сам**. Кнопки «Найти» больше нет.
- **Ровно один запрос на один набранный код.** Повтор того же кода без изменений не ищет снова. «Стереть» и новая цифра — новый поиск.
- Пока идёт поиск — ячейки неактивны, загрузка по правилу D-069 (индикатор только после 300 мс).
- **Неудачный поиск** («Код не найден»): по «Ввести ещё раз» ячейки очищаются и готовы к новому вводу.
- **Нет сети:** T-SCAN-01 и код крупно. По «Повторить» тот же код ищется снова, без перенабора.
- **После 429** набор возможен, но поиск не уходит до `Retry-After`. Человек видит, почему.
- Enter на компьютере при шести цифрах ничего не дублирует (запрос уже ушёл).
- «Выдать» на S-SCAN-03 остаётся отдельной кнопкой — ни скан, ни ввод не выдают заявку сами.

### 2. Блокировка компании — правило на сервере

- **Заблокированная компания не может принимать заявки, отмечать «Готово к выдаче» и отказывать** — ни из кабинета, ни кнопками WhatsApp. Сервер отвечает понятной ошибкой (новый код или существующий — на усмотрение агента, аддитивно в контракте). Кабинет показывает её текстом, а не падает.
- **Разрешено и при блокировке:** просмотр заявок и карточек, поиск по коду и выдача (`lookup`, `close`), включая позднее закрытие.
- **Нажатие кнопки WhatsApp заблокированной компанией** не применяется, остаётся след в `message_button_press` с понятным исходом. Нового шаблона сообщения нет (тексты W-* меняются только с одобрением Meta).
- **Пауза** (администратором или из-за подписки) действия по заявкам **не** запрещает — как сейчас.
- **Одно место решения.** «Может ли поставщик в этом состоянии выполнить это действие по заявке» — одна функция (доменная или рядом с `orderTransition`), ею пользуются оба канала. Тест на таблицу «состояние поставщика × действие × канал».
- Что сейчас делает сервер с **предложениями, сотрудниками и компанией** при блокировке — проверить и описать в отчёте. Менять не нужно. Если найдёте явную дыру, — в отчёт как предложение.

### 3. Мелочь

Текст конфликта по заявке, изменённой не сегодня: вместо «в вчера, 14:02» — грамматически верно на трёх языках («вчера в 14:02», «12 октября в 14:02»).

## Edge cases

- Вставка восьми символов «482 915 7» — берутся первые шесть цифр, поиск один.
- Быстрый набор шестой цифры дважды (двойное касание) — один запрос.
- Компанию заблокировали, пока у сотрудника открыта карточка новой заявки: «Принять» → понятный отказ сервера, карточка обновляется, кнопки исчезают.
- Блокировка снята — действия снова доступны без перезахода.
- Заблокированная компания выдаёт по коду готовую заявку — выдача проходит.

## Не входит

- Изменение поведения скана QR (уже автоматический).
- Автовыдача без «Выдать».
- Запрет правки предложений и сотрудников при блокировке (только отчёт о текущем поведении).

## Acceptance Criteria

1. Ручной ввод: шестая цифра (своя клавиатура, физическая, вставка) запускает ровно один поиск; кнопки «Найти» нет; «Стереть» и новая цифра — новый поиск; повтор после «Нет сети»; после 429 запросов нет. Тест логики и проход в браузере.
2. Сервер: таблица «состояние × действие × канал» покрыта тестом. Интеграционный тест: заблокированная компания получает отказ на `accept`, `ready`, `decline` из кабинета и при нажатии кнопки WhatsApp; `lookup` и `close` проходят; пауза не мешает; после снятия блокировки действия работают.
3. Кабинет показывает отказ сервера текстом.
4. «вчера в 14:02» и дата — на трёх языках, тест.
5. Контракт — аддитивно, `openapi:compat` без трейлера; `openapi:check` PASS.
6. `ARCHITECTURE.md` — короткий раздел; отчёт о поведении предложений, сотрудников и компании при блокировке.
7. `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — PASS; CI на main — success (включая интеграционные).
8. Отчёт `tasks/TASK-033.A-REPORT.md` со списком проверок для Product Owner на iPhone.

## Что должно реально работать

Product Owner в кабинете на iPhone открывает «Ввести код вручную», набирает шесть цифр — заявка находится сама, без лишних нажатий. «Выдать» — и готово.

Администратор (серверной командой или API) блокирует «Автомаркет» — «Принять» новой заявки в кабинете получает понятный отказ, а выдача готовой заявки по коду проходит.
