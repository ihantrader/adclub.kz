## UAT / E2E
Встроенный браузер, локально: API + worker + `admin-web` dev, dev-база с заполнением, тестовый администратор `+77019990034` (`admin:grant`).
1. Первый вход: номер → код (с `/dev/login-codes`) → экран настройки: QR (SVG на странице, 200 px), ключ `JA3T POKW …` группами, «По времени, 6 цифр, 30 секунд». Неверный код `000000` → «Неверный код. Проверьте время на телефоне…». Верный код (RFC 6238 из ключа) → 10 резервных кодов, «Войти в админку» неактивна до «Я сохранил коды» → вход, страница — та, что была запрошена (`/settings`).
2. В момент экрана кодов и после: `localStorage`, `sessionStorage`, `history.state`, `document.cookie`, адрес — пусто / без секрета, кодов и токенов; лог API — поиск ключа, резервного кода и TOTP-кода — «No logs matching»; консоль — только сетевые строки браузера, без значений.
3. «Пороги и лимиты» → «срок ответа поставщика»: 49 → «Допустимо от 1 до 48 ч», пустая причина → «Укажите причину…»; 3 ч с причиной; в это время оператор поставил 4 ч → «Эти данные только что изменил оператор сервера. Обновите страницу», значение 3 и причина остались; «Обновить» → «было 4 ч → стало 3 ч» → «Сохранено». «Журнал»: запись «Изменена настройка … Значение: 4 → 3 … причина».
4. Главная: счётчики (сбоя нет, сигналы, бюджет ИИ «$0.00 из $100.00», заявки на подключение 1, без фото 9, неполные 2, без совместимости 1, без перевода 0).
5. Сигнал «Поставщик недостижим»: отказ `no_whatsapp` через `dev:messages:webhook --status failed` → `jobs:run orders.watch-supplier-reach` → сигнал «Автомаркет · без WhatsApp 1 из 1 получателя» → «Взять в работу» → «В работе, +7***0034» → «Закрыть…» с комментарием → «Закрыт», комментарий виден. Найдено и исправлено: детектор открывал закрытый сигнал снова через минуту по тем же отказам (I551); после исправления — остаётся закрытым.
6. «Безопасность»: «Новые резервные коды» по коду приложения → новый набор один раз, «Готово» убирает его со страницы. Список администраторов с последним входом.
7. Выход → вторая вкладка тоже на входе. Вход резервным кодом из отменённого набора → «Этот резервный код не подходит или уже использован»; действующим — вход на ту же страницу. Вход кодом приложения после 5 попыток → «Слишком много попыток. Попробуйте через 4 мин» (предел сервера); после подъёма предела — вход.
8. Две вкладки, access-токен 20 с: после истечения обе обновили данные и остались внутри; вторая вкладка взяла токен у первой (у неё один обмен — при открытии).
9. Перезагрузка `/signals?status=closed` — вход сохранён, отбор «Закрытые» выбран.
10. «Нет сети» (событие `offline`): баннер, «Выйти» неактивна; `online` — баннер ушёл. «Нужно обновить»: подменённый ответ 426 `CLIENT_UPDATE_REQUIRED` → экран с текстом сервера.
11. Ширина 900 → «Админка рассчитана на компьютер», без горизонтальной прокрутки; 1024 и 1920 на всех страницах — без прокрутки страницы и таблиц; тёмная тема (фон `rgb(15,16,18)`), светлая.
12. «Политика клиента»: минимум админки 0.2.0 → «Нельзя установить минимальную версию админки выше текущей версии (0.1.0)»; текст обновления — три поля, длинный текст не ломает диалог. «Города»: стрелки меняют порядок и возвращают его.
13. Кабинет поставщика после переноса сессии: вход сотрудником «Автомаркета», выбор компании, перезагрузка — внутри.

Не проверено здесь: живое приложение-аутентификатор на телефоне, сканирование QR камерой, «Скопировать»/«Скачать как .txt» в настоящем браузере (в панели — только содержимое файла юнит-тестом), сессия на полные 12 часов.

## Errors & Fixes
- Детектор открывал закрытый администратором сигнал снова через минуту по тем же отказам → закрытый сигнал помнит последний отказ, новый открывается только по более позднему (I551; тест дополнен).
- Счётчики главной сначала читали чужие таблицы SQL-запросом → перенесены в модули-владельцы (правило границ модулей, ARCHITECTURE 4).
- Первый вариант формы: кнопка «Получить код» с `type="submit"` и `onClick` отправила бы два запроса → кнопка без `submit`, Enter — через `onSubmit`.
- `setState` в эффекте (`react-hooks/set-state-in-effect`) для данных шапки → данные сессии хранятся с её `sessionId`.
- Первый коммит случайно захватил уже проиндексированные `git mv` → коммит пересобран (`git reset --soft`, переиндексация), в истории — три чистых шага.
- Прогон пяти тяжёлых интеграционных файлов параллельно завис (~50 мин) → остановлен, файлы прогнаны по одному.

## Deviations
- **Сброс второго фактора с причиной — новый маршрут** `POST /admin/administrators/{adminId}/second-factor-reset {reason}`; прежний `…/totp-reset` без причины оставлен ради совместимости контракта (обязательное тело у существующего маршрута — несовместимое изменение) и сервером по-прежнему принимается. ## Known Issues / Risks
- Cookie сессии сервер ставит уже ответом на подтверждение TOTP: закрытая на экране резервных кодов вкладка при следующем открытии войдёт без показа кодов; новые коды — в «Безопасности» (I547).
- Номер скрывается сервером в виде `+7***1234`, а не `+7 777 *** ** 12` из SCREENS 7.0 (функция `maskPhone` используется во всём API с TASK-005).
- Имена администраторов берутся из имени учётной записи; у администратора без регистрации в приложении имя пустое — показывается скрытый номер.
- Бандл админки ~1,2 МБ (как у кабинета — контракты и zod целиком); разделение кода — вне задачи.
- В меню разделы следующих задач стоят тем же списком, что живые (без разделителя).
