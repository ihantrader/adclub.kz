# TASK-034 — Админка: каркас, вход с TOTP, главная, сигналы, настройки, журнал

Модель: Opus 5.5, High

## Цель

Сейчас всё администрирование клуба делается командами оператора в терминале и запросами к API. Это делает Product Owner через архитектора. Чтобы позвать людей на внутреннюю альфу, у администратора должна быть своя веб-панель.

Это первая из трёх задач админки (TASK-034 → TASK-035 справочники → TASK-036 поставщики, заявки, пользователи). Она даёт:
- каркас;
- безопасный вход с вторым фактором;
- главную «очередь внимания»;
- сигналы;
- настройки;
- журнал действий.

## Требования

### 1. Каркас

- Только компьютер (от 1024 px; на узком экране — понятное «Админка рассчитана на компьютер», без поломки). Интерфейс на русском. Светлая тема по умолчанию, переключатель темы.
- Боковое меню разделов. В этой задаче живые разделы: «Главная», «Сигналы», «Настройки» (пороги, политика клиента, города), «Журнал», «Безопасность».
- Разделы следующих задач — «Справочник», «Автомобили» (TASK-035), «Поставщики», «Заявки», «Пользователи» (TASK-036) — честные экраны «появится», как в кабинете. Модерация, отзывы, биллинг — этапы C–D, в меню не показывать.
- Адреса страниц переживают перезагрузку, «назад» браузера работает.
- В шапке — имя или номер администратора и «Выйти». Глобальный поиск A-SEARCH — в TASK-036, когда будет что искать.
- «Нужно обновить» по `CLIENT_UPDATE_REQUIRED`, «Нет сети» — как в кабинете.

### 2. Вход (A-AUTH)

- Номер → код → второй фактор:
  - **первый вход** — настройка TOTP: QR строится на странице из `otpauthUri` (никаких внешних сервисов QR), рядом секрет текстом для ручного ввода, затем проверочный код. После подтверждения — **10 резервных кодов один раз**: «Сохраните коды в надёжном месте, больше они не покажутся», «Скопировать», «Скачать как .txt», «Я сохранил коды». Без этого шага кабинет не открывается;
  - **следующие входы** — код из приложения-аутентификатора или резервный код («Войти резервным кодом»).
- Все запросы входа — с cookie (`credentials: "include"`), шаг входа живёт в cookie сервера. Ошибки по SCREENS и серверу: неверный код, исчерпанные попытки, истёкший шаг («Начните вход заново»), номер без прав администратора — понятный текст без раскрытия, существует ли номер.
- **Сессия 12 часов** (настройка сервера). Обмен токена — по cookie, одна вкладка не выбивает другую. Выход только по слову сервера или по «Выйти».
- Refresh-токен в JS недоступен, access-токен — только в памяти страницы. Секрет TOTP и резервные коды не попадают в хранилище браузера, адрес, историю и журналы.

### 3. Главная — очередь внимания (A-HOME) и сигналы (A-SIG)

- **A-HOME** — карточки со счётчиками в порядке важности SCREENS. В этой задаче — то, что сервер уже знает:
  1. **Сбой канала уведомлений** (`whatsapp_outage`) — выделена, со ссылкой на сигнал. «Продлить сроки» — ссылка на заявки появится в TASK-036, до этого — на список заявок-кандидатов текстом.
  2. **Сигналы:** двойная заявка при позднем закрытии, частые закрытия администратором, **поставщик недостижим** (новый), исчерпан бюджет ИИ (если сервер это знает — иначе в отчёт).
  3. **Новые заявки на подключение** поставщиков (воронка уже есть на сервере).
  4. **Качество справочника:** без фото, с неполными характеристиками, без совместимости в категориях с обязательной совместимостью, без перевода.

  Отзывы, модерация, жалобы, платежи — этапы C–D, не показывать. Нажатие на карточку — на соответствующий список. Если список появится только в TASK-035/036, — честное «появится», но счётчик правдивый.
- **Счётчики сервер отдаёт одним запросом** (новый маршрут, аддитивно). Клиент не собирает их из десяти запросов.
- **A-SIG:** список сигналов с отборами по типу и статусу; строка — тип, объект, время, статус «новый / в работе / закрыт». Действия:
  - «Открыть объект» — ссылкой, если раздел уже есть;
  - «Взять в работу»;
  - «Закрыть с комментарием».
  
  Статусы и действия **добавить на сервер** (аддитивно, с версией, журналом и обязательным комментарием при закрытии). Сигнал, который закрывается сам (сбой канала после первой доставки), закрывается как сейчас.
- **Сигнал «поставщик недостижим» (D-061)** — новый детектор на сервере по образцу `order-notice-channel.ts`: у компании есть получатели уведомлений, и последнее уведомление каждого получателя отказано как `no_whatsapp` (или правило точнее — на усмотрение агента, в ARCHITECTURE). Один открытый сигнал на компанию. Закрывается сам, когда до кого-то из её получателей дошло сообщение. Тест.

### 4. Настройки

- **A-SET-01 «Пороги и лимиты»** — все настройки, которые администратор может менять (`editableBy`), по группам реестра.
  - Для значения: название, описание, диапазон, единица, текущее значение, «по умолчанию», кто и когда менял.
  - **Правка:** поле по типу (число, длительность, время, флаг, JSON-текст для kk/ru/en), проверка диапазона до отправки, диалог «было → стало» с **обязательной причиной**.
  - **«Вернуть по умолчанию»** — тоже с причиной.
  - **Чужая версия** — «Эти данные только что изменил {администратор}. Обновите страницу».
  - **Настройки безопасности входа** видны только для чтения, с пометкой «меняет только оператор сервера».
- **История настройки** — постранично. Сервер сейчас отдаёт до 200 последних, без страниц. **Добавить курсор** аддитивно.
- **A-SET-02 «Политика клиента»:**
  - минимальные версии по платформам (iOS, Android, кабинет, админка);
  - текст обновления kk/ru/en;
  - «Нельзя установить минимальную версию админки выше текущей версии» — это проверяет сервер, показать его ответ.
- **A-SET-06 «Города»:** названия kk/ru/en, активен, порядок перетаскиванием или стрелками, архив. Сервер готов.

### 5. Журнал (A-AUD)

- Отборы: актор (администратор, сотрудник, пользователь, оператор), тип объекта, действие, период. Постраничная подгрузка курсором.
- **Строка:** время, кто (имя или номер; номера пользователей частично скрыты, как в SCREENS 7.0), действие понятными словами (словарь действий на русском, неизвестное — как есть), ссылка на объект (если раздел есть), «было → стало» компактно с раскрытием, причина.
- Код заявки и секреты в журнале не появляются (сервер их туда не пишет — проверить отображение).

### 6. Безопасность

- **«Мой второй фактор»:** «Новые резервные коды» (нужен текущий TOTP) — показать один раз, как при первом входе.
- **«Администраторы»:** список (номер частично скрыт, когда последний вход, настроен ли TOTP) и **«Сбросить второй фактор»** другому администратору — с причиной и подтверждением «что произойдёт». Назначает и снимает администраторов по-прежнему только оператор сервера: кнопок «добавить» и «снять» нет.

## Бизнес-правила

- Все права проверяет сервер. Админка показывает ответы сервера и ничего не решает сама.
- Причина обязательна там, где SCREENS 7.0 её требует. Пустая или из пробелов не принимается ни клиентом, ни сервером.
- Полные номера пользователей по умолчанию не показываются. Раскрытие с записью в аудит — в TASK-036. Здесь достаточно частичного скрытия.
- Секрет TOTP, резервные коды, токены, коды входа нигде не сохраняются и не логируются: не в адресе, не в истории, не в `localStorage`, не в консоли, не в журнале ошибок.
- Все администраторы равноправны.

## Edge cases

- Первый вход, страница закрыта до подтверждения TOTP — следующий вход снова начинается с настройки (сервер: `TOTP_SETUP_REQUIRED`).
- Резервный код использован — второй раз не принимается. Коды кончились — подсказка «Новые резервные коды» после входа по TOTP.
- Часы телефона администратора убежали — неверный TOTP. Понятный текст «Проверьте время на телефоне».
- Два администратора правят одну настройку — второй видит конфликт, введённое не теряется.
- Сессия кончилась за 12 часов, пока открыт диалог правки — после повторного входа администратор возвращается на ту же страницу. Введённую причину можно потерять, но не применённое изменение.
- Сигнал закрыт коллегой, пока открыт у второго, — «уже закрыт {кем}».
- Длинный JSON-текст обновления на трёх языках — поля не ломают раскладку.
- Ширина 1024 и 1920 — всё помещается, таблицы не вылезают.

## Не входит

- Справочники и автомобили (TASK-035), поставщики, заявки, пользователи, глобальный поиск, раскрытие номеров с аудитом (TASK-036).
- Шаблоны уведомлений A-SET-03, синонимы, регламенты, доступ для сторов (этапы C–D или позже).
- Назначение и снятие администраторов из интерфейса.

## Acceptance Criteria

1. Вход: первичная настройка TOTP с QR на странице и резервными кодами один раз; повторный вход по TOTP и по резервному коду; ошибки по серверу. Проход в браузере с настоящим TOTP (код считается тем же алгоритмом в тесте или скриптом проверки).
2. Сессия 12 часов, обмен по cookie, две вкладки не выбивают друг друга, выход только по слову сервера. Общая с кабинетом логика сессии переиспользована, а не скопирована (доказательство — где лежит код).
3. Каркас: меню, адреса, «появится» для TASK-035/036, узкий экран, «Нужно обновить», «Нет сети».
4. A-HOME одним новым маршрутом, правдивые счётчики (интеграционный тест на подсчёт). A-SIG со статусами и действиями на сервере (версия, журнал, комментарий при закрытии, тест).
5. Сигнал «поставщик недостижим»: детектор, один открытый на компанию, самозакрытие, интеграционный тест.
6. A-SET-01 и история с курсором (серверный курсор — аддитивно, тест), A-SET-02, A-SET-06: правка с причиной, «было → стало», конфликт, операторские настройки только для чтения.
7. A-AUD: отборы, подгрузка, понятные действия, «было → стало», причина, частично скрытые номера.
8. «Безопасность»: новые резервные коды; сброс второго фактора другому администратору с причиной.
9. Секреты не попадают в хранилище браузера, адрес, историю, консоль — проверено.
10. D-068, D-069, всплывающие сообщения; светлая и тёмная тема; 1024 и 1920.
11. Контракт аддитивно: `openapi:compat` без трейлера, `openapi:check` — PASS.
12. `ARCHITECTURE.md` — раздел решений (библиотека компонентов, общая веб-сессия, маршрут главной, статусы сигналов, детектор). `CLAUDE.md` блок 0 — как войти в админку в dev и что там есть.

## Что должно реально работать

Product Owner получает права администратора командой оператора на свой номер. В браузере компьютера он:
1. Входит в админку по коду.
2. Сканирует QR приложением-аутентификатором и сохраняет резервные коды.
3. Видит на главной правдивые счётчики.
4. Открывает «Настройки», меняет срок ответа поставщика с причиной — и видит это изменение в «Журнале» с «было → стало».
5. Берёт сигнал в работу и закрывает с комментарием.

Закрывает браузер, открывает снова — по-прежнему внутри (до 12 часов).
