# TASK-035.C — Справочник автомобилей: годы из списка, новый двигатель из модификации, без поля «Рынок»

Модель: Opus 5.5, Medium

## Цель

Product Owner проверил раздел «Автомобили» (TASK-035.B) и принял три решения (08.10.2026, D-071):

1. **Годы — выбор из списка**, а не ввод числа: с 2000 года по текущий.
2. **Новый двигатель — прямо из модификации.** Сейчас новый двигатель нельзя завести, не уходя во вкладку «Двигатели». Нужно как с брендом в позициях (TASK-035.B): поиск ничего не нашёл → «Новый двигатель «…»» → форма → он выбран.
3. **Поле «Рынок» (Казахстан / Другие рынки) убрать из админки.** Его не выбирает владелец в приложении, и его не учитывает подбор запчастей. Отличия версий для разных рынков уже видны по двигателю, коробке и приводу модификации. Сервер и данные не трогаем. Вернёмся к рынку, если понадобится — например, вместе с подбором по VIN, где рынок определится автоматически.

## Контекст

- **Справочник автомобилей** — TASK-014, TASK-035.B; ARCHITECTURE 4.24, 4.54.
- **Годы:**
  - у поколения — «с … по …», «по» необязательно;
  - у модификации — в пределах поколения;
  - согласованность проверяет сервер;
  - в админке сейчас — числовые поля.

  В казахстанском техпаспорте «год выпуска» — год производства, будущим он не бывает. Поэтому список — по текущий год включительно.
- **Выбор с поиском** — один компонент `SearchSelect` (`apps/admin-web/src/search-select`). Пример «нового значения из списка» — «Новый бренд «…»» в форме позиции.
- **Рынок модификации** — поле `market` (`kz` / `global`) в контракте, таблице, импорте и отборах. Приложение по нему не фильтрует. В админке сейчас — выбор в форме модификации и столбец в таблице модификаций поколения.

## Требования

### 1. Годы — выпадающий список

- **Список у поколения** («Год с», «Год по») и **у модификации** — **от текущего года вниз до 2000**, вместо ввода числа.
  - У «Год по» первым пунктом идёт «по настоящее время» (пусто).
  - У модификации список ограничен годами её поколения.
- **Запись старше 2000 года** (могла прийти импортом) показывает свой год и даёт его сохранить, а не ломается и не обнуляется молча.
- **Год на сервере.** Нужен ли серверный предел «не позже текущего года» — решение агента, записать его в ARCHITECTURE. Импорт с будущим годом не должен тихо проходить, если админка такого года не допускает.

### 2. Новый двигатель из модификации

- **Поле «Двигатель» формы модификации:**
  1. поиск ничего не нашёл;
  2. пункт «Новый двигатель «{введённое}»»;
  3. форма двигателя: код из введённого, топливо, объём, мощность;
  4. после сохранения новый двигатель выбран в модификации, уже введённое в её форме не теряется.
- **Одно поведение для всех.** Так же работает любое «новое значение» в выборе с поиском, если компонент его поддерживает: бренд уже так работает. Второго поведения быть не должно.

### 3. Без поля «Рынок» в админке

- Убрать выбор рынка из формы модификации и столбец рынка из таблицы модификаций.
- Новые модификации из админки получают прежнее значение по умолчанию (`kz`), сервер это принимает.
- **Ничего не менять:** контракт, таблицу, импорт (колонка `market` остаётся необязательной, как сейчас) и клиентский выбор.
- В записях журнала о модификации рынок не показывать — он ничего не говорит администратору.

## Бизнес-правила

- Все проверки на сервере, админка показывает ответ.
- Совместимость и подбор не меняются.

## Edge cases

- Модификация с годом 1998 из импорта: открыть, поправить двигатель, сохранить — год остаётся 1998.
- Наступил новый год — список сам начинается с нового года, без релиза.
- Два администратора одновременно добавляют один и тот же новый двигатель из двух модификаций — второй получает «Такой двигатель уже есть» и может выбрать существующий.
- Форма двигателя закрыта без сохранения — модификация осталась с введённым, двигатель не выбран.

## Не входит

- Справочник стран или рынков, изменение контракта и данных о рынке.
- Подбор по VIN.

## Acceptance Criteria

1. Годы — выпадающие списки 2000…текущий в поколении и модификации (у модификации — в пределах поколения); запись старше 2000 не ломается. Тест логики списка годов.
2. «Новый двигатель «…»» из модификации: форма, выбор после сохранения, введённое не теряется, дубль — понятный отказ. Поведение — у общего компонента.
3. Поля и столбца «Рынок» в админке нет. Создание модификации проходит. Контракт не менялся (`openapi:check` PASS, контракт в git без изменений).
4. Проход в браузере: Changan CS55 «I» с годами из списка и новым двигателем, созданным из модификации; импорт `import-example.csv` по-прежнему проходит.
5. `ARCHITECTURE.md` — короткий раздел; `CLAUDE.md` блок 0 — поправить «Автомобили в админке».
6. `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — PASS; CI на main — success.
7. Отчёт `tasks/TASK-035.C-REPORT.md` со списком проверок для Product Owner.

## Что должно реально работать

Product Owner заводит Changan CS55 «I», выбирая годы из списка. В модификации двигатель, которого ещё нет, создаёт прямо из поля «Двигатель», и он сразу выбран. Поля «Рынок» в форме нет.
