# TASK-035 — Админка: справочник товаров

Модель: Opus 5.5, High

## Цель

Справочник — основа каталога: категории, характеристики, позиции, переводы, фото, совместимость. Сейчас администратор ведёт его только запросами к API. Задача даёт экраны админки для всего справочника товаров.

Справочник автомобилей и импорт файлом (A-CAR-01, A-CAR-02) вынесены в следующую задачу **TASK-035.B**: план разделён, чтобы задачи были посильными за одну сессию.

## Контекст

- **SCREENS.md 7.2** — A-CAT-01 «Категории», A-CAT-02 «Характеристики», A-CAT-03 «Дозаполнение», A-CAT-04 «Позиции», A-CAT-05 «Карточка позиции» (вкладки: Основное, Характеристики, Переводы, Фото, Совместимость, Аналоги, Предложения, История). **SCREENS 7.0** — общие правила админки: причина, «было → стало», конфликт версий, номера скрыты, код заявки не показывается.
- **Сервер готов** (TASK-010…013, TASK-015, TASK-018; ARCHITECTURE 4.15, 4.17, 4.18, 4.19, 4.22, 4.25, 4.28; все маршруты с примерами — `CLAUDE.md` блок 0, разделы «Справочник в dev», «Позиции справочника в dev», «Товары, ставшие одинаковыми», «ИИ и автоперевод», «Фотографии позиций», «Совместимость в dev»):

  - **позиции** — поиск, отборы, создание, правка, значения, статус, аналоги, дубль 409 `CATALOG_ITEM_DUPLICATE` с `existingItemId`;
  - **дозаполнение** — таблица и запись «всё или ничего» с ошибками по ячейкам;
  - **переводы** — список ждущего, ручной текст, «Перевести заново», «Снять правку», источник `source/ai/manual`, `isSourceChanged`;
  - **фото** — загрузка (тело — файл), статусы с причиной, порядок, `photo_display_mode`;
  - **совместимость** — записи с условиями, архив, копирование с аналога, предложения поставщиков (очередь, подтвердить как есть или с правкой, отклонить с причиной);
  - **предложения позиции** (только просмотр — админский `GET /admin/suppliers/{id}/offers` или нужный аддитивный маршрут «предложения позиции»).
- **Админка** (TASK-034, ARCHITECTURE 4.52): каркас, `@adclub/ui` без внешней библиотеки, общая веб-сессия, D-068, D-069, всплывающие сообщения. Разделы «Справочник» сейчас «появится». На главной (A-HOME) есть счётчики качества справочника: без фото, неполные, без совместимости, без перевода. Теперь они должны вести в отфильтрованный список позиций.
- **Языки:** интерфейс админки — русский; данные справочника — kk/ru/en. Бренды не переводятся.

## Требования

### 1. Категории и характеристики (A-CAT-01, A-CAT-02)

- **Дерево двух уровней**, товары и услуги — раздельно.
  - У узла: названия kk/ru/en с источником перевода, значок (выбор из `categoryIcons` контракта с предпросмотром глифа), «Совместимость обязательна», статус (активна / скрыта / в архиве).
  - Создание, правка, перенос к другому родителю, изменение статуса.
  - Изменение порядка (перетаскиванием или стрелками) — всегда с проверкой ожидаемого порядка.
- **Характеристики категории:**
  - тип (число / список / да-нет / текст), единица, «Использовать в фильтрах», «Участвует в полноте», порядок, архивирование с сохранением значений;
  - варианты списка — с порядком и архивом;
  - при добавлении — «У N позиций значение будет пустым» и «Дозаполнить»;
  - если изменение сделало товары одинаковыми (`sameProductItems` > 0) — заметное предупреждение со ссылкой на список таких позиций.
- **Конфликт версий** — «Эти данные только что изменил {администратор}. Обновите страницу», введённое не теряется.

### 2. Дозаполнение (A-CAT-03)

- Таблица «позиции категории × характеристики», отбор «Только пустые» (по выбранной характеристике), правка в ячейке по типу (список — выбор варианта, число — с единицей, да-нет, текст).
- **Сохранение пакетом** «всё или ничего».
  - Ошибки — у своих ячеек, остальные правки не теряются.
  - Конфликт по ячейке (кто-то поменял значение) — показать текущее значение.

### 3. Позиции (A-CAT-04)

- **Поиск** по артикулу в любом написании и названию на любом языке. Подгрузка курсором, «всего N».
- **Отборы:** категория, бренд, тип, статус, «есть предложения», «без фото», «неполные характеристики», «без совместимости» (в категориях с обязательной совместимостью), «без перевода», «совпадают с другим товаром».
  - Чего нет на сервере — добавить аддитивно.
  - **Правило каждого отбора — то же, что у счётчика главной** (одно место, не второе правило). Счётчики A-HOME ведут сюда с соответствующим отбором, и число строк совпадает со счётчиком.
- **Строка:** миниатюра, название, бренд и артикул, категория, полнота, статус, число предложений.

### 4. Карточка позиции (A-CAT-05)

| Вкладка | Что сделать |
|---|---|
| Основное | Тип, бренд (выбор с поиском по написаниям), артикул и нормализованный вид, категория, название ru; создание новой позиции той же формой. Дубль «бренд + артикул» — «Такая позиция уже есть» со ссылкой. Статус. **Архивирование позиции с предложениями** — «У позиции N предложений и M активных заявок. Предложения будут сняты с витрины, заявки нужно выполнить» (числа — с сервера, аддитивно, если их нет) |
| Характеристики | Значения по активным характеристикам категории, пустые видны, сохранение с версией |
| Переводы | kk/ru/en по каждому полю: текст, источник («ИИ» с моделью / «вручную» / исходный), «исходник изменился», ждущая или отказанная задача с причиной. Ручная правка («ИИ её не затрёт»), «Перевести заново» (только для ИИ, отсутствующего и отказанного), «Снять ручную правку» |
| Фото | Загрузка файла (JPEG / PNG / WebP; источник и ссылка обязательны для найденных в интернете — поля формы). Список со статусами «предложено / подтверждено / отклонено / удалено», «Подтвердить», «Отклонить» с причиной, «Убрать», порядок подтверждённых (первая — основная). Отказы сервера словами: не изображение, неподдерживаемый формат, битый файл, слишком большой |
| Совместимость | Записи: условия (марка обязательна, модель, поколение, кузов, двигатель, КПП, привод, годы) выбором из справочника автомобилей, источник; создание, правка с версией, архив, «Скопировать с аналога». Предложения поставщиков «на рассмотрении»: «Подтвердить», «Подтвердить с правкой», «Отклонить» с причиной; «Такая запись уже подтверждена». **Проверка «подходит ли автомобилю»:** выбрать автомобиль — увидеть результат сервера (подходит / уточните параметр / не подходит / не указано) |
| Аналоги | Связи: добавить поиском, убрать |
| Предложения | Только просмотр: поставщик, цена, наличие, видно ли на витрине и почему. Число активных заявок |
| История | Журнал действий по этой позиции (`entityType=catalog_item`, а также её фото, совместимость) |

Для услуг — те же вкладки, что применимы. Вкладки «Совместимость» у услуги нет: сервер её не допускает.

### 5. Связи с главной и журналом

- Счётчики качества справочника на главной ведут в отфильтрованные списки позиций.
- В журнале ссылка на объект справочника открывает его карточку. Для категории, характеристики и варианта — дерево с выделенным узлом.

## Бизнес-правила

- Все проверки — на сервере: уникальность названий, два уровня дерева, тип характеристики, дубль позиции, идентичность товара, формат фото, согласованность условий совместимости.
- Админка показывает отказ сервера у нужного поля, а не общей ошибкой.
- Порядок меняется только с проверкой ожидаемого порядка (I151). Админка всегда передаёт его.
- Причина в справочнике не обязательна (SCREENS 7.0 её не требует), кроме отклонения фото и предложения совместимости — там её требует сервер.
- Совместимость считает только сервер. Админка не вычисляет «подходит» сама.
- Переводы: ручной текст автоперевод не затирает. Это правило сервера, админка его показывает.
- Код заявки и полные номера не показываются нигде.

## Edge cases

- Два администратора меняют порядок одних соседей — второй получает конфликт, а не тихую перезапись.
- Архивирование характеристики, после которого товары совпали, — предупреждение со ссылкой, а не отказ.
- Позиция без категории характеристик (новая категория) — понятное пустое состояние.
- Загрузка фото на остановленное хранилище — «Хранилище недоступно, попробуйте позже», остальное работает.
- Длинные казахские названия в дереве и таблицах — перенос или многоточие с полным текстом по наведению, без поломки раскладки.
- Тысячи позиций в категории — дозаполнение постранично, без зависания страницы.
- Повторная загрузка того же файла — сервер отвечает «уже есть», админка не создаёт дубль в списке.

## Не входит

- Справочник автомобилей и импорт файлом — TASK-035.B.
- Модерация запросов на позиции и фото от поставщиков, кандидаты фото от ИИ (этапы C–D). Предложения совместимости от поставщиков — **входят** (сервер готов).
- Услуги как отдельный раздел A-SRV (этап C). Услуги в списке позиций и в дереве — входят.
- Поставщики, заявки, пользователи (TASK-036).

## Что должно реально работать

Product Owner в админке:
1. Открывает с главной «Без фото».
2. Загружает фото колодок и подтверждает его.
3. Правит казахское название «Тормозных колодок».
4. Добавляет колодкам совместимость с ещё одной моделью и проверяет её на конкретном автомобиле.

В приложении через минуту у колодок фото, казахское название новое, а для добавленной модели они видны в каталоге с отметкой «Подходит».
