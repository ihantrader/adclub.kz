# TASK-036 — Админка: поставщики (воронка, список, карточка, сотрудники, статусы)

Модель: Opus 5.5, High

## Цель

Чтобы позвать реальных поставщиков на внутреннюю альфу, администратор должен вести их в админке:
- принимать заявки на подключение и вести их по воронке;
- заводить компанию с первым сотрудником;
- править профиль и часы точки;
- ставить паузу и блокировку;
- восстанавливать удалённых сотрудников.

Сейчас всё это делается запросами к API и командами оператора.

TASK-036 в плане разделена на две посильные задачи:
- **TASK-036** — поставщики;
- **TASK-036.B** — заявки, пользователи (включая клубный доступ) и общий поиск.

## Требования

### 1. Воронка (A-SUP-01)

- **Колонки или вкладки по статусам** со счётчиками: «Новая», «Связались», «Встреча», «Договор подписан», «Заведён», «Отказ».
  - Отборы — город, тип, БИН.
  - Заявки одного БИН помечены «ещё N заявок этого БИН».
- **Карточка заявки:**
  - данные формы (компания, БИН, город, что предлагает, контактное лицо, телефон — частично скрыт), заметки (добавить), история;
  - переход статуса — только допустимые сервером;
  - «Отказ» и «Вернуть из отказа» — с причиной.
- **«Добавить заявку вручную».**
- **«Завести поставщика»** из заявки «Договор подписан» → A-SUP-04.
- С главной «Новые заявки на подключение» ведёт сюда с отбором «Новая».

### 2. Заведение (A-SUP-04)

- **Из заявки** — форма заполнена её данными: компания, БИН, город (выбор), тип, адрес и район точки, первый сотрудник (имя, телефон).
- **Без заявки** — «Новый поставщик».
- **Кнопка «Создать и отправить приглашение».**
  - После — карточка поставщика и «Приглашение отправлено в WhatsApp».
  - Если такой БИН уже есть — понятный отказ со ссылкой на существующего поставщика.

### 3. Список поставщиков (A-SUP-02)

- **Отборы:** состояние (активен / пауза / блокировка / проверенный), город, тип. Поиск по названию и цифрам БИН. Подгрузка, «Всего N».
  - Отборы «рейтинг» и «проблема с оплатой» — этапы C–D, не показывать.
- **Строка:** название, город, тип, состояние с меткой, «проверенный», число сотрудников, активных предложений.
  - Если числа нет на сервере — добавить аддитивно.

### 4. Карточка поставщика (A-SUP-03)

| Вкладка | Что сделать |
|---|---|
| Профиль | Название, БИН, город, тип, адрес, район, телефон компании, «доставка по умолчанию»; правка с версией. Часы работы по дням (с перерывом, круглосуточно, выходной) и нерабочие даты — той же формой, что в кабинете (общий код, если возможно). Подсказка D-060: «Без часов работы предложения не показываются клиентам» |
| Статусы | «Проверенный партнёр» с датой договора; «Пауза» и «Блокировка» с **обязательной причиной** и подтверждением «Предложения будут сняты с витрины. Текущие заявки остаются в силе», для блокировки — ещё «Сотрудники не смогут принимать заявки и добавлять коллег; выдача по коду останется». Снятие — тоже с подтверждением. История статусов |
| Сотрудники | Текущие и удалённые (кто и когда удалил); «Добавить» (имя, телефон); «Отправить приглашение повторно» с понятным отказом по пределу; «Назначить контактным лицом»; «Восстановить доступ» с причиной; получатели уведомлений и предел; **сессии сотрудника** — устройство, время, «Завершить», «Завершить все сессии сотрудника» |
| Предложения | Только просмотр: вкладки «В продаже» / «Снятые», позиция, цена, наличие, видно ли клиентам и почему; ссылка на позицию справочника |
| Заявки | Список заявок компании (номер, позиция, статус, дата) только для чтения; полный раздел с карточкой и действиями — TASK-036.B (до неё — номер без перехода или «появится») |
| История | Журнал по компании, её сотрудникам и предложениям |

Вкладки «Рейтинг и отзывы», «Подписка», «Модерация» — этапы C–D, не показывать.

### 5. D-070 на сервере

- **Заблокированная компания не может:**
  - добавить сотрудника — ни из кабинета, ни администратором;
  - отправить приглашение, включая повторное.
- **Ответ сервера** — понятная ошибка. Код ошибки аддитивно, например существующий `SUPPLIER_BLOCKED`.
- **Кабинет поставщика** показывает этот отказ текстом. Кнопку «Добавить сотрудника» при блокировке лучше скрыть, но правило — на сервере.
- **Приглашение, поставленное в очередь до блокировки** и ещё не ушедшее, — не уходит (`stillSend` субъекта приглашения).
- **Интеграционный тест:** кабинет и администратор получают отказ, приглашение не уходит, после снятия блокировки всё снова работает.

### 6. Связи

- **С главной:** «Новые заявки на подключение» → воронка; сигнал «Поставщик недостижим» → «Открыть объект» → карточка поставщика, вкладка «Сотрудники».
- **Журнал:** ссылки на поставщика, сотрудника, заявку на подключение открывают нужную карточку.
- **Годы, БИН, номера** в журнале и везде — без разделителя тысяч.

## Бизнес-правила

- Все проверки на сервере: переходы воронки, БИН (контрольная сумма), уникальность БИН, мобильный номер, пределы приглашений, последний сотрудник, предел получателей уведомлений.
- Причина обязательна для паузы, блокировки, восстановления сотрудника, отказа и возврата заявки на подключение. Пустую причину не принимают ни клиент, ни сервер.
- Номера сотрудников и контактов заявок частично скрыты. Раскрытие полного номера с записью в аудит — общее правило, делается в TASK-036.B. Здесь достаточно скрытия.
- Код заявки не показывается нигде.
- **Не отправлять реальных сообщений:** в dev канал тестовый (`/dev/messages`). Никаких настоящих номеров в тестах.

## Edge cases

- Два администратора двигают одну заявку воронки — второй видит конфликт.
- Заявка того же БИН, что уже заведённый поставщик, — пометка и ссылка на поставщика.
- Восстановление сотрудника, чей номер уже состоит в другой компании, — понятный ответ сервера.
- Блокировка при открытом кабинете сотрудника — следующий «Добавить сотрудника» в кабинете получает отказ текстом.
- Пауза у компании без часов — обе причины «не видно» объясняются в «Предложениях».
- Длинное казахское название компании — без поломки раскладки на 1024.

## Не входит

- Раздел «Заявки» и карточка заявки с действиями, пользователи, клубный доступ, общий поиск, раскрытие номеров с аудитом — TASK-036.B.
- Рейтинг, отзывы, подписки и платежи, модерация — этапы C–D.

## Acceptance Criteria

1. A-SUP-01: колонки со счётчиками, отборы, карточка с заметками и историей, переходы только допустимые, отказ и возврат с причиной, ручная заявка, переход с главной.
2. A-SUP-04: заведение из заявки (форма заполнена) и без заявки, приглашение W-08 видно на `/dev/messages`, дубль БИН со ссылкой.
3. A-SUP-02: отборы, поиск, строки с числами (аддитивно, если нужно).
4. A-SUP-03: все вкладки из таблицы: правка профиля и расписания с версией; статусы с причиной и подтверждениями; сотрудники — добавление, повтор приглашения с пределом, контактное лицо, восстановление с причиной, сессии и их завершение; предложения и заявки компании; история.
5. D-070: интеграционный тест (кабинет и администратор, ждущее приглашение, снятие блокировки); кабинет показывает отказ текстом.
6. Связи с главной и журналом; числа без разделителя тысяч (тест форматирования).
7. Проход в браузере:
   1. заявка с публичной формы (`POST /supplier-leads`) → по воронке → заведение → вход сотрудника в кабинет по приглашению;
   2. пауза → предложения пропали из каталога приложения;
   3. блокировка → кабинет не может добавить сотрудника, выдача по коду работает;
   4. снятие блокировки;
   5. восстановление удалённого сотрудника.
8. Контракт аддитивно, `openapi:compat` без трейлера, `openapi:check` PASS.
9. `ARCHITECTURE.md` — раздел решений; `CLAUDE.md` блок 0 — «Поставщики в админке».
10. `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — PASS; CI на main — success.
11. Отчёт `tasks/TASK-036-REPORT.md` со списком проверок для Product Owner.

## Что должно реально работать

Product Owner отправляет с публичной формы заявку «Детали Юг». В админке проводит её по воронке до «Договор подписан» и заводит поставщика с первым сотрудником — приглашение видно на `/dev/messages`. Задаёт точке часы работы. Ставит компании паузу с причиной и видит, что её предложения пропали из каталога приложения. Снимает паузу.

Блокирует «Автомаркет» — в кабинете нельзя добавить сотрудника, а выдача по коду работает. Снимает блокировку.
