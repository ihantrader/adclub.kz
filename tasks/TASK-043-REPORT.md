## Result
В админке появился раздел «Биллинг» (SCREENS 7.8 A-BILL-01…04). Он стоит в меню между «Поставщиками» и «Настройками» и состоит из четырёх вкладок.

- **«Сводка» (`/billing`).** Период — дни по Алматы, по умолчанию последние 30. На странице:
  - подписки пользователей: действующие (iOS / Android / прочие), новые и прекращённые за период;
  - поставщики по группам: «Оплачено», «Проблема с оплатой», «Пауза по оплате», «Без подписки»;
  - списания периода: успешные (число и сумма) и отказы банка;
  - тариф поставщиков и его ближайшее изменение.

  Каждая карточка открывает список с теми же отборами, и **её число равно «Всего» этого списка**. Это так, потому что сводка и списки считают одной и той же функцией.
- **«Подписки пользователей» (`/billing/users`).** Вкладки «Действующие», «Прекращённые», «Все» со счётчиками. Отборы хранятся в адресе: статус, платформа, провайдер, «истекает в ближайшие N дней», период начала или прекращения, поиск по части номера или по имени, `accountId`. Номер скрыт. Строка открывает вкладку «Клубный доступ» пользователя.
- **«Платежи поставщиков» (`/billing/payments`).**
  - «Неуспешные»: отказ банка, «ждёт платёжную систему», пауза. В строке — сумма, причина, номер попытки и время последней, следующая попытка (или «Автоматических попыток больше не будет»), дата паузы и «через N дней».
  - «История списаний»: отборы по периоду, поставщику, статусу и виду. Карта показана только маской. У «Оплатить сейчас» видно, кто из сотрудников нажал. Есть «на сумму N ₸».
  - «Все поставщики»: все пять групп.
- **«Тарифы» (`/billing/plans`).**
  - Поставщики: тариф в силе, объявленное и запланированное изменения, история записей (отменённые тоже, с указанием, кто и почему их завёл или отменил).
  - «Запланировать изменение…»: показывает «было → стало» и дату анонса; сервер проверяет правила.
  - «Отменить…»: доступно только для записи, которая ещё не вступила в силу.
  - Пользователи: записи тарифа только для просмотра. Текст анонса повышения правится тем же диалогом, что в «Настройках».
- **Главная.** Карточка «Платежи поставщиков не прошли · N» ведёт в «Неуспешные» и показывает отказы банка вместе с паузами.
- **«Открыть объект» у сигналов.** «Платёжная система недоступна» ведёт в «Неуспешные» с группой ожидания, «Нет тарифа» — в «Тарифы».
- **Карточки.** У пользователя появилась ссылка «Все подписки», у поставщика — «Все платежи».

Администратор ничего не списывает и статусов не меняет. Команда оператора `billing:plan:add` / `billing:plan:list` осталась и работает через тот же сервис `Plans`.

## Technical Decisions
Все решения внесены в ARCHITECTURE 4.78.

- **I847 — сводка равна списку.**
  - Число сводки — вызов функции счёта своего списка с его отборами.
  - «Действующая» подписка — та, что даёт доступ по `subscriptionAccessUntil` (SQL-двойник общий с клубным доступом).
  - «Новая за период» — первое применённое `started` попало в период.
  - «Прекращена за период» — подписка сейчас в `expired`, и переход в `expired` попал в период. Подписка, которая лапсировала и снова действует, прекращённой не считается: это найдено при проходе в браузере и исправлено.
  - У поставщика пять групп, каждый ровно в одной: `paused` → `declined` → `awaiting_provider` → `paid` → `none`. В задаче было четыре группы; «ждёт платёжную систему» вынесена отдельно, потому что это не неуспех плательщика. «Проблема» в сводке = `declined` + `awaiting_provider`.
- **I848.** Курсоры и индексы — см. замер ниже.
- **I849.** «Следующая попытка» и «дней до паузы» считаются одной доменной функцией для кабинета, W-05 и админки.
- **I850 — правила нового тарифа администратора:**
  - начало не раньше завтрашнего дня; самый первый тариф можно начать сегодня;
  - повышение — не раньше первого дня, чьё 00:00 не раньше «сейчас + N дней», и N ≥ 1;
  - для понижения N не требуется;
  - цена от 1 до 1 000 000 ₸, N от 0 до 365;
  - одновременную правку отсекает версия (число записей + число отмен);
  - команда оператора идёт тем же сервисом, но без правил дат: так команда сохраняет свободу, как с настройками безопасности (D-053), и продолжает заводить тарифы задним числом в dev и тестах.
- **I851 — отмена.** Запись не удаляется, а помечается. Анонс исчезает из кабинета со следующего запроса; это сделано осознанно, и диалог предупреждает об этом. Освобождённый день можно запланировать снова.
- **I852.** Текст анонса правится через `SettingDialog`: второго пути записи настройки нет.
- **I853 — главная и сигналы:**
  - карточка главной заменила прежнюю карточку сигнала `payment_failed`; сам сигнал остался в «Сигналах»;
  - «Открыть объект» у `payment_failed` по-прежнему ведёт в «Подписку» поставщика: объект один, и его карточка полезнее списка.

## Deviations
- **Пять групп поставщиков вместо четырёх.** «Ждёт платёжную систему» выделена из «проблемы», потому что это не отказ плательщика (I819). «Проблема» в сводке остаётся их суммой.
- **Правила дат — только для администратора.** Команда оператора идёт тем же сервисом, но правил «не сегодня / повышение не раньше срока» не применяет: в тестах и dev тарифы заводятся задним числом. Решение записано в I850.

## Known Issues / Risks
- **Отмена тарифа убирает уже показанный анонс.** Так задумано, но поставщик, который его видел, отдельного сообщения не получает.
- **Откат миграции удаляет отменённые записи `plan`.** Иначе нельзя вернуть полный уникальный ключ.
- **Числа сводки и списка снимаются разными запросами.** Между сводкой и открытием списка данные могут измениться — это ожидаемо.
- **CI.** Прогон запускается push'ем; его id — в ответе агента. Результат не ожидался.
