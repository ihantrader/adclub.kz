## Technical Decisions
Все решения внесены в ARCHITECTURE.md 4.65.

- **Регистрация изменений — триггеры (I669).** Их вызывает одна функция базы, а не вставки из сервисов: любой путь записи (сервис, операторская команда, импорт, seed) регистрирует себя сам, откат транзакции не оставляет строки.
- **Применение outbox (I670).** Singleton-задача, которую раз в секунду ставит наблюдатель worker'а. Если индекс недоступен, это не сбой задачи: строки ждут, следующая попытка — через 2ⁿ с, не больше 5 минут.
- **Документ хранит ключи домена (I671).** Это `searchKey`: индекс сравнивает ровно то же, что домен. Значений-токенов для фасетов в документе нет — числа считаются по показанному. Это отклонение от состава 10.1, обоснование ниже в Deviations.
- **Совместимости в индексе нет (I672).** Кандидатов фильтрует единый `CompatibilityEvaluator`.
  - Замер на 3 000 позиций: общий запрос «масло» с Atlas II и городом — 3 004 результата, медиана 466 мс и 508 мс в двух запусках теста (по 5 прогонов, 425–583 мс); применение outbox для 3 000 новых позиций — 5,3–5,5 с.
  - Применение outbox для 3 000 новых позиций — 5,3 с.
- **Синонимы — группы в настройках индекса (I673).** Группа — синонимы категории вместе с её названиями.
- **Запрос (I674).** Варианты уходят одним `multi-search` дважды: со стратегией `all`, а если ничего не нашлось — `last`. Кандидат без единого слова запроса в своих текстах отбрасывается: Meilisearch со стратегией `last` давал «зимние шины» → задние колодки.
- **Порядок (I675):** артикул → точное → частичное → только с опечаткой; внутри — город → релевантность → популярность → «своё название» → цена → id.
- **T-CAT-08 (I676):** `searchReading` по текстам найденного, с учётом склейки «5w30» ↔ «5W-30».
- **Фасеты (I677)** — точные числа по показанному. Счётчики значений характеристики считаются без её собственного фильтра.
- **Падение индекса (I678–I680).** Ответ из PostgreSQL. Перестройка — через `swap-indexes` с повторным применением изменений, пришедших во время перестройки. Ночная сверка.
- **Качество (I681).** Набор фраз и тот же прогон в тесте и в команде оператора.

## Errors & Fixes
- **Стратегия `last` давала мусор.** Meilisearch находил по «зимние шины» задние колодки с оценкой 0,11. Добавлено доменное правило: кандидат без единого слова запроса в своих текстах не показывается (`searchReading().kept`).
- **«масло 5w30» показывало T-CAT-08 «масло».** Прочтение не знало, что индекс склеивает «5w 30». `searchReading` теперь учитывает пары соседних слов.
- **Линтер запрещает импорт модулей мимо `index`.** Прямой импорт `visibleOffers` из showcase создал бы цикл showcase ↔ search-index. Документ строится по `shownOffers` — тому же SQL-двойнику правила, которым выбирает `visibleOffers`.
- **Цепочка отката миграций** в `database.integration.test.ts` начиналась с последней миграции, и тест сломался после её добавления. Для новой миграции добавлено звено.
- **Падение под нагрузкой.** При одновременном запуске пяти интеграционных файлов (≈10 контейнеров) один тест TASK-044 один раз ответил 500 — похоже на таймаут запроса под нагрузкой. Отдельно файл проходит 18/18.

## Deviations
- **Состав документа отличается от 10.1** (обосновано в I671). Нет `attrs.*`-токенов для фасетов, `compat`, `names_translit`, `min_price`, `has_photo`, `is_complete`.
  - Задача прямо называет «значения фильтруемых характеристик для фасетов». В документе они есть как искомый текст (`values`: «5w 30»).
  - Числа фасетов индекс не даёт: по условию задачи они точные, по показанному, поэтому считаются в PostgreSQL функциями списка подкатегории.
- **Регистрация через триггеры.** Задача говорит «через одну функцию»; функция — в базе (`search_outbox_register`), и вызывают её триггеры, а не сервисы. Обоснование — I669.
- **Популярность не регистрируется заявками.** Её обновляют ночная сверка и любое перестроение документа: заявка, меняющая популярность, через outbox не проходит.

## Known Issues / Risks
- **Мгновенное отражение в индексе зависит от worker'а.** Без него индекс отстаёт, но лишнего не показывает. На машине без `MEILISEARCH_URL` поиск работает на PostgreSQL, как раньше.
- **Кандидатов — не больше 5 000 на вариант запроса** (`maxTotalHits`, как предел TASK-044). Для очень общего запроса на большом справочнике будут видны только первые 5 000 по релевантности.
- **Доступ к индексу.** В production нужен ключ с правами на поиск и запись (`MEILISEARCH_API_KEY`), а не мастер-ключ. Отдельный ключ только на поиск для API — улучшение на будущее.
- **Нагрузка при локальном прогоне.** Под сильной нагрузкой (много контейнеров сразу) интеграционные тесты могут ловить таймауты запросов к PostgreSQL. В CI тесты разнесены по частям.
- **Приложение.** Нажатия в браузере в этой сессии проверялись через DOM: панель была скрыта. Камера и движение шторок к задаче не относятся.
