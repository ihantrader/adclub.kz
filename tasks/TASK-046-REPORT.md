# TASK REPORT — TASK-046

## Status
COMPLETED

## Result
Поставщик загружает свой прайс как есть — Excel `.xlsx` или CSV — в разделе «Прайс» кабинета (новая пятая вкладка). API сразу отвечает «обрабатываем», файл приватно ложится в объектное хранилище, а worker потоком раскладывает его в строки: находит заголовок под шапкой 1С, помечает служебные строки (шапка, группы, «Итого», повтор заголовка) и детерминированно определяет роли колонок (Артикул · Бренд · Название · Цена · Наличие · Срок) по словарю заголовков ru/kk/en и по содержимому. Кабинет показывает первые 20 строк товаров с выбором роли над каждой колонкой и пометкой «определено автоматически»; поставщик правит, оставляет «Запомнить для следующих загрузок» и нажимает «Продолжить» — сервер разбирает значения (цена в целых тенге, наличие, срок в рабочих днях) и показывает «Разобрано: N строк, ошибки в строках — M» со списком ошибок по строкам. Следующий файл того же формата проходит без экрана колонок; тот же файл узнаётся («Этот файл уже загружали»). Файл, который нельзя прочитать, отклоняется с причиной словами. Администратор видит загрузки поставщика на вкладке «Прайс» его карточки (только просмотр). Предложения и витрина не меняются — сопоставление и применение будут в TASK-047.

## Technical Decisions
Все внесены в `ARCHITECTURE.md` 4.66:
- **Библиотека для Excel (I683):** свой разбор каталога ZIP + `fflate` (распаковка) + `sax` (потоковый XML) — обе без зависимостей и поддерживаются, `pnpm audit` по ним чист; лист распаковывается и разбирается потоком, у каждого элемента потолок распаковки (ZIP-бомба — «файл повреждён»). SheetJS из npm (0.18.5) отвергнут из-за известных уязвимостей без исправлений в npm, `exceljs` — не обновлялся с 2023 года и тянет много зависимостей. `.xls` — понятный отказ «Сохраните как .xlsx»; `.xlsx` под паролем распознаётся. `pnpm add` прошёл без `EPERM`.
- **Колонки без ИИ (I689):** словарь заголовков как данные, самое длинное написание решает, «опт» — сомнительная цена (≤ 0,5), каждая роль — одной колонке, свободные роли — по содержимому.
- **Выбор листа (I686):** первый видимый лист со строкой «таблицы» (две ячейки и одна из них число); скрытые и обложки пропускаются.
- **Объединённые ячейки (I687):** по строкам — значение в каждую строку, по колонкам — только в первую.
- **Округление цены (I691):** до целого тенге, половина вверх.
- **Блокировка (I697):** загрузка и разбор разрешены (не пишут наружу и не меняют витрину), применение (TASK-047) будет запрещено.
- **Администратор (I698):** вкладка «Прайс» в карточке поставщика, только список; файла никто, кроме worker'а, не получает.
- **Предел частоты (I696):** на компанию в скользящий час, считается по записям в базе под advisory-блокировкой.

## Known Issues / Risks
- Казахские тексты кабинета и написания заголовков на казахском — черновик, не проверены носителем языка.
- Распознавание по содержимому эвристическое: у необычных прайсов (например, две колонки с ценами без заголовков) поставщик поправит роли сам — для этого и экран S-PRICE-02.
- `.xls` не поддерживается (только отказ с подсказкой); `.ods` — «не таблица».
- Во встроенном браузере не проверены настоящий системный выбор файла и перетаскивание мышью (подставлялось скриптом), а также загрузка с телефона.
- `pnpm audit --prod` по-прежнему показывает уязвимости в чужих зависимостях, не связанных с задачей (`sharp` < 0.35.5 в API, зависимости Expo в мобильном) — новые пакеты в списке не значатся.
