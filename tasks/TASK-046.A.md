# TASK-046.A — Импорт прайса: защита API и worker'а от тяжёлых файлов

Модель: Opus 5.5, High

## Цель

Приёмка TASK-046 (11.10.2026) показала, что импорт прайса работает, но файл может остановить сервер.

Архитектор собрал `.xlsx` размером 2 МБ, в котором часть `xl/sharedStrings.xml` объявлена как 100 байт, а внутри около 2 ГБ сжатых нулей. Результат:
- загрузка этого файла **на 6 секунд остановила весь API** — `/health` тоже ответил через 6 с;
- с разрешённым размером 20 МБ остановка — около минуты;
- отказанные файлы не считаются в пределе загрузок, поэтому любой сотрудник поставщика может повторять это без ограничения.

Эта задача убирает такую возможность в API и в worker'е и доделывает найденное при приёмке. Поведение для поставщика не меняется.

  - `file/xlsx.ts` — потолки `SMALL_CEILING` 64 МБ и `SHEET_CEILING` 512 МБ; объединённые ячейки обрабатываются в строках 470–511.

- **ARCHITECTURE:**
  - 4.66 (I682–I701) — решения TASK-046;
  - 12.1 — разбор в worker'е, не в API;
  - 12.3 — крупные файлы.
- **Требование TASK-046:** «Разбор — в worker, не в API. API отвечает сразу».
- **Проверка приёмки** (повторить в тесте) — скрипт архитектора собирает такой файл вручную:

## Требования

### 1. API не распаковывает и не разбирает файл
- API при загрузке делает только дешёвые проверки:
  - размер по ходу чтения тела (уже есть);
  - распознавание формата по первым байтам: подпись ZIP/OLE/PDF/картинки, текст и его кодировка по ограниченному началу файла;
  - хэш, запись в хранилище, запись `price_import`, постановка задачи.
- Всё, что требует распаковки `.xlsx` или прохода по всему CSV, делает worker:
  - зашифрованный или повреждённый `.xlsx`;
  - нет листа с таблицей;
  - слишком много строк;
  - кривой CSV.
  
  Загрузка становится `failed` с той же причиной, и кабинет показывает те же слова.
- Если какая-то проверка в API остаётся (например, пароль `.xlsx` по каталогу ZIP без распаковки), она не распаковывает данные и укладывается в единицы миллисекунд при любом файле до 20 МБ.
- **Тест:** файл-бомба 20 МБ, во время его загрузки `/health` отвечает быстрее 200 мс, загрузка отвечает 201 или 400 быстрее 500 мс.

### 2. Настоящий потолок распаковки
- Распаковка каждой записи — **потоком с обрывом**. Как только вышло больше объявленного размера или больше потолка записи, распаковка прекращается, и файл объявляется «повреждённым».
- Потолок записи берётся не из объявленного размера, а из общего бюджета.
- **Общий бюджет распакованных байтов на файл** — например, не больше N × сжатого размера и не больше абсолютного предела (значения выбирает агент и записывает в ARCHITECTURE).
- Ограничено число записей в архиве.
- Листы без таблицы распаковываются не больше одного раза.
- **Тест:** бомба в `sharedStrings`, бомба в листе, бомба при объявленном честном большом размере, тысячи записей. Каждый случай — отказ «повреждён» за разумное время, без роста памяти worker'а на гигабайты.

### 3. Отказы считаются в пределе
- Отказанная при загрузке попытка тоже входит в предел частоты компании (или в отдельный предел неудачных загрузок на сотрудника — решение агента).
- **Тест:** серия отказанных файлов приводит к 429.

### 4. Объединённые ячейки
- Число `mergeCell` ограничено (сверх — «повреждён» или «слишком сложный файл» словами).
- Применение объединений — без квадратичных проходов.
- Долгий синхронный разбор отдаёт управление циклу событий: тайм-аут задачи и остановка worker'а работают.
- **Тест:** лист с 100 000 объединений не вешает worker; соседние задачи выполняются.

### 5. Надёжность фоновой части
- **Повтор задачи `prices.parse`** у загрузки с запомненным форматом, упавшей во время чтения значений, продолжает её. Загрузка не висит в `reading` до тайм-аута.
- **Срок фазы** (`phase_started_at`) отсчитывается от начала работы worker'а, а не от загрузки. Загрузка, ждущая в очереди, не истекает, не начав читаться.
- **Загрузка, помеченная `failed`** (тайм-аут), больше не получает строк от опоздавшей задачи.
- **Ключ запомненного формата** — хэш заголовка (не сам текст в первичном ключе): у любых длинных заголовков `PUT …/columns` с «Запомнить» не даёт 500.
- **`PUT …/columns` из устаревшей вкладки** (после того как коллега уже подтвердил и загрузка разобрана) не перезаписывает молча: проверка версии загрузки или явное правило. Контракт — только аддитивно.
- **Испорченные курсоры** списка и строк (`1e20`, 36 дефисов и т. п.) — 400, не 500.

## Что должно реально работать

Сотрудник поставщика загружает файл-бомбу. Кабинет через мгновение пишет «Не удалось прочитать файл». Каталог, кабинеты и админка всё это время отвечают как обычно, а worker продолжает разбирать прайсы других компаний.
