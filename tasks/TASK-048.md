# TASK-048 — Импорт прайса: экран сверки и итог в кабинете, «Модерация», выгрузка и обратная загрузка

Модель: Opus 5.5, High

## Цель

После TASK-047 сервер умеет всё: сопоставление, черновик сверки, применение, запросы на позиции. Но поставщик видит только числа групп — сверять он может лишь запросами. Эта задача даёт поставщику в кабинете полный путь F9:

> загрузка → колонки → **сверка** → **итог** → **«Модерация»**

Плюс «Скачать мой прайс» и обратная загрузка этого файла со стопроцентным сопоставлением. После неё EPIC-16 закрыт.

## Контекст

**Экраны (SCREENS):**
- **S-PRICE-03 «Сверка»:**
  - сводка;
  - пять вкладок: «Уверенно» (свёрнуто, «12 500 → 13 000», резкая цена выделена и требует отдельного подтверждения), «Нужно проверить» («предложено ИИ», «Верно» · «Другая позиция» · «Пропустить», «Пропустить все оставшиеся»; массового подтверждения нет), «Не найдено» (по умолчанию «Отправить администратору на добавление», можно снять или найти вручную), «Ошибки в строках», «Пропали из файла» (выбор обязателен, без значения по умолчанию; «По N позициям есть активные заявки — их нужно выполнить»);
  - кнопка «Применить: обновить N · снять M · отправить на добавление K», неактивна до выбора по пропавшим; «N строк не проверены и не будут применены»;
  - незаконченная сверка сохраняется.
- **S-PRICE-04 «Итог»:** «Готово: обновлено N, снято M, на добавление отправлено K — результат в разделе „Модерация“»; «К предложениям»; «Цены в созданных заявках не меняются».
- **S-PRICE-01:** «Скачать мой прайс» — только свои предложения.
- **S-MOD-01 «Модерация»:** запросы на позиции, фото, совместимость; статусы «На рассмотрении» / «Добавлено» / «Отклонено: {причина}»; отметка «новое».
- **S-OFF-05 «Запрос на добавление позиции»:** из поиска позиции «Нет в справочнике? Отправьте запрос на добавление» — название, бренд, артикул или характеристики, категория (подсказки), комментарий → «Запрос отправлен администратору. Результат — в разделе „Модерация“». Фото — без него: фото поставщиков — EPIC-26.

**Решения:**
- D-039, D-052 — флажок подтверждения резкой цены в строке;

**Сервер TASK-047** (маршруты — в `packages/contracts/src/price-review.ts` и `routes.ts`):
- сводка `GET /supplier/price-imports/{id}/review`, строки по группам, решение по строке с `expectedVersion`, `skip-remaining`, пропавшие и выбор, `apply` (202 → `applying` → `applied` с `result`);
- `GET /supplier/catalog-requests`;
- предложения совместимости поставщика — `GET /supplier/compatibility-proposals` (TASK-015).

**Кабинет:**
- `apps/supplier-web/src/price/` — загрузка, колонки, итог разбора, новые состояния;
- образцы — «Предложения» (таблица и карточки, правка в строке, «Сохранено · Отменить»), поиск позиции `/offers/search`, `SearchSelect` из `@adclub/ui`;

**Найдено при приёмке TASK-047 (доделать здесь):**

## Требования

### 1. Экран сверки (S-PRICE-03) — `/price/<id>` в состоянии `review`

**Сводка — числа сервера.**

**Вкладки со счётчиками.** Списки — страницами, на телефоне — карточки, от 1024 — таблица (как «Предложения»).

**«Уверенно»:**
- строка файла ↔ позиция: название, бренд, артикул, фото;
- «было → стало» по цене, наличию, сроку; «новое предложение», если его нет;
- **резкая цена** выделена, в строке флажок «Подтвердить новую цену», без него строка не применится;
- «Изменить» — та же замена позиции, что «Другая позиция»;
- раскрыть и свернуть.

**«Нужно проверить»:**
- текст строки файла и предложенная позиция с кандидатами;
- «предложено ИИ» с пояснением модели;
- «Верно» · «Другая позиция» (поиск позиции поставщика, как `/offers/search`, с теми же отказами словами) · «Пропустить»;
- принятое решение видно в строке: кто и когда, «Отменить решение»;
- «Пропустить все оставшиеся» — с подтверждением «N строк не будут применены»;
- **кнопки «подтвердить всё» нет нигде** (D-039).

**«Не найдено»:**
- по умолчанию — «Отправить администратору на добавление» (переключатель в строке);
- «Найти вручную» — тот же выбор позиции;
- ранее отклонённый администратором ключ приходит выключенным, с причиной отказа (как решил сервер).

**«Ошибки в строках»** — номер строки, текст, причина словами; не применяются.

**«Пропали из файла»:**
- список (позиция, цена, активные заявки);
- предупреждение «По N позициям есть активные заявки — их нужно выполнить»;
- выбор «Снять с продажи» / «Оставить как есть» без значения по умолчанию.

**Кнопка «Применить»:**
- текст с числами предпросмотра сервера;
- неактивна до выбора по пропавшим, с объяснением;
- рядом — «N строк не проверены и не будут применены» и «N строк с новой ценой ждут подтверждения»;
- подтверждение перед применением.

**Конфликты и состояние:**
- **конфликт версий** (коллега в другой вкладке) — «Сверку только что изменил {кто}», данные перечитываются, своё решение повторяется одним нажатием;
- **повторное применение** — «Прайс уже применил {кто} в {время}»;
- **ход** `applying` — «Применяем…» с опросом, только пока вкладка видима;
- **черновик** — уход со страницы и возврат продолжают с того же места; истечение срока сверки — «Сверка истекла — загрузите прайс заново».

**Тексты** — kk/ru/en. Сводка и кнопка — по SCREENS дословно.

### 2. Итог (S-PRICE-04)

- «Готово: обновлено N, снято M, на добавление отправлено K — результат в разделе „Модерация“» по `result` сервера;
- отдельно: создано, вернулось в продажу, снято «нет в наличии»;
- «Не применено» — сгруппировано по причинам словами (требует подтверждения цены, позиция недоступна, нет в наличии у новой позиции, «под заказ» без срока…), со списком строк;
- «К предложениям», «Цены в созданных заявках не меняются»;
- история на «Прайс» показывает применённые загрузки с итогом.

### 3. «Модерация» (S-MOD-01) и запрос на добавление (S-OFF-05)

**Раздел «Модерация» в меню кабинета:**
- **запросы на позиции** (из прайса и ручные) и **предложения совместимости** компании;
- статусы «На рассмотрении» / «Добавлено» (со ссылкой на позицию и «Выставить», если предложения ещё нет) / «Отклонено: {причина}»;
- отметка «новое» у решений, которые сотрудник ещё не видел;
- счётчик непросмотренных — в меню.

Что «просмотрено» — на сервере (у сотрудника или у компании — решение агента; записать).

**S-OFF-05:**
- из поиска позиции «Нет в справочнике? Отправьте запрос на добавление»;
- форма: название (обязательно), бренд (подсказки по написаниям), артикул, категория (подсказки), комментарий;
- запрос — тот же `catalog_request`, без дублей открытого запроса на тот же артикул компании;
- предел частоты на компанию — настройка.

Администратор видит такие запросы там же, где запросы из прайса («Запросы на позиции»), с пометкой «вручную».

### 4. «Скачать мой прайс» и обратная загрузка

- **Выгрузка `.xlsx`** своих предложений (в продаже и снятых — по выбору, по умолчанию в продаже) с колонками ARCHITECTURE 12.4 и скрытой технической колонкой `item_id`.
  - Услуги не выгружаются: у них цены по моделям.
  - Чужое не попадает никогда.
  - Генерация — потоком.
  - Файл — со своим `item_id` в каждой строке.
  - Ограничение частоты.
- **Обратная загрузка** этого файла (поставщик правит цены и наличие в Excel):
  - колонки узнаются как запомненный формат;
  - строки с `item_id` своей компании сопоставляются по нему — **уверенно, без ИИ и без поиска**;
  - `item_id` чужого предложения или несуществующий — ошибка строки (не подсказка, чья это позиция).
- **Повторная загрузка выгрузки без правок** — ноль изменений.

### 5. Услуги в прайсе

Строка, которая по артикулу или названию совпадает с позицией-услугой, — **ошибка строки** с причиной словами. Она не попадает в «не найдено» и не уходит запросом администратору.

### 6. Состояние

- Новые маршруты, задачи, миграции — в `apps/api/src/testing/expected/*`.
- Контракт — аддитивно.

## Не входит

- фото и PDF прайса (этап D);
- фото поставщиков в запросах и модерация фото (EPIC-26);
- сводка W-06 (TASK-071);
- замер моделей ИИ для сопоставления (отдельной задачей по D-058).

## Edge cases

- Сверка на 1 240 строк, из них 800 «нужно проверить» — список не тормозит (страницы), «Пропустить все оставшиеся» работает одним запросом.
- Два сотрудника сверяют одну загрузку в двух вкладках — конфликт словами, ничего не теряется.
- Резкая цена подтверждена, затем коллега вручную поменял цену предложения — итог «требует подтверждения цены» объяснён словами.
- Выгрузка с 0 предложениями — файл с заголовком и подсказкой; «Скачать» не падает.
- В выгрузке поставщик удалил колонку `item_id` — строки сопоставляются обычным путём (память компании, точный артикул).
- В выгрузке поставщик вписал чужой `item_id` — ошибка строки, ничего чужого не меняется.
- Телефон 375 px — сверка без прокрутки страницы вбок, кнопки строки доступны пальцем.

## Что должно реально работать

Сотрудник «Автомаркета» загружает выгрузку 1С и открывает «Сверку». Наверху сводка; во вкладке «Нужно проверить» он подтверждает две строки «предложено ИИ», остальные пропускает одной кнопкой. В «Уверенно» отмечает «Подтвердить новую цену» у строки, где цена выросла вдвое, а в «Пропали из файла» выбирает «Оставить как есть». Кнопка «Применить: обновить 2 · снять 0 · отправить на добавление 3» → «Готово…».

Затем он открывает «Модерацию» и видит три запроса «На рассмотрении». Администратор создаёт позицию по одному из них — у сотрудника появляется «Добавлено» с отметкой «новое».

Наконец он скачивает свой прайс, меняет в Excel две цены и загружает файл обратно. Сверка — всё «уверенно», меняются ровно две цены.
