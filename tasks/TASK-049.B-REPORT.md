## Technical Decisions
Всё внесено в `ARCHITECTURE.md` 4.70:

- **I753 — тестовый заказ и пределы текста.**
  - Признак тестового заказа — поле `reviewUnavailable`, его вычисляет сервер. По одному `isTest` пришлось бы на клиенте решать, выдана ли заявка.
  - Пределы длины текста — поле `feedbackLimits` из настроек.
  - `UserOrder` не входит ни в один `oneOf` ответа, поэтому `openapi:compat` проходит без трейлера.
- **I754 — логика экранов** — чистые функции в `orders/order-feedback.ts`.
- **I755 — экраны корневого стека.** Экраны отзыва и жалобы сами читают заявку, начиная с ответа, который сохранил экран заявки. Поэтому «Оценить» работает и из истории.
- **I756 — один ключ повтора на экран.**
- **I757 — сообщение после отправки выбирается по ответу сервера.** Если опубликована только оценка (без текста), показывается «Спасибо! Отзыв опубликован», а не T-REV-01 (см. Deviations).
- **I758 — размещение на заявке:** блоки отзыва и жалобы — под статусом; T-ORD-08 — первой строкой в действиях. Без сети — блоки из последнего ответа сервера.
- **I759 — `StarsInput` и многострочное поле.**
- **I760 — отзыв и жалоба не требуют клубного доступа.** Сервер его не проверяет; приложение следует серверу.
- **I761 — плавающий тест.**
  - **Причина.** pg-boss перед следующим опросом ждёт `interval − длительность прошлого опроса` и не ждёт вовсе, если остаток ≤ 100 мс. Обработчик теста работает 400 мс при интервале 500 мс, поэтому worker, выполнивший задачу, сразу опрашивает снова. Первый победитель почти всегда остаётся победителем.
  - **`localConcurrency` ни при чём:** у singleton-задачи он равен 1, как и умолчание pg-boss.
  - **Исправление.**
    1. Оба worker'а 3 с опрашивают очередь вместе — проверяется, что singleton не выполняется дважды одновременно.
    2. Затем каждый worker по очереди остаётся единственным: второй останавливается и запускается снова, поэтому каждый гарантированно берёт задачу.
  - Утверждения теста не менялись.

## Deviations
- **Сообщение после оценки без текста.** Оценка без текста публикуется сразу (I737), поэтому вместо T-REV-01 «Отзыв появится после проверки» показывается «Спасибо! Отзыв опубликован» — T-REV-01 здесь был бы неправдой. Отзыв с текстом получает T-REV-01 дословно.

Задача требует показывать кнопку по `complaintReasons`, а сервер (I743) разрешает жалобу и у принятой заявки. Сделано по серверу. Если по продукту это нужно только для завершённых, правило меняется на сервере, а не в приложении.
