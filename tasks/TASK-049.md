# TASK-049 — Отзывы и жалобы: сервер, проверка до публикации, админка

Модель: Opus 5.5, High

## Цель

По решению Product Owner (13.10.2026) этап C продолжается доверием (EPIC-17). Три задачи:
1. **TASK-049** (эта) — отзывы и жалобы на сервере: проверка отзыва до публикации (детерминированные правила + ИИ), очередь и решения администратора, жалобы, всё в админке;
2. **TASK-049.B** — экраны приложения: «Оценить» (M-ORD-05), «Пожаловаться» (M-ORD-06), состояния на заявке;
3. **TASK-050** — расчёт рейтинга (оценки, доля ответов, соблюдение сроков), «Новый поставщик», страница поставщика с отзывами (M-CAT-09), сортировка «по рейтингу», сигнал о низком рейтинге.

После этой задачи пользователь (пока запросами) оставляет отзыв по выданной заявке, отзыв проходит проверку и публикуется или задерживается администратору. Администратор разбирает очередь отзывов и жалобы в админке.

## Контекст

## Требования

### 1. Отзыв — сервер

**`POST /reviews`** (мобильная сессия) — `orderId`, `score` 1–5, `text?` (до N знаков — настройка; пустой и пробельный = без текста), `idempotencyKey`.
- **Разрешено**, только если:
  - заявка своя;
  - статус `completed` (выдана; у услуги — выполнена);
  - не тестовая;
  - отзыва по ней ещё нет.
- **Иначе — коды словами:**
  - чужая и несуществующая заявка — одинаковый 404;
  - не выдана;
  - тестовая — «Отзыв недоступен: это тестовый заказ»;
  - уже есть.
- **Предел частоты** на учётную запись — настройка.

**Состояния отзыва** (записать в 5.9):
- `checking` — ждёт проверки;
- `published`;
- `held` — задержан: проверка нашла причину или ждала дольше `review_check_max_wait_minutes`, решает администратор;
- `text_rejected` — администратор отклонил текст с причиной, пользователь видит её;
- `hidden` — администратор скрыл опубликованный с причиной.

Оценка без текста проверку не проходит — сразу `published`.

**Проверка — фоновая задача:**
1. **Детерминированные правила, без ИИ:**
   - контакты и ссылки — `warrantyTextContacts`;
   - название поставщика заявки и его написания (без учёта регистра, kk/ru раскладок — как поиск, `searchKey`);
   - имена сотрудников поставщика.
   
   Сработало → `held` с причиной, ИИ не вызывается.
2. **ИИ** — новая операция `review_check` через `AiService`:
   - мат и оскорбления (kk/ru/en, транслит, смешанная речь), угрозы, личные данные, реклама;
   - ответ — нарушения с видами из фиксированного списка и коротким объяснением;
   - **критика и низкая оценка — не нарушение** (это в инструкции модели и в наборе тестовых примеров);
   - модели — настройки `ai_model_review_check_primary` / `_fallback`; умолчание — как у перевода, замер — Future по D-058;
   - `TestAiGateway` отвечает детерминированно по словам-маркерам (для dev и тестов).
3. **Нарушений нет → `published`. Есть → `held`** с причинами.
   - **ИИ никогда не отклоняет сам.**
4. **ИИ недоступен или исчерпан дневной бюджет** — отзыв ждёт в `checking`, проверка повторяется сама. Ждёт дольше `review_check_max_wait_minutes` → `held` с причиной «проверка недоступна» (свипер).

**Решения администратора** (с версией и журналом, причина обязательна там, где сказано):
- «Опубликовать» (`held` → `published`);
- «Отклонить текст» с причиной из списка (`held` → `text_rejected`);
- «Скрыть» (`published` → `hidden`);
- «Вернуть» (`hidden` → `published`).

**Пользователь при `text_rejected`:**
- «Исправить текст» **один раз** — новый текст снова проходит проверку; повторное исправление — отказ;
- «Опубликовать только оценку» — текст снимается, `published` без текста.

**Опубликованный отзыв не редактируется пользователем.**

**Что видно пользователю на своей заявке:**
- отзыва нет и можно — «Оценить»;
- `checking` / `held` — «Отзыв на проверке» (причину задержки до решения администратора пользователь **не видит**);
- `published` — «Отзыв опубликован»;
- `text_rejected` — T-REV-02 с причиной словами и действиями;
- `hidden` — «Отзыв опубликован» (скрытие пользователю не сообщается, как и причина) — **решение агента, записать**; если считаете иначе — вынести в Deviations.

**`canReview`** в истории и в карточке заявки вычитает заявки с отзывом.

**Публичное чтение отзывов поставщика** (для M-CAT-09 в TASK-050):
- маршрут списка опубликованных отзывов поставщика — оценка, текст, дата, автор «Имя Ф.» (имя и инициал фамилии из имени учётной записи), страницами;
- кто видит — по правилу `showcase-visibility.ts`: гостю и без клубного доступа поставщик скрыт, значит и его отзывы по id не отдаются; решение — записать;
- дата — месяц и год или дата — решение агента;
- телефона и id пользователя нет никогда.

### 2. Жалоба — сервер

**`POST /complaints`** (мобильная сессия) — `orderId`, причина из пяти, текст (обязателен для «Другое», для прочих — по желанию; длина — настройка), `idempotencyKey`.
- **Разрешено:** своя заявка в конечном статусе или принятая.
  - «Не получил товар» — по выданной заявке: именно её T-ORD-08 / P-ORD-06.
  - Тестовая — тоже можно (жалоба не статистика).
- **Одна открытая жалоба на заявку**; после «решена» — можно новую.
- **Предел частоты.**
- **Статусы** `new` → `in_progress` → `resolved` (записать в 5.9; `dismissed` из модели не нужен — «решена» с комментарием).
- **Пользователь видит** «Жалоба на рассмотрении» / «Жалоба рассмотрена». Внутренний комментарий — только администратору.
- **Поставщик жалоб не видит нигде.**

### 3. Админка

- **«Отзывы»** — новый раздел или вкладка (решение агента).
  - **«На проверке»** (`held`; `checking` дольше порога уже стали `held`):
    - оценка, текст, причины с пометкой [AI] у найденного моделью;
    - заявка (ссылка в карточку), поставщик, дата;
    - «Опубликовать» / «Отклонить текст…» с причиной из списка.
  - **«Опубликованные»** — поиск и отбор по поставщику, «Скрыть…» с причиной.
  - **«Скрытые»** — «Вернуть».
  - **«Отклонённые»** — текст, причина, исправлял ли пользователь.
- **«Жалобы»** (A-REV-02):
  - список с отборами по статусу, причине, поставщику;
  - карточка — причина, текст, заявка, пользователь (номер скрыт, «Показать номер»), поставщик, внутренний комментарий;
  - «Взять в работу», «Решить» с комментарием;
  - версия и конфликт двух администраторов словами.
- **Главная** — карточки «Отзывы на проверке · N», «Жалобы · новых N».
- **«Заявки»** — отбор «Есть жалоба», в карточке заявки — отзыв и жалобы.
- **«Пользователи»** — блок жалоб пользователя.
- **«Поставщики»** — вкладка «Отзывы» (список отзывов поставщика всех состояний).
- **Журнал словами** — все действия с отзывами и жалобами.

## Бизнес-правила

- Отзыв — только владелец, только выданная нетестовая заявка, один на заявку.
- Проверка не отклоняет никогда. Отклоняет текст только администратор, и только с причиной.
- Критика и низкая оценка публикуются.
- Поставщик не видит жалоб и не видит, кто оставил отзыв (кроме имени и инициала на публичной странице).
- Решения администратора — с версией, в журнале.

## Edge cases

- Отзыв на услугу (выполненная запись) — так же, как на товар.
- Два запроса отзыва с одним ключом — один отзыв; два с разными ключами одновременно — один отзыв, второй — «уже есть».
- Текст с номером телефона, записанным словами или с пробелами (`+7 705 555 01 01`), — `held` по правилу контактов.
- Текст «отличный магазин Автомаркет, рекомендую» — `held` («название поставщика»), хотя отзыв положительный.
- Текст «долго ждал, цена выше обещанной, больше не приду» — `published`: критика.
- ИИ недоступен час — отзыв `held` с причиной «проверка недоступна»; ИИ вернулся до порога — отзыв проверен и опубликован сам.
- Исправленный текст снова задержан и отклонён — остаётся только «Опубликовать только оценку».
- Администратор скрыл отзыв, пользователь удалил аккаунт (позже) — ничего не ломается.
- Жалоба по чужой заявке — 404; по заявке «ждёт ответа» — отказ словами.

## Что должно реально работать

Тестовый пользователь с клубным доступом оформляет заявку у «Автомаркета», поставщик выдаёт её по коду. Пользователь оставляет оценку 2 и текст «долго ждал ответа, цена в итоге выше» — через пару секунд отзыв опубликован.

Второй пользователь пишет «Автомаркет топ, звоните +7 705 555 01 01» — отзыв на проверке, у администратора в очереди с причинами «название поставщика» и «контакты». Администратор отклоняет текст с причиной «личные данные». Пользователь публикует только оценку.

Третий пользователь жалуется «Не получил товар». Администратор берёт жалобу в работу и решает её с внутренним комментарием, пользователь видит «Жалоба рассмотрена». Поставщик в кабинете ничего из этого не видит, кроме опубликованных отзывов с именем и инициалом.
