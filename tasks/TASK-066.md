# TASK-066 — Гостевой режим: сверка и закрытие EPIC-25

Модель: Opus 5.5, Medium

## Цель

EPIC-25 обещает: гость пользуется распознаванием фото, голосом и помощником в пределах бессрочного лимита на устройство; лимит и бюджет задаются в настройках (PRODUCT 6.6). Большая часть уже построена задачами 057, 058, 059, 060, 062, 063:
- `guest_limits` на устройство;
- пределы с адреса у каждого маршрута;
- `guest_ai_daily_budget_usd`;
- M-AI-02 в приложении.

Задача объединяет TASK-066 и TASK-067 плана. Она закрывает то, чего не хватает, и проверяет режим целиком одним сценарием. Новых экранов нет.

При приёмке TASK-060.A архитектор нашёл две настройки, которые видны администратору, но ничего не делают:
- **`guest_ip_rate_limit_per_hour`** — ни один маршрут её не читает. У каждого гостевого маршрута свой предел с адреса: `vehicle_document_per_ip`, `speech_per_ip`, `assistant_guest_per_ip`.
- **`guest_attestation_required`** — точки проверки, обещанной ARCHITECTURE 8.6 («настройка и точка проверки в гостевом middleware»), нет.

## Требования

### 1. Мёртвая настройка `guest_ip_rate_limit_per_hour`

Удалить ключ:
- из реестра настроек;
- из ARCHITECTURE 14 и 8.6;
- из админки, если он там упомянут.

Сохранённое значение в `app_setting`, если есть, убрать миграцией — или тем способом, каким проект уже удалял ключи (проверь историю: `git log -S` по реестру). Защита с адреса остаётся в пределах каждого маршрута; второго общего предела не вводить.

### 2. Точка проверки подлинности приложения у гостя

**Одно место** для всех гостевых ИИ-маршрутов:
- фото: техпаспорт, панель, деталь;
- голос: `/speech/transcribe`;
- помощник: `/assistant/messages`.

Это место читает `guest_attestation_required`.

Интеграции с App Attest / Play Integrity нет (BACKLOG). Поэтому при `true` ни один гостевой запрос подтверждения не имеет, и гость получает отказ:
- новый код ошибки (например, 403 `GUEST_SIGN_IN_REQUIRED`; имя выбери сам, контракт — только аддитивно);
- отказ — до чтения тела, до счёта пробной попытки и без вызова модели;
- вошедший не затрагивается.

Так настройка работает выключателем «ИИ только для вошедших» на случай злоупотребления. Описание настройки в реестре говорит это прямо.

Приложение показывает на этот отказ M-AI-02 «Пробные запросы временно недоступны» с «Войти» — тот же текст, что при исчерпанном гостевом бюджете. «Выбрать из списка» и текстовый поиск остаются доступны.

Проверить все точки:
- поиск голосом и по фото детали;
- пробег голосом и по фото;
- автомобиль голосом и по техпаспорту (после отказа — «Выбрать из списка»);
- помощник.

### 3. Сверка правил PRODUCT 6.6 на сервере

Один интеграционный файл (например, `guest-mode.integration.test.ts`) проверяет режим целиком:
- **Пробные попытки.** Фото, голос и помощник считают их по устройству, каждый своим счётчиком. Исчерпание одного не трогает другие.
- **Новое устройство.** Новый `deviceId` получает лимит заново (защиты на старте нет — так по 6.6).
- **Изменение лимита.** Новое значение `guest_limits` действует без перезапуска — не позже срока кэша настроек.
- **Гостевой бюджет.** Исчерпан `guest_ai_daily_budget_usd` — каждый гостевой маршрут отвечает своим отказом «гостевой бюджет», вошедший работает.
- **После входа.** Тем же устройством, но с сессией — гостевой лимит не действует.
- **Без ИИ.** Текстовый поиск, каталог под гостевой автомобиль и `POST /vehicles/match` доступны при исчерпанных попытках.
- **Выключатель.** `guest_attestation_required = true` — отказ гостю на всех пяти маршрутах, без следа в `ai_job` и без счёта попытки; вошедший работает.

### 4. Что видно для решения о выключателе

ARCHITECTURE 8.6 называет признаки, по которым включают проверку:
- доля гостевых ИИ-запросов с устройств старше суток без регистрации;
- всплеск новых устройств с одной подсети.

Сделать их видимыми минимальным способом:
- **сейчас** — серверная команда `guest:status` или раздел в `ai:status`: гостевой расход суток против бюджета, вызовы по видам, число устройств за сутки, число новых устройств, верхние подсети по новым устройствам — без адресов целиком, только /24 и /64 с маской;
- **потом** — метрики для дашборда TASK-073.

Где хранить «устройство впервые увидено» — реши сам. Без новых персональных данных: идентификатор устройства уже хранится в Redis-ключах лимитов.

### 5. Проход в приложении

`api-test-ai`, `mobile-web`; безголовый Chrome, если панель скрыта. Ru и kk, светлая и тёмная.

Гость с автомобилем:
1. Пробует фото детали, голос в поиске и помощника.
2. Исчерпывает лимит одного вида — M-AI-02 «Войти».
3. Входит тестовым номером — тот же запрос проходит.
4. `guest_attestation_required = true` — у нового гостя во всех точках M-AI-02. «Выбрать из списка» и текстовый поиск работают.

Снимки — `tasks/TASK-066-shots/`. Настройки после проверки вернуть `settings:reset`.
