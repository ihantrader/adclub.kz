## Technical Decisions
Все решения внесены в ARCHITECTURE 4.95, I1156–I1163.
- **Повторная проверка под блокировкой строки владельца.** Это лучше, чем переносить сетевую запись в транзакцию: файлы по-прежнему уходят до транзакции, и транзакция не держит соединение на время сети. Решение администратора блокирует ту же строку запроса, поэтому исход однозначен: либо 409, либо фото переносится вместе с остальными.
- **Причина переполнения — код в `rejectionReason`, а не текст.** Иначе поставщик не увидит причину на своём языке. Контракт ответа не меняется: поле осталось строкой.
- **`due` — пул по числу активных предложений, затем порядок по числу видимых.** Цена: позиция, у которой все предложения не на витрине, может занять место в пуле. При пуле 200 и пакете 20 это не мешает набрать пакет.
- **Память — повторное скачивание выбранных** (до `photo_search_candidates` дополнительных запросов на поиск) плюс ограничение одновременного декодирования. Вариант «хранить только сырые байты» не снижал пик: 20 файлов по 10 МБ — те же 200 МБ.
- **`BlockList` нельзя пополнять подсетями `::ffff:…/96`.** Node сопоставляет IPv4 с IPv4-mapped подсетями, и такая подсеть заблокировала бы весь IPv4. Первая попытка уронила юнит-тест «пропускает 8.8.8.8», поэтому проверка сделана по группам адреса.
