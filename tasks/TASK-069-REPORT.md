## Technical Decisions
Всё внесено в ARCHITECTURE 4.87.
- **«График от нуля» (I997).** `dueMaintenance` смотрит вперёд от пробега. Пройденная точка у него исчезает, и напоминание пропадало бы, едва пробег её перешёл. Поэтому для напоминаний замены по графику до начала журнала считаются сделанными:
  - база — точка графика не выше первого показания;
  - срок — следующая точка;
  - пропущенная замена остаётся просроченной, пока её не отметят.

  Точки графика — те же, что у `dueMaintenance`.
- **«Тот же пробег» отвечает на вопрос о пробеге (I1001).** По правилу TASK-058 то же значение ничего не пишет в журнал, и M-REM-02 после «Сохранить» оставался на месте. Это найдено при проходе в браузере. Теперь подтверждение отмечается в `account_car.mileage_confirmed_at`. Журнал и оценка пробега не меняются.
- **«Подобрать» считается только для `due`/`snoozed` (I1000).** Список подкатегории — это запрос на каждый элемент. У прочих элементов `catalog: null`.
- **Тексты:**
  - для замены по графику карточка говорит «по регламенту — каждые N км», а не «прошло около N км»: эту замену никто не видел;
  - для услуги — «{Замена моторного масла} для {автомобиль} — пора: …» и push P-REM-01a «… — пора. Записаться?». Это наш текст, ждёт согласования; «Пора менять замена моторного масла» — не по-русски.
- **`apiRoutes` из частей (I1006).** Один объектный литерал всех маршрутов перерос предел сериализации типа в декларацию (TS7056 при сборке `packages/contracts`). Теперь `apiRoutes: typeof coreApiRoutes & typeof reminderRoutes`. Следующая группа маршрутов добавляется следующей частью.
- **Push удалённому автомобилю.** Edge case допускает «задача не ставит его для исчезнувшего автомобиля». Задача берёт строку автомобиля под блокировку в своей транзакции: удалённый — пропускается. Строки `maintenance_reminder` удаляются каскадом. Push, уже стоящий в очереди, не отменяется: он уходит за секунды после постановки.
