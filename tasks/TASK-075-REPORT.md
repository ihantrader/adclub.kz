Все внесены в ARCHITECTURE.md 4.10:

- **Раскладка (I86):** `ui-core` (CommonJS, как остальные общие пакеты, без React/DOM) — общий для веба и мобильного; `ui` — только веб; компоненты RN — в `apps/mobile/src/design-system` (3.5: универсальных компонентов нет); каждый пакет экспортирует только `"."` — подпути не понадобились, граница пакетов (4.1 I4) и настройки Metro не менялись. - **`ui` — ESM (I87),** осознанное исключение из 4.1 I3: иначе в бандл попадали бы все ~5 000 значков Tabler.
- **Тема в вебе (I90):** CSS-переменные в `theme.css`, сгенерированном из токенов и сверяемом файловым снимком; `data-theme` на `<html>`; встроенный скрипт в `index.html` против вспышки светлой темы.

- **Витрины (I94):** веб-витрина — отдельный dev-пакет (при экспорте из `ui` она оставалась в production-бандле — найдено проверкой `dist`).

- **Иконки (I96):** растры из SVG `design/brand` одной командой; значок уведомлений — через плагин `expo-notifications` (в SDK 57 нет поля `notification` в `app.json`).

## Known Issues / Risks

- Мобильные компоненты и витрина на реальном устройстве не проверены агентом (см. UAT); иконки и заставку видно только в нативной сборке (EAS, TASK-074).
- Размер JS веб-бандлов ~830 КБ (основная часть — zod из контракта); Vite предупреждает о чанках > 500 КБ. Базовый размер до задачи не измерялся.
- iOS-иконка 1024 сохранена с альфа-каналом (непрозрачным); App Store не принимает альфа-канал — Expo при prebuild удаляет прозрачность, но это нужно подтвердить в TASK-074.
- При сбое загрузки шрифта в RN семейства `Onest-*` не зарегистрированы — iOS может выводить предупреждение и использовать системный шрифт.
- Встроенный скрипт темы в `index.html` потребует разрешения (хэш) при будущей политике CSP.
- `pnpm brand:assets --check` не добавлен в CI: побайтовое совпадение PNG, отрисованных на Windows и Linux, не проверялось.
- При горячей замене модулей в dev после пересборки `@adclub/ui` в консоли может появиться разовая ошибка контекста (два экземпляра модуля); полная перезагрузка страницы её убирает.
