# TASK-080 — Админка: каждый экран по дизайн-системе

Модель: Opus 5.5, High

## Цель

Product Owner попросил довести каждый экран до «грамотно, удобно, премиально». Разбор админки (65 экранов, 1440 × 900, вся страница) — **`tasks/TASK-080-audit.md`**: сквозные проблемы X1–X29 и замечания по каждому экрану A-….

Самое заметное:
- синие браузерные ссылки повсюду;
- системные `<select>` и «Choose File»;
- кнопки, которые переносятся и налезают друг на друга (вкладка «Сотрудники» поставщика);
- журнал с JSON и UUID;
- «Настройки» — одна страница на 17 575 px.

## Контекст

- **Источник истины:**
  - DESIGN.md 7.3 — админка только светлая;
  - 7.7 и 7.8 — компоненты и метки статусов;
  - 7.13 — готовые компоненты с темой из токенов, плотная раскладка, строки 40–48;
  - SCREENS.md 2 и 7.
- **Выполнено до этой задачи:**
  - TASK-077 убрала переключатель темы и починила «Нет связи» после перезагрузок (X29 — здесь только экран ошибки поверх содержимого);
  - TASK-079 сделала в `@adclub/ui` общие веб-компоненты: поле 48, `SearchSelect` в той же оболочке, поле даты, компактный `WeekHoursEditor`, `ActionBar`, текстовую кнопку, метки.

  Админка берёт их оттуда, своих копий не заводит.
- **В этой задаче в `@adclub/ui` появляются** (если их ещё нет):
  - свой `Select`;
  - зона загрузки файла (как «Прайс» кабинета);
  - `StatusBadge` с одной картой «статус → роль»;
  - `PageHeader` — крошки, заголовок, действия, одна полоса вкладок;
  - тулбар таблицы;
  - `EmptyState` (обычный и компактный);
  - меню строки «⋯».
- **Журнал словами** уже есть (`audit-words`, TASK-036.B). X16 продолжает его: технические поля — под «Подробнее», «было» и «стало» без подложек, группировка одинаковых подряд.
- **Токены не меняются.** Тексты SCREENS — без изменений; если нужно — Deviations.
- **Решения архитектора по спорным пунктам** (не пересматривать):
  - X1 — ссылкой служит вся строка или название, не три колонки;
  - X5 — фильтр статуса — всегда чипы DESIGN 7.7;
  - X11 — у страницы объекта вместо вкладок раздела — крошки;
  - X13 — обратимые «В архив», «Заблокировать» — второстепенные с текстом `danger`, не заливка;
  - X22 — «Настройки» — навигация по группам.

## Требования

1. Сквозные X1–X28 — в общих компонентах и раскладке админки. Каждый экран переводится на них.
   - **X20 таблицы:** `table-layout: fixed`, `nowrap` у сумм, дат, номеров, телефонов и статусов; одинаковые ширины на вкладках одного списка.
   - **X22 длинные списки:** постранично или «Показать ещё» — сессии, загрузки прайса, журнал. Если маршрут сервера отдаёт всё сразу, добавить курсор аддитивно.
2. Замечания по экранам (раздел 2 разбора) — все, включая «Н». «Проверить» — сначала подтвердить.
3. Ширины 1024, 1440 и 1920:
   - содержимое по центру вместе с шапкой;
   - горизонтальной прокрутки страницы нет;
   - у широких таблиц прокрутка — внутри таблицы, первая колонка закреплена.
4. Состояния по SCREENS 2: загрузка без мигания (D-069), пусто, ошибка поверх содержимого (X29), конфликт версии, нет прав.
5. Клавиатура: фокус виден только с клавиатуры (`:focus-visible`), меню «⋯» и `Select` управляются стрелками, Enter и Esc.

## Бизнес-правила

- Вид меняется, права и запросы — нет.
- Номера по-прежнему скрыты сервером, «Показать номер» пишет в журнал.

## Edge cases

- Поставщик с 100 сессиями и 35 загрузками.
- Отзыв на казахском в 10 строк.
- Позиция с 9 вкладками.
- Журнал с объектом, которого больше нет.
- Настройка-объект и настройка-текст kk/ru/en.
- 792 запроса на позиции.

## Не входит

- продуктовые расхождения — TASK-077;
- новые разделы админки (биллинг — TASK-043, дашборды — их задачи);
- тёмная тема админки (её нет по DESIGN 7.3).

## Acceptance Criteria

1. Каждый пункт X1–X28 и раздела 2 разбора — в отчёте таблицей: «пункт → что сделано → PASS / не подтвердилось (почему)».
2. Скриншоты до и после каждого экрана админки на 1440 (и 1024 там, где раскладка меняется) — в scratchpad, список в отчёте. Ни одной синей ссылки `#0000EE`, ни одного системного `select` или `input[type=file|date|time]` на экранах (проверка скриптом по DOM в отчёте).
3. Юнит-тесты (jsdom) новых компонентов: `Select` (клавиатура, поиск по первой букве, отключённый), зона загрузки (перетаскивание, неверный тип, размер), `StatusBadge` (карта ролей покрывает все статусы контракта — тест падает, если в контракте появится статус без роли), меню «⋯».
4. Журнал: юнит-тесты на группировку подряд и на «Подробнее» для технических полей; ни в одной строке журнала нет UUID и JSON вне «Подробнее».
5. Новые курсоры маршрутов — аддитивно (`openapi:compat` без трейлера, `openapi:check` PASS); новые маршруты `/admin` — в `apps/api/src/testing/expected/admin-routes.ts`.
6. `ARCHITECTURE.md` — версия по порядку, дополнение раздела «Веб-компоненты» (новые компоненты, карта статусов).
7. Локально `pnpm format:check`, `lint`, `typecheck`, `test`, `build` — после последней правки кода; интеграционные тесты модулей, где менялись маршруты. CI проверяет архитектор.
8. Отчёт `tasks/TASK-080-REPORT.md` с идентификатором прогона CI.

## Что должно реально работать

Администратор открывает главную: карточки ровные, ненулевые — первыми.

Затем — карточка «Автомаркета», вкладка «Сотрудники»: у каждого сотрудника одна кнопка и «⋯», ничего не налезает, сессий 10 и «Показать все». Часы работы — семь строк.

«Настройки» — группы слева, справа одна группа.

Журнал — время в одну строку, кто и что словами, JSON только под «Подробнее».
